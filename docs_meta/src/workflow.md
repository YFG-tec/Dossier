# 一刀

换根不带走。原则见仓库根 `readme.md`。目录落点见 `directory.md`。

目录给了落点，一刀给了范围。两件缺一，代理就会在 `src/` 里自由发挥。

## 开桌：先议事，后立案

一刀之前有一段不是一刀的东西：**和规划席把大框架聊透**。
`roles.md` 说规划席的典型环境是「读全树、**议事**、改文档快」——议事就是这一段，但它一直没落成一个阶段。
缺了它，第三刀才发现合同自相矛盾，前两刀白做：那是「退卡」表里「合同没写」那一行的批发版。

这一段的失败模式有两个，方向相反：

- 框架没理顺就开刀 → 合同边做边换，每一刀都在改上一刀的前提。
- 为了「理顺」把细节全定死 → 定的是猜的。**写下来的猜测比「未定」更糟**，因为下一刀会拿它当判据引。

躲开两边靠一条不对称的收口判据：

> **框架要聊全，判据只要够第一刀。**
> 全的是**章节**——这件事分成哪几块、每块要回答什么问题，一个都不能漏。
> 够的是**答案**——只有第一刀要碰的那一**条**得有授权，其余可以还只是问题。

「聊透」聊的是前者。**知道有哪些问题，和知道那些问题的答案，是两件事**；开桌只欠后者。

所以合同层要分开两件事，别塞进同一个标记：

| | 是什么 | 靠什么 |
|---|---|---|
| **权威**——能不能当判据引 | **二元**：已定 / 不已定 | 标记，机械可查 |
| **进度**——想到哪一步 | **三元**：验证过 / 有答案没验证 / 没答案 | 正文叙述，不承重 |

### 权威：正向标定

**机械保险在这里：默认不可引。** 合同层的一条只有带上 `【定】` 才能被卡片当判据引用；
其余一律是**参考**——可查阅、可作规划席提建议的依据，**不可引**。

```text
【定】一次只做未勾的一行。          ← 可引
      退卡的一刀怎么记进已办，没定。 ← 参考，不可引
```

为什么是正向标确定，不是反过来标不确定：

| | 标不确定 | 标确定 |
|---|---|---|
| 默认 | 可引，除非标了 | **不可引**，除非标了 |
| 标记丢了 | 沉默升格——**失效朝危险倒** | 降成参考——**失效朝安全倒** |
| 谁吃亏 | 下游：拿参考当合同做了一刀 | 上游：该标没标，东西没人引，很快发现 |

**改的不是宽严，是失效方向。** 标记一定会丢——上下文压缩会丢、摘录会丢、
复制粘贴会丢、手滑改一行也会丢。设计时就假定它会丢，然后让它往安全那边倒。

三条落地约定，缺一条这机制就漏：

- **行内标记，不另立清单文件。** 一份「已定条目清单」就是第二真相，
  和正文迟早不一致，且不一致时没人知道该信哪个（`directory.md`）。
  要索引就 `grep -n` 现算，**不存盘**。
- **裸的是授权，反引号里和代码块里的是提及。** 描述这个标记的文字不发授权。
  这不是文风：整套机制押在 `grep` 上，分不出「用」和「提」，检查就会自伤。
- **落笔在人。** 加一个标记就是发一次授权，和勾 TODO 同性质。
  人可以口头下令、由代理代抄，但**决定权不下放**。

**代价照写：丢了「局部自明」。** 一个问句看一眼就知道不能引，零纪律成本；
正向标定要回源头查一次。补偿是这个查询**能机器做**——精确子串比对，不是语义判断——
而且只卡在写卡那一个口，那是所有合同引用的必经之路。

### 进度：三态照写，只是不再承重

| 态 | 长什么样 |
|---|---|
| **已定** | 物理与离散的事实 |
| **草案** | 有答案、没验证；开头标「草案 / 未实现」 |
| **占位** | **只有问题，没有答案** |

这三态给规划席看：这件事想到哪一步、下一刀该啃哪一块。**它不决定能不能引**——
没标记的「已定」照样引不动，标了的照样能引。节的态从此只是摘要，不承重；
**一节里几条已定、几条还是问题，是常态，不是脏。**

**占位建议写成问句**，但这条现在只是**写作建议**。
留着它的理由换了一个：**问句逼你说清到底不知道什么。**
「边界条件用哪一种？」暴露了未知；「边界条件暂定周期」把没想明白的事
伪装成想明白了一半——骗的是写的人自己。既然引不动，它就不再危险，只是可惜。

**这就是 `docs/design/` 作为一个目录存在的主要理由。** 不是「把物理写下来存档」——存档写一页就够。
它是**未定事项的收容层**：有了它，「还没想明白」才有地方合法地待着，而且待在一个不会被当判据引用的位置。

没有它，未定的东西只能往在办层挤。Xenia 没有 `docs/design/`，
346 行的 `TODO.md` 里就长出了带日期的裁决（「用户拍板（锁）：①…⑤」「原文锁死」「会话点头不算。」）——
因为 `SESSION.md` 每刀覆盖，那些话没有别的地方可去。
**在办层留不住话，合同层才留得住。** 把长期的东西放进留不住的那一层，就只能靠一份不断变胖的 TODO 去抗覆盖。

开桌交三样，都很短：

1. `docs/design/` **章节名先立**，内容三态。占位一句话，说清将来要回答什么。
2. `docs/TODO.md` 第一版。**三五行就够。**
3. `CLAUDE.md` 约定：禁令、先读顺序。

`docs/design/` 不必填完——**第一刀要碰的那一条必须标了，其余可以是占位。**
`directory.md` 的先读顺序本来就写着「相关 `design` **一节**」，不是全部。

## TODO 只能长，不能变胖

一开始短是对的。它会长，合法的长法有两种，非法的只有一种：

- **合法一：占位裂成行。** 一个「未分解」的占位条目，随着开发变清楚，裂成两三行可执行的。
- **合法二：勾完的行沉进「已办」。** 勾完**不删**，原措辞不动，加一个 `cmd/PROMPT_xx.md` 指针和结案日期，搬到文件末尾。
- **非法：一行变胖。** 行里长出公式、完成标准、拍板记录——内容爬到了错的层，TODO 就成了第二份路线图（`directory.md`）。

判据一句话：**一行永远只是「点名 `design` 的某一节」加一个勾选框**（已办行多一个指针和一个日期，不多别的）。
细节往 `design` 走，不往 TODO 里塞。
未分解的占位行写明「占位，未分解」——它不是一刀，闸一不放它过。

**已办区是把名字欠的那一格补上，不是新发明。** `在办` 这个层名取自公文三态——
**待办 / 在办 / 已办**——可「已办」在这一层里一直没有落点：**旧规矩勾完就删**，案子结了反而什么都不剩。
`cmd/` 留得住的是**具体实施细则**（当初让干什么），留不住的是**人立案时写的那句话**。
两件事不是一件：**TODO 那行是概要，`cmd/` 是细则**——粒度不同，谁也算不出谁。

**已办区和 `cmd/` 互为对账的两边。** 每一份 `cmd/PROMPT_xx.md` 在 TODO 页上恰好出现一次，
每一条已办恰好点名一份 `cmd/`；对不上就是有一刀没落盘，机器一跑就知道。
**一份 `cmd/` 在那一页只有一个落点，就是它自己那一行**；行外不另起一段讲它，
否则对账就多出一个指针。**别把它写成第二份路线图**：一刀一行、一个指针，
不是「做过什么」的叙述——叙述在 `cmd/`，事实在 `design/`。
为什么这一份存得、而「已定条目清单」存不得，判据见合同层（母本的落点是 `paradigm.md` §5 末段）。

**老人老办法，新人新办法。** 旧规矩勾完删行，之前那些刀的原措辞捞不回来；
补救格式是**占位 + 简要概括 + 注明「原措辞无法寻回」**，这样的行只占位置、不参与对账。
新的一刀一律严格按格式来，不许再用补救式。

**未定怎么变已定：收口时回填。** 一刀做完，若它顺手回答了某个占位问句，领班在对账里点名：
「本刀回答了 `design/X` 的占位问题 Q，建议升格」。升格和勾选一起，由人在闸二定。

**升格就是在那一行前面加一个标记。** 不是一句表态，是一个**能 diff 出来的动作**——
和勾 TODO 完全同性质：人决定，落笔可以代抄，决定权不下放。

所以闸二不只做减法（勾 / 不勾），也做加法（**发一次授权**）。
这是「未定的东西逐渐清晰」唯一的落盘出口——不在收口里点名，它就永远只是参考。

## 工作单元 = 一刀

- 待办只有 `docs/TODO.md`。
- **一次只做未勾的一行。** 不发明新阶段，不顺手并刀。
- 代理不准自己勾。勾选是人看完红绿之后的管理动作。
- 没有本刀卡片（`docs/SESSION.md`），不准改 `src/`。

## 状态在磁盘，不在聊天

```text
docs/TODO.md               勾选清单；一次一行；勾完移进页末「已办」，只增不删
                           已办一行 = 原措辞 + 一个 cmd 指针 + 结案日期
docs/cmd/PROMPT_*.md       可贴的一刀指令；**本刀的许可面就是它**，闸一之后不再动
                           只增不删——这一层唯一的**指令全文**
docs/SESSION.md            指向本刀那份 cmd 的链接 + 运行态；本页覆盖，被指的只增不删
                           不复述卡片字段；实现读链接指的那份，不读这里
```

下一刀覆盖 `SESSION.md`，上一刀聊天可以扔——因为该留的已经在 `docs/cmd/` 里，只增不删。
**别只写一半。** ② 产出的是**一份卡片 + 一个链接**：`PROMPT_xx.md` 新增一份；
`SESSION.md` 整篇覆盖，只装指向它的链接和本刀的运行态。**不是两份卡片。**
**实现读的是链接指的那份，不是 `SESSION.md`**——理由不是规矩好看，是那份改不动：
**许可面定在闸一，之后不再动**（收口记录只往后追加，仍是只增不删），
没人能中途悄悄改它，而 `SESSION.md` 整刀都在变。
只写 SESSION 的代价是排障时翻不到「当初到底让干什么」——那一刀的卡片早没了，TODO 那行也早删了。
「继续推进」只够沿着当前卡片走下一步，不够当扩大范围。
聊天里点头不算许可；许可面就是卡片本身。

## 卡片最低字段

| 字段 | 干什么 |
|---|---|
| 状态 | 等批准 / 施工中 / 已收口 |
| 本刀是 TODO 哪一行 | 原文锁死，不发明 |
| 现状 | 实现会踩的坑，写在开干之前 |
| **交什么** | 3–6 条可验收；写到哪些路径 |
| **不交什么** | 本刀明确不做 |
| 禁令 | 本刀不可破的短列表 |
| 验收命令 | 可复制；工作目录是项目根 |
| 独立审查 | 是 / 免（改了 `src/` 就是；写「免」要说明这一刀为什么不需要） |

写卡和改核之间有一个**停**。没说「按卡片做」不开始实现。

## 人每天只做四件事

1. 看 `docs/SESSION.md`
2. 看验收红绿
3. 决定勾不勾 `docs/TODO.md`
4. 拒超售

人是产品负责人，不是结对程序员。

## 收口纪律（领班收口 = 绿落盘 + 对账）

一刀里，**tester（以及需要时的审查）做完之后、请人勾 TODO 之前**，领班做收口。就这一段，两件事一起做（派了审查就是三件）：

1. **绿必须落盘。** 卡片里的验收命令真跑一遍，stdout / pytest 写进 `.tmp/`（或报告附件）。对人说话时指这份文件，禁止只在聊天里说「全绿」。
2. **对账。** 打开 `SESSION.md` 的「交什么」，逐条写：做到 / 没做到 / 打回 TODO。没交的不准写成「待下一阶段」了事，也不准自己勾选。本刀若顺手答了 `design/` 里某个占位问句，在这里点名，建议升格为已定——建议而已，落笔在人。
3. **代抄审查那一页。** 审查不写文件，它的结论只能是发言，落盘只能由领班代劳——**照抄、标出处，不摘要、不合并、不改措辞**。领班派了实现和测试、又要说「建议勾不勾」，是有利害的那只手；这一条防的就是它顺手把结论揉平。理由见 `roles.md`。

然后才告诉人：改了哪些路径、落盘日志在哪、对账表、请人决定勾不勾。审查那一页**和对账表并列呈**，不塞进对账表的某一条；领班的不同意见写自己那栏。

其余：

- 不 commit / 不 push，除非人本回合点名。
- 新文件只能落在 `directory.md` 那张图里；不写到项目外。
- 对用户用简体中文；代码和标识符用英文。

## 全程

开桌一次性（见上面「开桌」）：换根 → 议事 → 人落 `CLAUDE.md`（约定）→ 人和规划席立 `docs/design/` 章节（进度三态）→ 写下 `docs/TODO.md` 第一版。**合同不必填完，但第一刀要碰的那一条必须已标记。** 之后每一刀都是 ① 到 ⑧ 一圈：

## 退卡：做不到 ≠ 做错了

红测、破界、核散是**做错了**——有东西可对，走完 ⑥⑦ 由人打回。
**做不到**是另一类：卡片自相矛盾、合同根本没写、或者只剩下要偏离合同的折衷。这时候继续往下走是空转——测试测什么、审查审什么。所以 builder 当场**停**，退卡，不走 ④⑤⑥。

**什么时候必须退卡**（任一条成立就不许再试）：

- 下一步要动的东西**超出卡片**：碰卡片没点名的路径、要改合同、要放宽验收命令。
- 试满三条路仍不成（和 `verify.md`「约 3 轮仍无定性」同一个止损）。

**退卡交什么**（写进 `.tmp/`——builder 不能写 `docs/`；由领班代抄呈人，和审查那一页同一个机制）：

1. 卡上**哪一条**做不到。引「交什么」的原文，不写「这刀太难」。
2. 试过哪几条路、各自为什么不行、证据在 `.tmp/` 哪个文件。
3. **卡在哪一层**——这一条决定往回退几步：

| 卡在 | 退到 | 谁改 |
|---|---|---|
| 卡片自相矛盾、验收命令不可能通过 | ② 写卡 | 规划席 |
| 合同没写，或两处互相矛盾 | 合同层 `docs/design/` | 人 + 规划席 |
| 合同清楚，但代价大到要折衷 | **人** | 只有人 |
| 合同和口径都清楚，纯粹不会写 | ② 缩小卡片重开 | 规划席 |

4. 要折衷就**摆选项**：每条写偏离合同的哪一句、代价是什么、有没有一条能失败的新判据。

**builder 有提议权，没有采纳权。** 折衷就是偏离合同，而 `directory.md`「4 不能代替 2：代码悄悄偏离设计文档，等于换合同」。摆出来给人选是合法的；自己选了做下去，是第 6 类失败（散了先改数值旋钮）的一般形式。这和审查「有发言权、没有否决权」、测试「写红测、不修到绿」是同一条骨架：**发现问题的手不是拍板的手。**

退卡不算这一刀失败，多半说明**闸一放过了一张不该放的卡**。退卡那一页要反过来喂给 ②：下次这类卡的「现状」栏该写什么。

两道闸就是人每天四件事的位置：闸一 = 看 `SESSION.md` + 拒超售，闸二 = 看红绿 + 勾 `TODO.md`。闸与闸之间人不插手。

角色顺序见 `roles.md`。验证条款见 `verify.md`。写权限那一面（层 × 手）见 `diagram.md`。
