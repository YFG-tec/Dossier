# 验证与排障

不铺进宿主工作区。原则见仓库根 `readme.md`。交付落点见 `directory.md`。

## 验证诚信

主要从 `31` 抽；另两桌的「不能只靠看起来像」是弱形式。目录上的含义：结论写在 `docs/reports/`，数字来自 `src/` / `tests/` 的机器产出，图内嵌在报告里。

- 禁止同义反复：计算值与期望值不能同源。
- 写测试先问：什么样的实现 bug 会让它报错？答不上来就重写。
- 「通过」只用于预先声明的量化判据，且只出现在交付层。`.tmp/` 只写「实测得到 / 预测被否定 / 未定」。
- 未做的写「未实现」，不写「待下一阶段」。
- 收敛至少 3 个网格，给实测阶，不说「残差变小了」。
- 报告数字对回 JSON / 日志，不凭记忆；口径对齐要写明。
- **图是断言。** 必须打开看。坐标 + 单位 + 网格/时间参数。
- 控制组 / 故意的错误实现要画在图上，并在读图里点名。

阶段报告最低结构：

1. 目的与判据
2. 方法与参数
3. 可复制的运行命令（入口在 `src/` 或 `tests/`）
4. 结果：表 + 内嵌图
5. 限制：本结果推不出什么
6. 结论：对照判据逐条 通过 / 未通过 / 未测试

探索要进 `src/` 的门槛预先写在 `docs/design/` 草案里：收益/代价、不破坏旧判据、一条能失败的新判据。不满足就写「实测不划算，不实现」。

## 排障也是开发流程

散了先分类，再改 `src/`。定性书面四件套，缺一件不准动离散：

- 哪一项
- 哪个时标
- 属于哪一类（初值 / 边界 / 稳定帽 / 合同 / 真泄漏）
- 证据在哪个 `.tmp/` 文件

只跑过探针 ≠ 已定性。禁止把拧旋钮当第一修法。
约 3 轮仍无定性：停堆标量，图出到 `.tmp/`，看形态再决定。
要正式留证，进引用它的那份文档所在层的 `figures/`。禁止 `docs/figures/`。

## 环境只留与复现有关的

- 解释器钉在项目内 `.venv`，命令写进卡片和报告。
- 画图不弹窗。
- 命令从项目根复制即可跑。

语言栈和同步脚本是项目自己的，不进公共范式。
