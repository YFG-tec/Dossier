# 目录

不铺进宿主工作区。原则见仓库根 `readme.md`。三桌对照见 `sources.md`。
收哪些目录进公共层，按提取原则甄别，不是三桌并集。

三桌不是按文件类型分目录（「代码放一起、文档放一起」），而是按**权威等级**分目录：谁说了算、谁可以写「通过」、谁明天可以扔。

## 三桌顶层对照（历史快照，不是目标态）

```text
Xenia (mhd/)                29_slow_mhd                 31_operator_split
─────────────────────       ─────────────────────       ─────────────────────
CLAUDE.md / AGENTS.md       CLAUDE.md / AGENTS.md       CLAUDE.md / AGENTS.md
docs/                       docs/                       docs/
  TODO.md SESSION.md          TODO.md SESSION.md          design/          ← 合同
  cmd/ ROADMAP.md …           cmd/ design/ report/      TODO.md            ← 落在根上
  reports/                    figures/                  reports/           ← 交付在根上
src/                        src/                        src/
tests/                      tests/                        opsplit/         ← 库
examples/                   examples/                     tests/           ← 验证阶梯
.tmp/                       .tmp/                       .tmp/
utils/ scripts/             research/                   （无 examples）
papers/ codes/              papers/ codes/
```

一眼能对上的公共层只有六块。名字可以争，职责不能混：

| 层 | 三桌里的名字 | 权威 | 寿命 |
|---|---|---|---|
| 约定 | `CLAUDE.md` `AGENTS.md` | 每会话怎么干 | 和项目一样长 |
| 合同 | `docs/design/`（Xenia 是 ROADMAP / KERNEL 等长文） | **看桌分两档**（下同）：**业务类**装物理与离散事实，**以及还没定的那些问题**；**管理类**只服务方案思路 | 业务类改了必须同步实现；管理类**落地牵头一律在 `TODO`**，反映到行里才算数 |
| 在办 | `TODO.md` `SESSION.md` `docs/cmd/` `queue.md` | 现在这一刀 | 两种寿命三种角色：TODO 勾完移进「已办」、`cmd/` 结案后只增不删（退卡的卡留档盖章），SESSION 下一刀覆盖；queue.md 活过序列走完（授权历史，不随刀覆盖） |
| 实现 | `src/` | 可复现逻辑 | 和项目一样长 |
| 交付 | `docs/reports/`（算例叙述仍可在 `examples/*/REPORT.md`） | 对外说「通过」 | 阶段结束入库 |
| 草稿 | `.tmp/` | 零 | 探针、dump，默认不进 git |

其余都是加厚，不是入场券：`tests/` 与 `examples/` 常分开；`research/` 是设计之前的调研；`papers/` `codes/` 是只读对照；`utils/` 是尺子，不是公开 API。批跑 / 同步入口走 `examples/`，不另开 `scripts/`。

### 合同那一行为什么分两档

**轴是现成的，不新开一根**：管理类 / 业务类，正文在 `workflow.md`「标记只落在业务结论上」。
那张表已经写着管理类的 `design/` 用宽松语言写**思路**、记录落 `TODO.md`。
这里只是把同一根轴兑现到权威和寿命两栏。

分档的理由是**能不能被引成判据**。业务类那一边，`design/` 里一条一条定下来的是物理与离散事实，
实现偏离它就是偏离事实，所以「改了必须同步实现」。管理类那一边没有这种东西可引：
宽松语言写的是思路，**思路服务方案设计，不当红绿**。
落地要牵头的话进 `TODO.md` 那一行，反映到行里才算数。

**代价照写**：管理类桌的 `design/` 从此拦不住实现。拦得住的是卡和行，不是它。
换来的是不会有人拿一句思路当条款去判红绿——**那种判据一旦立住，改思路就等于改判据，
而思路本来就是要改的**。

## 按权威分层，不要按「文档 / 代码」二分

代理默认会把「能写字的地方」当成同一权限。目录设计要让错误落点变难：

```text
权威从高到低（向下依赖，禁止向上污染）

  1. 约定        CLAUDE.md / AGENTS.md
  2. 合同        docs/design/          业务类：实现跟它走，冲突先改它
                                       管理类：只服务思路，牵头落 TODO
  3. 在办        docs/TODO.md
                 docs/SESSION.md       每次整篇覆盖
                 docs/cmd/PROMPT_*.md  与 SESSION 同一套公式
  4. 实现        src/                  库；求解器只住这里
  5. 把关        tests/                根上，不进 src/；能独立失败
  6. 演示        examples/             算例、长跑、给人看的图文
  7. 交付        docs/reports/         阶段报告 + 随报告的 JSON/图
  8. 调研        research/             还没升格成合同；不是草稿箱
  9. 草稿        .tmp/                 可写可跑；不准自称通过
 10. 对照        papers/ codes/        只读
```

硬规则都是跨层的，不是文件格式的：

- **4 不能代替 2。** 业务类桌：代码悄悄偏离设计文档，等于换合同。
  管理类桌那边 `design/` 不是合同，偏离它不叫换合同；那一档要换的是 `TODO` 那一行，
  行没改就动手，才是这一条在管理类桌上的样子。
- **9 不能代替 4。** `.tmp/run_*.py` 被报告引用 = 交付不可复现（`31` A-1）。
- **9 不能写入 7。** 探索产物不进 `docs/reports/`。
- **8 不能当 9。** 调研稿不是 dump 箱（`29` 写明了）。
- **6 不当 5。** 算例长跑不是调试内环，也不代替模块单测。
- **7 只能引用 4 + 5。** 「验证通过」的入口必须在 `src/` / `tests/`。

### 打卡义务沿着这张表递减

**卡守的是承诺**，而承诺住在高层。这不是新开的一根轴，就是上面那张表本身：

| | 要不要卡 | 对价 |
|---|---|---|
| 约定 / 合同 / 在办 / `src/` 契约 | **要** | 说的话算数 |
| `examples/` | **不要** | `examples/<case>/REPORT.md` 不是阶段门的「通过」文书 |
| `.tmp/` | **不要** | 不准自称通过 |

**免卡不是白给的，对价是「说的话不算数」。** 三档的代价这份文件各自已经写过，
这里只是把它们排成一列。

**`examples/` 免卡的理由不是「权威低所以随便」**——它恰恰是合法的可重跑入口，
和 `.tmp/` 正相反（下文「机出图必须有可重跑入口」那条把它和 `src/` `tests/` 并列）。理由是**不动核心**：
只往里加算例、加叙述、加图，**加东西不改承诺，所以不用先立案**。
一旦要改 `src/` 的契约或 `tests/` 的口径，就不是这一档的活了。

**`tests/` 不上这张表。** 它不是「要不要卡」的问题——它是一刀内部的第 ④ 步，
许可面本来就是当刀那张卡，跟着卡走。方向也已经定死：跟卡写红测、收紧，是测试席本职；
**放宽口径是人的那一爪**，不随卡自动走（见 `roles.md` 与 `verify.md`）。
「跟着卡走」两头都算数：**卡撤了，这一层也要跟着清账**——退卡时 `src/` 和 `tests/` 两层都过一遍
（`src/` 机械回滚，`tests/` 由测试席自己判删还是改；见 `workflow.md`「退卡之后收摊」第 2 条）。

## 建议的公共顶层（讨论稿）

```text
<project>/
  CLAUDE.md                 每会话约定（细）
  AGENTS.md                 同一份约定（短）
  docs/
    TODO.md                 唯一待办；一次一行
    SESSION.md              本刀卡片；覆盖写
    queue.md                序列单：授权过的行序＋当前停在哪＋断点。授权原话逐字落这里；代理席只改「状态」「断点」两列，序列内容非经人不改
    cmd/                    可贴的一刀指令 PROMPT_*.md
    design/                 合同：物理 / 离散 / 草案
    reports/                阶段交付（报告是文档，不进仓库根）
  src/<pkg>/                库：网格、EOS、通量、推进、诊断、绘图
  tests/                    把关：一模块或一阶一文件
  examples/                 演示：一算例一目录
  .tmp/                     草稿；gitignore，只跟踪 README.md
  .venv/                    项目解释器
```

加厚才出现的目录，默认不要预建：

| 目录 | 何时才要 |
|---|---|
| `research/` | 有持续文献对照、还没写成 `design/` 合同 |
| `docs/README.md` | `design/` / `reports/` 长到找不到；目录名不够当地图时才写 |
| `utils/` | 长期尺子 / 校准，且明确不是公开 API |
| `papers/` `codes/` | 本地对照材料；只读 |

`.claude/`、`.cursor/` 对**桌**是工具配置，不是项目内容层。有没有角色**文件**是档位问题，见 `roles.md`。
对 **Dossier** 而言它们是产品本身，规划在 `claude-code.md` / `cursor.md`。

这一段说的是**桌**长成什么样。母本自己不长 `src/` `tests/` `.venv/`。
`docs/` 是给桌的骨架，由 `init` 铺到宿主上；`docs_meta/` 是母本自己的规划与品牌，不铺进宿主工作区。见 `naming.md`。

## `docs/` 内部怎么切（→ harness）

不设常设的 `docs/README.md`。目录名就是地图；开刀顺序见在办层和 `CLAUDE.md`。人每天四件事见 `workflow.md`。
SMAIRT 那种 CONTEXT_INDEX 是文件堆成一摊才要的；权威分层之后，索引就是这棵树。
`design/` / `reports/` 长到找不到，再写一页地图（加厚）。

开干时的先读顺序（锁在 `CLAUDE.md`，不另写成一页）：

```text
议事先读     design 那一节 → 当材料读，不当判据
开刀先读     TODO 该行 → SESSION → CLAUDE 禁令
排障先读     SESSION 四件套空位 → 本刀 .tmp/ → 相关 tests
写报告先读   SESSION 交什么 → tests/验收日志 → 卡里预先声明的判据
```

**设计那一层单开一档，不留在「开刀先读」里。** 开刀那一档是手准备动文件时读的，
把设计那一节摆在这一档，等于请手把一段思路当判据用。议事是另一回事：
那时候要读的正是思路，读完得出的是方案，不是红绿。业务类桌真要拿它当判据，
得像别的判据一样先写进卡里（`verify.md` 第一条：「通过」只用于预先声明的量化判据）。

写报告那一档同理：交出去的「通过」只能引卡里预先声明的判据和跑得出来的日志，
不引设计那一层的措辞。

不要另开 `prompts/`，也不要另开 `USERGUIDE.md`，也不要另开 `archive/`。
收口后该留的事实进 `design/`，通过进 `reports/`，探针仍在 `.tmp/`。

```text
docs/
  TODO.md          近期待办 + 页末「已办」。不是第二份路线图，不是设计文档
                   已办一行 = 原措辞 + 一个 cmd 指针 + 结案日期，只增不删
  SESSION.md       当前刀，下一刀整篇覆盖。不是历史——指令全文在 cmd/，结案后只增不删
  cmd/             本刀指令。和 SESSION 同一套公式，不是设计文档
                   结案后只增不删；退卡的卡留档盖章：这一层唯一的指令全文
  design/          合同：已定 / 草案 / 占位。草案标明「草案 / 未实现」；占位写成问句
    figures/       合同层共用图（示意、模板、几何；动图也算图）
  reports/         交付。先有判据再有「通过」
    figures/       交付层共用图
```

**`design/` 还是未定事项的收容层，不只是存档。** 三态里的「占位」——只有问题、没有答案、写成问句——住在这里。
少了这一层，未定的东西会往在办层挤：`SESSION.md` 每刀覆盖，扛不住，于是全堆进 `TODO.md`，
那份待办就开始长裁决、长公式、长日期，变成第二份路线图（Xenia 的 346 行是实例）。
**在办层留不住话，合同层才留得住**；长期的东西必须落在不被覆盖的那一层。开桌与升格路径见 `workflow.md`。

**附件跟引用它的文档走。禁止 `docs/figures/`。**
`docs/` 根上不另开图库，主层级只留在办、合同、交付。
`design/figures/` 和 `reports/figures/` 是各层的公共服务：有该层第一张正式图时再建，不是加厚。
普通文档不另建夹，正文用 `![论点](figures/xxx.png)` 内嵌。动图（gif / 短动画）算图，仍进 `figures/`；
声音等少见附件同层，不必另起 `assets/`。
只有附件多到「一份文档自己成夹」才更易读时，才建与 `.md` 同名的子目录
（例如 `reports/C4_3_a_B7.md` + `reports/C4_3_a_B7/`）。默认不要。

两层都要同一张图：复制一份进各自的 `figures/`，不准抽到 `docs/` 根上共用。
没有引用它的正式文档，就没有正式图。探针仍在 `.tmp/`。
从 `.tmp/` 拷过去不算升格：机出图必须有可重跑入口（`src/` / `tests/` / `examples/`，不准是 `.tmp/run_*.py`）。
手绘示意跟合同走，草稿仍可在 `.tmp/`，`design` 正文内嵌才算升格。

| 别混 | 为什么 |
|---|---|
| `TODO` vs `design` | 待办是勾选；设计是事实**和还没定的问题**。TODO 一行点名 design 的某一节，不把公式抄进 TODO 当第二真相。TODO **只能长**（占位裂成行；勾完沉进「已办」，不删），**不能胖**（行里塞细节） |
| `SESSION` vs `cmd/` | **不是两份公式，是一份加一个链接。** `cmd/PROMPT_xx.md` 给人粘贴，**结案冻结、结案才永久**（结案后只增不删；退卡的卡留档盖章），是这一层唯一的**指令全文**；SESSION 给本仓库角色读，下一刀覆盖，装的只有一个指向那份卡的链接 + 本刀的运行态。**禁止各写一套公式**——旧办法要求两边写得一样（靠人对齐），现在只写一份，没有第二份可以走样 |
| `TODO` 已办 vs `cmd/` | **结案之后**都留得住，**互为对账的两边**。已办行是**概要**（人立案时的原措辞 + 一个指针），`cmd/` 是**具体实施细则**。粒度不同，谁也算不出谁；每份 `cmd/` 在 TODO 页上恰好出现一次，对不上就是有一刀没落盘 |
| `cmd/` vs `design/` | **结案之后**都留得住，但留的不是一种东西。`cmd/` 是**指令**的流水（当初让干什么），`design/` 是**事实**的落点（后来定下了什么）。混了就长出第二个 `archive/` |
| `design`（草案）vs `reports` | 草案里的数是预测或实测笔记；报告里的「通过」必须能复现 |
| 层内 `figures/` vs `docs/figures/` | 图只住 design / reports 各自的 `figures/`。根上不准开 `docs/figures/`；重复就复制 |

`31` 的合同几乎全在 `docs/design/`，在办文件却在根上（`TODO.md`）——职责对，落点散。`29` 把在办、合同、交付都收进 `docs/`，地图更清楚。**建议在办文件统一进 `docs/`。**

## 代码侧：`src/` / `tests/` / `examples/`

三桌都把「库」和「怎么证明库对」分开，只是切法不同：

| | 库 | 把关 | 演示 |
|---|---|---|---|
| Xenia | `src/xmf/` | 根 `tests/`（契约 / ABI / 模块） | `examples/<name>/`（`run.py` + `REPORT.md`） |
| `29` | `src/slowmhd/` | 根 `tests/` | `examples/` 脚本 + `docs/report/`（现名，公共层用 `docs/reports/`） |
| `31` | `src/opsplit/` | `src/tests/`（Test A–H 各一文件） | 无独立 examples；报告就是演示 |

**拍板：`tests/` 放仓库根上，不要放进 `src/`。** `31` 能工作，但是把它的「验证阶梯 = 产品」误当成默认切法。公共范式里测试是把关层，不是库的一部分。

理由：

1. **权威分层要看得见。** `src/` 是求解器；`tests/` 是专门用来让它失败的。塞进 `src/tests/`，代理会把两层当成同一权限。
2. **两席写不同的树。** 实现的手改 `src/`，测试的手改 `tests/`。路径分开，比靠角色名称自觉便宜。
3. **报告入口仍然合法。** 「通过」可以引用 `src/` **或** `tests/`，不准引用 `.tmp/`。
4. **包装干净。** 测试进包、进 wheel 是后患。
5. **和 `examples/` 的三角更清楚。** 库 / 把关 / 演示是三件事。验证阶梯仍是 `tests/`。

```text
src/<pkg>/          库：网格、EOS、通量、推进、诊断、统一绘图
tests/              把关：一模块或一阶一文件；能独立跑、必须能失败
examples/<case>/    演示：run.py + REPORT.md + 本算例图；批跑 / 出图 / 同步入口也在这里
```

`31` 那种「整个项目就是一架验证阶梯、没有独立算例」：测试仍然放根上 `tests/`，报告引用 `tests/test_a_*.py` 即可。
`utils/` 若存在：只放长期尺子，不算公开 API，也不要变成第二套 `src/`。
不另开 `scripts/`。Xenia 的 `sync_xmf.py` 那种入口，原则上也进 `examples/`。

## `.tmp/` 是目录设计，不是 gitignore 细节（→ harness）

- 代理临时文件有且只有这一处；禁止落到 `docs/`、`research/`、桌面、系统 Temp。
- 可直接写、改、跑，不必问。除 `README.md` 外不 `git add`。
- **零权威。** 不准写「通过」；不准当报告运行入口；图若只要自己看，也出在 `.tmp/`。
- 探索脚本复用 `src/` 只读接口；新算子先写在 `.tmp/` 脚本内部。要入库走提升门槛，再进 `src/`。

`31` 把这层写成了正式模式（`tmp-experiment`）。缺这一层，求解器会先长在草稿里，再被报告引用——目录一旦被污染，后面的验证条款全空转。

## 交付落点：报告进 `docs/reports/`

| 桌 | 阶段报告（现名） | 机器产出 | 算例叙述 |
|---|---|---|---|
| `31` | 根 `reports/` | 同目录 JSON + `figures/` | 无独立算例目录 |
| `29` | `docs/report/` | 图在 `docs/figures/` 或 `.tmp/` | `examples/` 脚本 |
| Xenia | `docs/reports/` | 多在 `.tmp/` / 算例目录 | `examples/*/REPORT.md` |

**拍板：阶段报告统一放 `docs/reports/`。** 报告本质是文档，不在仓库根另开一套 `reports/`。

随报告的 JSON、内嵌图进 `docs/reports/figures/`，和正文一起入库；普通报告不另建夹。
探针图仍在 `.tmp/`。没有引用它的报告，图不准进 `docs/`。
合同也要同一张：复制进 `docs/design/figures/`，不准升到 `docs/figures/`。

算例叙述仍可留在 `examples/<case>/REPORT.md`，跟可跑入口走；它不是阶段门的「通过」文书。阶段门的结论只写 `docs/reports/`。

## 一张目录把两席的写权限钉死

「写」= **这一层归你，改了不必请示**，不是「谁敲键盘」。这套东西的前提是人不敲键盘，按落笔算整张表都没意义。

| 路径 | 规划席默认 | 实现席（有卡片之后） | 代理席（序列在办时） | 人 |
|---|---|---|---|---|

**「实现席」这一列还要再拆三只手**，`src/` 和 `tests/` 不归同一只手。
手名取自 `roles.md`（**实现** / **契约测试** / **审查**），第二只简写成两字；
第二只手叫「测试」不叫「把关」——把关是 `tests/` **那一层**的名字，层和手不共用一个词：

| 手 | 写 | 不写 |
|---|---|---|
| 实现 `builder` | `src/`（卡片「交什么」点名的）、`.tmp/` | `tests/` 的验收口径 |
| 测试 `contract-tester` | `tests/`、`.tmp/` | `src/` 算法 |
| 审查 `review` | **无** | 一切，含 `.tmp/` |

压成一行就等于说「改核的手可以改测试口径」，`readme` 五条里的第二、三条当场作废。
三只手可以同坐一个会话（轻档），但顺序和写路径不变。职责全表见 `roles.md`。

用户说「继续推进」只打开规划席路径，打不开 `src/`。

**约定层两席都只读。** 它是第 1 层，两席住第 2、3 层，改它就是向上污染；
更要紧的是，被约定管着的手要是自己就能改约定，约束就是装饰品（`readme`「防的从来不是人，是不受约束的智能体」）。
起草 `CLAUDE.md` 仍是规划席的活，落槌的是人——和「改核的手不改测试口径」同一条。

**合同层人和规划席共写。** 物理与离散的口径是人的东西，规划席代笔。
人不写实现、不写把关、不进 `.tmp/`；往右只剩看红绿。这张权限面画成图见 `diagram.md`。
角色职责见 `roles.md`。
