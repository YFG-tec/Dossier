# 角色与档位

换根不带走。原则见仓库根 `readme.md`。写权限路径见 `directory.md`。
各 harness 落成哪些文件：`claude-code.md`、`cursor.md`。

目录回答「写到哪」；角色回答「谁许写」。两者对同一张权威图。
角色不是人设，是**写权限 + 失败时许做什么**。一个代理兼写规格、实现、测试、审查，目录分层会立刻被绕开。

## 两席

两席对应两种 harness，分工不是风格差异，是**能力差异加上权限差异**：

| | 规划席 | 实现席 |
|---|---|---|
| 典型环境 | Cursor 这类：读全树、议事、改文档快 | Claude Code 这类：能长时间跑工具、改文件、跑测试 |
| 干什么 | **开桌议事**、读合同、写卡、对账 | 按卡片改 `src/`、写测试、落盘日志 |
| 默认可写 | `docs/` `research/` `.tmp/` | 卡片「交什么」点名的路径 + `.tmp/` |
| 说「继续推进」时 | 只够写卡 / 改文档 | 打不开——没有卡片不许动核 |

选哪个 harness 坐哪一席可以换，**两席必须是两个会话**这一条不能换。
同一个会话里既议事又改核，卡片就退化成事后叙述，许可面消失。

接口是在办层三份文件，不是互读聊天。对账读落盘产物，不要猜另一席刚说了什么。

**开桌那一段是规划席唯一一次不写卡的正事。** 和人把大框架聊透，把 `docs/design/` 的章节立起来，
分成已定 / 草案 / 占位；聊到能写出第一刀的判据就停，不把没想明白的细节当成已定写下去。
这一段没有卡片，因为它就是在造出第一张卡片能引用的东西。规矩见 `workflow.md`「开桌」。

**原则上角色要分开**，不因项目早期、单会话、没 agent 文件而取消。文件和分窗是落地厚度，不是「可以混岗」的许可证。

## 公共角色（对目录一层）

| 角色 | 只许动 | 不许动 | 失败时 |
|---|---|---|---|
| **领班**（主会话） | 派角色、跑收口验收、对人说话 | 自己少写核 | 告诉人勾不勾；不 commit、不勾 TODO |
| **写卡** `write-cmd` | **新增** `docs/cmd/PROMPT_xx.md`（结案后只增不删；退卡即删）+ **覆盖** `SESSION.md` | `src/` `tests/` | 写完**停**。要的是可贴指令，不是开刀。**两份都要出**：PROMPT 是历史，SESSION 是当前 |
| **规格看守** `spec-guard` | 只覆盖 `SESSION.md` | `src/` `tests/`、自己派 builder | 写完**停**。没有卡片不准往下 |
| **实现** `builder` | 卡片「交什么」里的 `src/`；`.tmp/` 探针 | `tests/` 的验收口径、`TODO` 勾选、对照材料 | 核散了先交定性，不准在核里试一刀修法；做不到或只剩折衷则**退卡**（`workflow.md`），摆选项给人选，不自己采纳 |
| **契约测试** `contract-tester` | `tests/`；`.tmp/` 试跑 | `src/` 算法 | 核错了写**红测**并回报，禁止在测试角色里「修到绿」。退卡清账时本刀的 `tests/` 也归它判：**删还是改，只这两向**，不许借机放宽（`workflow.md`） |
| **审查** `review` | 无（只读、只跑） | 一切改动；不问做法、不听自评 | 只核对结果和预先声明的标准。一页：哪条过了、哪条没过、要不要返工 |
| **规划席默认** `cursor-desk` | `docs/` `research/` `examples/` 叙述 `.tmp/` | `src/` `tests/`、派 builder | 「继续推进」只够写卡 / 改文档 |

调度（`one-slice`）和公式写法（`example-report`）不是角色。探索模式对应 `.tmp/` 层，不是第五个实现角色。

## 顺序是锁，不是建议

```text
写卡 / spec-guard  →  停，等人看卡片
       ↓ 人说「按卡片做」
builder            →  只交「交什么」
       ↓                做不到 / 只剩折衷 → 退卡，当场停，回卡片或回合同
contract-tester    →  只收紧本刀 tests/
       ↓
review             →  本刀改了 src/ 就派；SESSION 写「免」才跳过
       ↓
领班收口           →  绿落盘 + 对照「交什么」逐条对账，交给人勾选
```

禁止并行改同一份核。四个角色不要同时碰 `src/`。
卡片已由 `write-cmd` 写过且与 TODO 一致：开刀时不要再派 `spec-guard`。
**动了 `src/` 就派审查**——只分配内存、只改 ABI 也算。声明了却没接上的口（枚举写着三档，未实现的那两档静默退回默认档）正好长在这种刀上：契约测试全绿，交出去的却是个假的选择面。不动 `src/` 的刀（只改文档、只写卡）不派。

## 为什么要拆这么细

拆开的是失败模式，不是工种兴趣：

- **写卡的人若接着改核**，卡片变成事后叙述，许可面消失。
- **实现的人若顺手改测试口径**，「通过」是他把门槛挪了，不是核过了。
- **测试的人若顺手改核**，红测被消灭，合同没被检查。
- **审查的人若能写文件**，审查变成第二实现席，四件套定性会被改核代替。

审查的手不写文件。这不是洁癖，是唯一能让「审查」保持审查的办法。各 harness 怎么禁写，见 `claude-code.md`。

**审查只核对结果和标准。** 结果是落盘的数、图、测试输出；标准是卡片里预先声明的判据和 `design/` 合同。
不问怎么做的，不听实现者自评，不建议换算法、不改旋钮、不重写测试。做法是实现席的事；它只回答：这份结果对照这几条标准，过了还是没过。

**它判的是合同里写不成测试的那一部分**——「测试全绿」和「结果可信」之间那段距离。
距离能靠再写一条测试补上（性能阈值、ABI 兼容），就写测试，不要加手；
补不上（要打开图看、要对比基线、判据只能跑完才成形），才值一只只读的手。

**公共层只给位置，判什么各桌自己填。** 数值桌填收敛阶、守恒量、间断位置，
agent 尽可以叫 `numerics-review`，卡片字段写「数值审查」；
数据桌填分布漂移和静默截断，编译器桌填优化前后语义等价。
本页末那条「课题锁不抽进公共角色表」管的就是这里：公共层只写
**零写权限、改了 `src/` 就派、只核对结果和标准、产出一页、原样送达**这五条。

它是言官：**无职掌，所以能判断。** 不任一部一司的实务，不占一寸写路径，因而没有利害——
它的结论可信不是因为它尽职，是因为它无从让结果好看。便宜也是设计的一部分：
只读只跑、产出一页，是全套最省的一只手，却能把整刀送回返工。位卑而言重，低成本才独立。

有两处不像，都要记住。**审查不能风闻奏事。** 言官凭传闻即可上奏，制度故意把开口成本压到最低；
审查每句话背后要有跑得出来的数（`verify.md`「报告数字对回 JSON / 日志，不凭记忆」）。
**审查不判人，只判交出来的东西。** 言官弹劾百官，卡片里却没有「谁写的」这一栏——
评的一旦是手，红测就成了指控，实现下一刀会开始防御性写码。

**那一页要原样送到人手上。** 审查不写文件，产出只能是发言；而复述它的是领班——
派了实现和测试、并且要说「建议勾不勾」的那只手。监察的结论经由被监察那条线的调度者转述，
是这套里最后一个没堵的口子。所以收口时：

- 审查那一页**原样**落盘。领班当抄手，不当编辑：照抄、标出处，不摘要、不合并、不改措辞。
- 呈给人时，审查那页和领班的对账表**并列**，不揉进对账表的某一条。
- 领班可以在自己那栏写不同意见，但不动上面那页。

审查**没有**否决权——否决是人那一爪；它有的是**不被改写地送达**的权利。
不写文件是手段，不被改写才是目的。收口那一段见 `workflow.md`。

课题锁写在各桌自己的「不可以改」里，**不抽进公共角色表**。公共层只保留：路径、停点、红了许做什么。

## 和目录的对应

```text
docs/cmd + SESSION     ←  write-cmd / spec-guard / cursor-desk
src/<pkg>/             ←  builder
tests/                 ←  contract-tester
（无写路径）            ←  review
docs/reports/          ←  领班收口后由规划席写；实现席不擅自写「通过」
.tmp/                  ←  除审查外都可写；零权威
```

人每天仍只做四件事（`workflow.md`）。角色是给代理的；勾选、拒超售仍是人的。

## 没做这么严，原则上仍要分开

落地厚度不同，**不是**「不严的那种可以混岗」。原则上始终成立的：

- 写卡的手不接着改核
- 改核的手不改测试口径
- 写测试的手不把核修到绿
- 审查的手不写文件
- 审查只核对结果和标准，不问做法、不听自评
- 规划席说「继续推进」打不开 `src/`

单会话也能守这些条（先写卡、停一下、再改 `src/`、红了先报、审查只读、只对结果和标准）。agent 文件只是把原则变成机械隔离，不是原则本身。旧桌没有义务补文件；新桌按上表分职责，核一脏就把文件落下来。

## 档位（只谈管理厚度）

不要按物理或代码栈选档，按**目录已经脏到什么程度、一刀有多容易超售**来选。

| | 轻 | 重 |
|---|---|---|
| 目录 | `directory.md` 六块就够（`tests/` 仍在根上） | 另开 `examples/` `research/` `utils/` |
| 会话 | 规划+实现可同一会话 | 两席分开，写卡后停 |
| 角色文件 | 职责仍按上表分，可不落成 agent 文件 | 写卡 / 实现 / 测试 / 审查各一份文件 |
| 探索 | 必须有 `.tmp/` 层，否则核会长在草稿里 | 探针仍走 `.tmp/`，入库仍走一刀 |

读法：

- 角色**文件**和分窗是加厚；原则上角色仍要分开。同一窗口又写卡又改核又改测，是没守原则，不是轻档。
- 完整角色流水线在「改共享离散核」时值回票价；在「跑一个 `.tmp` 探针」时是税。
- 轻档 / 重档各 harness 落哪些文件，见 `claude-code.md`、`cursor.md`。
