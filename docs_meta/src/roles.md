# 角色与档位

不铺进宿主工作区。原则见仓库根 `readme.md`。写权限路径见 `directory.md`。
各 harness 落成哪些文件：`claude-code.md`、`cursor.md`。

目录回答「写到哪」；角色回答「谁许写」。两者对同一张权威图。
角色不是人设，是**写权限 + 失败时许做什么**。一个代理兼写规格、实现、测试、审查，目录分层会立刻被绕开。

## 两席（→ harness）

两席对应两种 harness，分工不是风格差异，是**能力差异加上权限差异**：

| | 规划席 | 实现席 |
|---|---|---|
| 典型环境 | Cursor 这类：读全树、议事、改文档快 | Claude Code 这类：能长时间跑工具、改文件、跑测试 |
| 干什么 | **开桌议事**、读合同、写卡、对账（**写卡归哪一席，由桌自己定**，见本节末段） | 按卡片改 `src/`、写测试、落盘日志 |
| 默认可写 | `docs/` `research/` `.tmp/` | 卡片「交什么」点名的路径 + `.tmp/` |
| 说「继续推进」时 | 只够写卡 / 改文档。这一格的意思是**打不开 `src/`**，不是「一定由它写卡」——由桌自己定 | 打不开——没有卡片不许动核 |

选哪个 harness 坐哪一席可以换，**两席必须是两个会话**这一条不能换。
同一个会话里既议事又改核，卡片就退化成事后叙述，许可面消失。为什么是物理隔离不是自觉：并行要独立状态、两种活要两种上下文（原理注⑤与总则）。

**两席各背一条品质要求，方向相反。** 规划席要**快**：快出结果、快出结论。
实现席要**稳**：产出稳定、准确。
一只手同时背这两条，等于一条都不背。上面那句「能力差异加上权限差异」买的就是这个。

接口是在办层三份文件，不是互读聊天。对账读落盘产物，不要猜另一席刚说了什么。

**开桌那一段是规划席唯一一次不写卡的正事。** 和人把大框架聊透，把 `docs/design/` 的章节立起来，
分成已定 / 草案 / 占位；聊到能写出第一刀的判据就停，不把没想明白的细节当成已定写下去。
这一段没有卡片，因为它就是在造出第一张卡片能引用的东西。规矩见 `workflow.md`「开桌」。

**原则上角色要分开**，不因项目早期、单会话、没 agent 文件而取消。文件和分窗是落地厚度，不是「可以混岗」的许可证。

**卡本体只由一只手执笔，哪一席执笔由桌自己定。** 另一席不改它，只在 `SESSION.md` 横线以下 review。
两边达成共识，这一刀才往下走。
review 不是事后检查，是两席之间唯一的沟通渠道——民主协商，不是补救措施。
公共层只给这个位置，**不替桌填**：各 harness 的默认见 `claude-code.md`、`cursor.md`。

## 代理席（序列立法后）

| | |
|---|---|
| 典型环境 | 有定时醒来能力、能操作键鼠屏、能派子代理的宿主 |
| 干什么 | 守序列单：按授权代笔点行、代落开工印、结案代笔（条件见下）；定时巡查读盘验结构记偏差（谓词：记偏差即断点呈人）；断点呈报；为两席备料 |
| 默认可写 | `queue.md` 的「状态」「断点」两列、`.tmp/`、当值那一刀按 write-cmd 与收口纪律的桌面 |
| 不许动 | `src/` `tests/` 条文不经本席刀；两席的卡与 SESSION（当值那一刀除外）；两席两个会话不因此合并 |

**代理席在两席外面，是第三席，不是第四只手。** 两席必须是两个会话这一条不因它松动——它住的既不是规划席的窗口，也不是实现席的窗口。

**代笔三件事的条件写死**：序列单在案（`docs_meta/docs/queue.md`）、该行判据可机读（当前刀的谓词判「可盖」，或按已授权序列点下一行）、审查无返工。三件缺一就是断点。**发授权、松判据、改序列、动根基条款、退卡、胖行，永远断点停**——这六样没有任何代笔路径。**自治随谓词走，无谓词不扩权（5.21，2026-10-06）**：常设自治权（自动发印、序列代笔、定时巡查、flash 分档等）各绑一个可盖谓词——机器可跑、一票否决、超阈自动断点呈人；只绑常设权，一次性代笔与存量裁定授权以留痕代谓词、不回溯；谓词红后人仍可裁继续，走松判据那一爪、原话逐字留痕——谓词与人阀，不许有一方形同虚设。和「只有人能做的四样」不冲突：结案代笔是序列事先把「人亲口」折成了「按式」，发授权和松判据没有折。断点判断要全局——代理席是唯一必须长上下文的席（原理注总则）。

**代理席的印是蓝印，效力与人印一致。** 印分两色：人印朱红、代理印蓝，**在文档管理上两色完全相同，仅区别操作者是人还是代理**（人 2026-10-02 裁）。文档层的「蓝」就是标注位 `--代理席落印`；将来 harness 若能渲染颜色，按同一标注位上色。固定词「闸一红印」保留当仪式名，检查认形不改。人印的落笔权与逐字纪律不受影响。

**代理席永远不 push。** commit 只落本分支，远端同步是人的动作（人 2026-10-02 裁「另外，禁止push」）。


### 副官（常驻建制）

**副官是代理席的随官，常驻，不占两席编制**（人 2026-10-02 三裁，原话见 `docs_meta/docs/design/model-routing.md`）。双职责：

- **代看**（走工具层模态）：截图巡查、图 alt 与实图核对、首屏/版面形态验收、GUI 探查——按格点名，不按刀。产出落 `.tmp/`：形态描述＋原始截图存档；「长得对不对」类验收必须带原始截图，不只交文字转述。
- **项目状态活索引**：代理席与规划席按需访问副官拿导航，主力精力留给规划和解决问题。答询三律：**带出处**（每句答案附盘上路径＋行号，答不出出处者不采信）、**带时点**（标注读于哪个 `HEAD`/mtime，盘面过时先重扫再答）、**不落结论**（答「在哪、是什么、什么状态」，不答「过不过、该不该」）。了然于胸必须从盘上现算，不靠记性——磁盘是真相，副官是索引；地图腐化（答旧盘）即失格，重建即复位。

**多模态任职资格条款挂起不删**：副官必须是多模态模型——此条当下随代理席同模型执行（人 2026-10-02 裁），主驱动原生多模态之日即资格回归之时，届时恢复上岗看图自测。

### 工牌（并行供给）

**并行刀派 subagent 施工，必须发工牌**（人 2026-10-03 点名入法）：一份自含任务文件，落 `.tmp/<刀>/<块>/brief.md`，四件套齐全——**产品路径**（唯一可写）、**草稿纸**（本块目录）、**读材料**（含卡）、**验收格**（本块专属）。工牌由领班署名起草，是分工手册的实体：subagent 只吃工牌不吃聊天上下文，「读 `<工牌路径>` 并执行其中全部指令」是唯一发射形（首演 5.14 实证：发射通道对长内联参数脆弱，工牌文件制同时解决供给与发射两问）。工牌同时压住两个机制：只吃牌不吃聊天＝干扰面；短供给＝指令密度（原理注③②）。

块间不通信、不互读草稿纸；subagent 回话落草稿纸 `report.md`，领班汇账后才写 SESSION。**工牌是许可面的载体，不是第二许可面**——卡仍是唯一许可面，工牌内容与卡冲突时以卡为准。

## 公共角色（对目录一层）

| 角色 | 只许动 | 不许动 | 失败时 |
|---|---|---|---|
| **领班**（主会话） | 派角色、跑收口验收、对人说话；docs/reports/ 的报告正文（收口后） | 只派单、不落笔核 | 告诉人勾不勾；不 commit、不勾 TODO |
| **写卡** `write-cmd` | **新增** `docs/cmd/PROMPT_xx.md`（结案后只增不删；退卡的卡留档盖章）+ **覆盖** `SESSION.md` | `src/` `tests/` | 写完**停**。要的是可贴指令，不是开刀。**两份都要出**：PROMPT 是历史，SESSION 是当前 |
| **规格看守** `spec-guard` | 只覆盖 `SESSION.md` | `src/` `tests/`、自己派 builder | 写完**停**。没有卡片不准往下 |
| **实现** `builder` | 卡片「交什么」里的 `src/`；`.tmp/` 探针 | `tests/` 的验收口径、`TODO` 勾选、对照材料 | 核散了先交定性，不准在核里试一刀修法；做不到或只剩折衷则**退卡**（`workflow.md`），摆选项给人选，不自己采纳 |
| **契约测试** `contract-tester` | `tests/`；`.tmp/` 试跑 | `src/` 算法 | 核错了写**红测**并回报，禁止在测试角色里「修到绿」。退卡清账时本刀的 `tests/` 也归它判：**删还是改，只这两向**，不许借机放宽（`workflow.md`） |
| **审查** `review` | 无（只读、只跑） | 一切改动；不问做法、不听自评 | 只核对结果和预先声明的标准。一页：哪条过了、哪条没过、要不要返工 |
| **规划席默认** `cursor-desk` | `docs/` `research/` `examples/` 叙述 `.tmp/` | `src/` `tests/`、派 builder | 「继续推进」只够写卡 / 改文档 |

调度（`one-slice`）和公式写法（`example-report`）不是角色。探索模式对应 `.tmp/` 层，不是第五个实现角色。

## 谁决定什么（→ harness）

上面那张表分的是手，这一节分的是决定权。两件事不一样：
表里那几行说的是谁动哪些文件，这一节说的是哪些事根本不归手。

**只有人能做的四样：立案（含占位裂行，第五爪）、结案、发授权、松判据。** 立案的代笔纪律——行内引原话逐字加日期——住「全程」⓪ 格，本页不复制。

**结案的显式例外（5.12，2026-10-03）：代理席可以结案。** 前提三件写死：序列单在案、
该刀谓词判「可盖」（或按已授权序列推进）、审查无返工——三件齐即结案代笔合法（勾行、
搬已办、commit；push 永禁）。这一条由「允许批印（自动发印）」推出，人 2026-10-03 裁定
显式落字，防推理链断在换模型或上下文截断处。发授权、松判据无任何例外，仍只归人。

- **结案**——勾 `todo.md` 那一行。代理不准自己勾 TODO，也不准写结案日期、不准往已办搬（序列授权下的结案代笔见下方显式例外）。
- **发授权**——给一行加标记。加一个标记就是发一次授权。
- **松判据**——放宽验收命令、改宽检查口径、接受偏离合同的折衷。

「松」只指放宽这一个方向。**收紧判据是测试那只手的本职**，本来就不在这几样里。
一处放宽讲得再有理也还是放宽，不因为理由充分就变成手能自己做的事。

人可以口头下令、由代理落笔。**是谁说了算，不是谁敲键盘。**
分界在决定权不下放，不在谁动的键。代落的那一份记录该写成什么样，
见下面「为什么要拆这么细」讲收口的那三条，第一条就是。

**报告的正文归领班，报告里『通过』的断言只许转述判据与日志**——写新的结论性判词仍是人那一爪。（6.10，2026-10-02：对账内容只有领班有，报告正文随之；36 桌口头推翻的事故形状就此销。）

**公共层只保留：路径、停点、红了许做什么。** 判什么、判到什么程度，各桌自己填。

## 顺序是锁，不是建议

```text
写卡 / spec-guard  →  停，等人看卡片
       ↓ 人说「按卡片做」
builder            →  只交「交什么」
       ↓                做不到 / 只剩折衷 → 退卡，当场停，回卡片或回合同
contract-tester    →  只收紧本刀 tests/
       ↓
review             →  本刀改了 src/ 就派；SESSION 写「免」才跳过
       ↓
领班收口           →  绿落盘 + 对照「交什么」逐条对账，交给人勾选
```

禁止并行改同一份核。四个角色不要同时碰 `src/`。
卡片已由 `write-cmd` 写过且与 TODO 一致：开刀时不要再派 `spec-guard`。
**动了 `src/` 就派审查**——只分配内存、只改 ABI 也算。声明了却没接上的口（枚举写着三档，未实现的那两档静默退回默认档）正好长在这种刀上：契约测试全绿，交出去的却是个假的选择面。不动 `src/` 的刀（只改文档、只写卡）不派。

## 为什么要拆这么细

拆开的是失败模式，不是工种兴趣：

- **写卡的人若接着改核**，卡片变成事后叙述，许可面消失。
- **实现的人若顺手改测试口径**，「通过」是他把门槛挪了，不是核过了。
- **测试的人若顺手改核**，红测被消灭，合同没被检查。
- **审查的人若能写文件**，审查变成第二实现席，四件套定性会被改核代替。

审查的手不写文件。这不是洁癖，是唯一能让「审查」保持审查的办法。各 harness 怎么禁写，见 `claude-code.md`。

**审查只核对结果和标准。** 结果是落盘的数、图、测试输出；标准只认卡片里预先声明的判据。
设计那一层算不算标准，各桌自己定：业务类那种装着物理与离散事实的，桌可以把它写进判据；
管理类那种只服务思路的，不进（`directory.md` 六块表「合同」那一行）。
不问怎么做的，不听实现者自评，不建议换算法、不改旋钮、不重写测试。做法是实现席的事；它只回答：这份结果对照这几条标准，过了还是没过。

请示的形状有人核：审卡那一页看卡上「要人点的请示」每条带不带途径附注，验收那一页看施工中的停报同样带不带。规矩本体在 `workflow.md`「跟人请示：两条途径」，本文件不复述。

**它判的是合同里写不成测试的那一部分**——「测试全绿」和「结果可信」之间那段距离。
距离能靠再写一条测试补上（性能阈值、ABI 兼容），就写测试，不要加手；
补不上（要打开图看、要对比基线、判据只能跑完才成形），才值一只只读的手。

**公共层只给位置，判什么各桌自己填。** 数值桌填收敛阶、守恒量、间断位置，
agent 尽可以叫 `numerics-review`，卡片字段写「数值审查」；
数据桌填分布漂移和静默截断，编译器桌填优化前后语义等价。
本页末那条「课题锁不抽进公共角色表」管的就是这里：公共层只写
**零写权限、改了 `src/` 就派、只核对结果和标准、产出一页、原样送达**这五条。

它是言官：**无职掌，所以能判断。** 不任一部一司的实务，不占一寸写路径，因而没有利害——
它的结论可信不是因为它尽职，是因为它无从让结果好看。便宜也是设计的一部分：
只读只跑、产出一页，是全套最省的一只手，却能把整刀送回返工。位卑而言重，低成本才独立。

有两处不像，都要记住。**审查不能风闻奏事。** 言官凭传闻即可上奏，制度故意把开口成本压到最低；
审查每句话背后要有跑得出来的数（`verify.md`「报告数字对回 JSON / 日志，不凭记忆」）。
**审查不判人，只判交出来的东西。** 言官弹劾百官，卡片里却没有「谁写的」这一栏——
评的一旦是手，红测就成了指控，实现下一刀会开始防御性写码。

**那一页要原样送到人手上。** 审查不写文件，产出只能是发言；而复述它的是领班——
派了实现和测试、并且要说「建议勾不勾」的那只手。监察的结论经由被监察那条线的调度者转述，
是这套里最后一个没堵的口子。所以收口时：

- 审查那一页**原样**落盘。领班当抄手，不当编辑：照抄、标出处，不摘要、不合并、不改措辞。
- 呈给人时，审查那页和领班的对账表**并列**，不揉进对账表的某一条。
- 领班可以在自己那栏写不同意见，但不动上面那页。

审查**没有**否决权——否决是人那一爪；它有的是**不被改写地送达**的权利。
不写文件是手段，不被改写才是目的。收口那一段见 `workflow.md`。

课题锁写在各桌自己的「不可以改」里，**不抽进公共角色表**。公共层的界线在上面「谁决定什么」那一节。

## 原理注（为什么是两只手两只会话）

- ①**注意力稀释与位置偏差**：长会话末段的指令，与会话开头的不一样重。
- ②**指令密度递降**：上下文越长，每条指令分到的确定性越薄；发射通道对长内联参数脆弱。
- ③**干扰面**：一只上下文同时装议事、卡、核、测，互相踩。
- ④**同源偏见伤审查**：自审形同虚设；新鲜上下文才是无偏的验伪者。
- ⑤**并行物理上需独立状态**：两个块同时写，状态就得各在各处。

**总则：执行的手要短上下文，领班要全局反而必须长——两种活两种上下文。**
留存判据：删掉这段「为什么」，第一次含糊处会不会被读歪——会才留，不会就退回 `design/`。

## 模型下限

每个角色都可独立配模型（应用侧绑定）；**范式管的不是型号，是每个角色的下限**。绑定可换，下限不可破：

| 角色 | 模型下限 | 一句话理由 |
|---|---|---|
| 写卡 `write-cmd` | 重 | 判据可执行性、预期值都在这只手 |
| 实现 `builder` | 沿档位浮动 | 轻刀可降；动条文、写检查脚本恒重 |
| 契约测试 | 写口径重；跑格进命令 | 能进命令的不劳模型（`check-verdict.sh` 先例） |
| 审查 `review` | **恒重** | 换弱模型＝换松判据 |
| 领班 | 重 | 对账、代抄、呈报判断 |
| 代理席 | 重 | 断点判断是它的全部价值 |
| 副官 | 必须多模态（挂起，见代理席节） | 看不见的副官是空椅子 |
| 巡查 | 无下限 | 命令、便宜模型、副官皆可 |

**换绑红线**：下限之内的浮动，代理席可调；**触碰下限——给审查降档、给写卡换轻模型——是「松判据」的另一种形状，归人那一爪**。配置面不许变成绕闸的后门。

**绑定表不进库**：谁跑在哪个模型上，真值住应用侧；仓库里只放下限表。「现状」作为副官答询的一格，从 app 侧现读，作证词不作真相。

**落地建议**：先三档（重 / 轻 / 多模态），不一角色一模型——交接面正是没有闸的地方，模型数量越多交接面越宽。

## 和目录的对应

```text
docs/cmd + SESSION     ←  write-cmd / spec-guard / cursor-desk
src/<pkg>/             ←  builder
tests/                 ←  contract-tester
（无写路径）            ←  review
docs/reports/          ←  领班收口后写正文；规划席可另写阶段叙述；实现席不擅自写「通过」
.tmp/                  ←  除审查外都可写；零权威
```

人每天仍只做四件事（`workflow.md`）。角色是给代理的；勾选、拒超售仍是人的。

## 没做这么严，原则上仍要分开

落地厚度不同，**不是**「不严的那种可以混岗」。原则上始终成立的：

- 写卡的手不接着改核
- 改核的手不改测试口径
- 写测试的手不把核修到绿
- 审查的手不写文件
- 审查只核对结果和标准，不问做法、不听自评
- 规划席说「继续推进」打不开 `src/`

单会话也能守这些条（先写卡、停一下、再改 `src/`、红了先报、审查只读、只对结果和标准）。agent 文件只是把原则变成机械隔离，不是原则本身。旧桌没有义务补文件；新桌按上表分职责，核一脏就把文件落下来。

## 档位（只谈管理厚度）

不要按物理或代码栈选档，按**目录已经脏到什么程度、一刀有多容易超售**来选。

**第二条轴：有没有「编译运行」**，也就是有没有能机械变红的东西。
没有，产出是文字不是核，把手拆开买不到保护对象——往返照付，隔离买不到，走轻档，快速完成即可。
有，且是共享离散核，重档值回票价。
这一条是结构条件，不是阶段论：**不许写成「现在还早、等成熟了再说」**。
翻转点因此是一个看得见的动作——桌上长出能机械变红的东西的那一天。
**拧档也可以走人的判断**：两条轴都读作轻、管理厚度却要重的桌（调研重、实现轻），人可以直接拧重——走的是判断，不是轴上的条件；桌在自己 design/ 记一笔『走的是判断不是轴』。

**档位拧的是领班以下那几只手，不拧席。** 席是常设的两个、两个会话，不进这张表，理由见「两席」那一节。
（人 2026-09-09 裁，`PROMPT_009`。）

| | 轻 | 重 |
|---|---|---|
| 目录 | `directory.md` 六块就够（`tests/` 仍在根上） | 另开 `examples/` `research/` `utils/` |
| 会话 | **两席仍是两个会话**；实现席内部一只手兼多职 | **两席仍是两个会话**；实现席内部按手分开，写卡后停 |
| 角色文件 | 职责仍按上表分，可不落成 agent 文件 | 写卡 / 实现 / 测试 / 审查各一份文件 |
| 探索 | 必须有 `.tmp/` 层，否则核会长在草稿里 | 探针仍走 `.tmp/`，入库仍走一刀 |

读法：

- 角色**文件**和分窗是加厚；原则上角色仍要分开。同一窗口又写卡又改核又改测，是没守原则，不是轻档。
  **轻档减的是手的份数，不是那六条原则，也不是席。** 弯了哪一条，要写明并说清代偿——不是不许弯，是不许不说。领班射程被拧（加码、收权、换载体）同一待遇：写明代偿，登记落在发出那道令的页。
- 完整角色流水线在「改共享离散核」时值回票价；在「跑一个 `.tmp` 探针」时是税。
- 轻档 / 重档各 harness 落哪些文件，见 `claude-code.md`、`cursor.md`。
