## 闸二之前，人提了一件（正文未动）

实现落完、⑤ 还没派的时候，人提了一件，**关于本刀刚落地的那一段**。原话逐字：

> 原则上，如果之前某个部分有问题，可以直接提补卡，所谓的评注功能已经名存实亡了

> 中途中断，往往意味着重写卡，后面提 commit 的形式进行修改，我们留了口子，不是问题

> 以往 session 中不断提新 commit 的方式进行更新，不是问题

第四句（人当场纠了写卡这只手的一个错误论证）：

> 评注 = PR comment，别删

**结论：正文不动，评注留着。** 底下这段是回应，不是原话（原话就是上面四句）。

**写卡这只手先前推错了一步，收回**：它说「一个不能改变任何东西的通道，
就是把聊天写进了盘」，据此建议把评注降格。**这一步是错的。**
PR comment 同样不合并任何东西，没人因此说 code review 没用。差别有两样，**都不在权限上**：

- **锚**：聊天是散的；comment 挂在**具体那一版**上，和它评的东西并排在盘上，有先后。
- **必须被回应**：聊天没人有义务答；comment 按 `4.4` 那条**必须逐条回应**——
  「原话留着 + 回应对得上」，两件同时在场才验得了连续性。**这一页此刻就是那个样子。**

所以「名存实亡」按第一句和第四句合起来读，**收窄成一半**：

| 评注的哪一半 | 归谁 |
|---|---|
| **要加卡上没有的东西**（改变许可面） | **归补卡。** 这一半确实名存实亡，本刀正文已经把它堵死 |
| **对已有的东西提意见、要求解释、逼出回应** | **留着，就是 PR comment。** 不删 |

**整个模型因此对上了**：一刀 = 一个 PR，递进修改 = 往上加 commit，
横线以下 = comment，闸二 = merge。人第二、三句说的正是这件事——
