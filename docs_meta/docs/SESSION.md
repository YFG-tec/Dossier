## 业内那一查，结论在这儿

行里写死了一条前置：落笔前真查一遍业内怎么铺，查完把结论写回行里。
行里还自我设限过一句：`copier` 那条「看上去带 `copier update`」的话没实测，不许当判据用。
**这一查已经做了，结论已经写回 `todo.md` 那一行，细则在卡上。**

**证据级别先说清楚。** 手段是网络检索；`copier` 的官方文档域、`github.com`、Spec Kit 的文档站
这三处本窗都取不到（网络策略挡下），所以拿到的是检索摘要，不是原始页，更不是实测。
**因此这一查只用来定「抄谁、不抄谁」，一格都不进验收表。** 本刀的红绿全是自己盘上跑得出来的数。

**抄 Spec Kit 那一族的规范**：动词就叫 `init`；`--here` 加位置参数两种指靶子的写法；
「已存在的一律跳过、只装缺的」这条语义。**不抄模板铺开那一族的机制。**

不抄 `copier` 的理由不是它不好，是和我们铺的东西对不上：
`copier update` 是三路合并，撞车时往文件里写冲突标记或另甩一个 `.rej`。
我们往宿主铺的 `TODO.md` `SESSION.md` 装的是真活，写进冲突标记就是把活搞坏。
`cookiecutter` 只管生成那一刻，升级要另装 `cruft`；`degit` 没有「已经有了怎么办」这一档。

**查到的最有用的一件，是 Spec Kit 那个公开的 bug 咬不到我们，而理由值得写下来。**
它的病根是母本自己拥有的文件也走 `init` 铺，于是「已存在的一律不动」把上游修补堵在门外，
所以它在往「清单哈希对得上才覆盖」那个方向走。
我们的形态里那批文件根本不过 `init` 的手：母本自己的东西躺在子模块里，
升级走 `git submodule update --remote`。`init` 只铺宿主自己的活。
**对宿主的活，「一律不动」本来就是正解，不是将就。**

清单哈希那一档本刀不采纳：相对行里写死的判据它是放松，而松判据是人的一爪。这一件记进了缺口。

**规范抄到了，所以不算自己造。** 实现自己写，只用标准库，不引任何一家当依赖。

### （一）`docs_meta/src/sources.md:44`–`:45`，论证方向翻个个儿之后

**先说翻得对的那一半。** 原句「Spec Kit 的 `specify init` 是反方向」是站在换根立场上说的——有「换根」这个参照系，才有「反方向」。换根作废之后，这个参照系没了，`specify init` 和母本的 `init` 现在是同一个方向。不翻这句，留下的就是一句说反的话。卡 `:287`–`:288` 判它必须翻，本席同意；**只换词而不翻方向会坏，翻了是对的**。同理，原句末的「嫁接比换根合适」是两种机制之间的择一推荐，新句「走的是同一个 `init`」是对唯一机制的陈述——机制从两条收成一条，句式跟着从比较句变成陈述句，这一步也对。

**再说本席读出来不对的那一处，这是本页最重的一条。**

`form.md` 说的是：`init` 是**各家通用**的词，Spec Kit **也**是其中一家。新落的 `sources.md:45` 说的是：母本那个 `init` **就是从这儿**抄的。**「也是其中一家」被写成了「就是这一家」。** 这不是换说法，这是把一条来历从「行业通用」收窄成「单一出处」，比它声称照抄的那份出处**说得更满**。
