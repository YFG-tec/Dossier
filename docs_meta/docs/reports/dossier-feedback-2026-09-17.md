## 一、这张桌为什么要对母本做二次开发

### 1. 调研是重头，落地反而是轻活

母本 `roles.md` 档位那节的第二条轴是「有没有能机械变红的东西」，
翻转点写成「桌上长出那种东西的那一天」。

本桌没有 `src/`、没有 `tests/`，那条轴上的条件**一条没成立**。
可它要干的活重得很：上千条元数据，判据得从 IMAS、从五份对照代码、
从现有的 `ids` 列里一点点对出来。对出来之后写成清单，反倒是轻活。

**二次开发**：开了 `research/` 层，加了第五份 agent `topic-research` 和第四份同名 skill。
母本 `claude-code.md:15-23` 那份四 agent 三 skill 的清单，本桌当**底盘**用、不当上限，
依据是 `roles.md` 那句「公共层只给位置，判什么各桌自己填」。

**给母本的建议**：档位那两条轴都是按「核脏不脏」画的。
存在一整类桌——调研重、实现轻——在两条轴上都读作「轻」，实际需要重档的管理厚度。
值得在档位那一节补一句：**拧档可以走人的判断，不必等轴上的条件成立**，
并要求把「走的是判断不是轴」写进桌自己的 `design/`。本桌就是这么记的。

### 2. 席的分工被人改了

母本默认规划席议事写卡、实现席改核。
本桌的人把**调研和文档撰写压在实现席的领班**身上，规划席主要辅助验收。

**二次开发**：`directory.md:277` 那行 `research/` 的实现席那格，
从「只读」改成「**只读，除 `topic-research` 这一只指名的手**」。

是**增量**，不是转移——规划席那格原样没动，它本来就能写 `research/`。
代偿三条边界（只这一只手 / 只 `research/` 这一层 / 这一层的东西引不动）
记在本桌 `docs/design/harness.md`，按 `roles.md`「弯了哪一条，要写明并说清代偿」办，
没抽进公共角色表。

### 3. 管理类刀在表上没有手

### 1 · 领班写不了报告，可报告的内容只有领班手里有

**类型**：设计层。**证据**：这份文件本身。

#### 盘上是怎么写的

`roles.md:147`：

```text
docs/reports/          ←  领班收口后由规划席写；实现席不擅自写「通过」
```

`roles.md:44`，领班那一行：

| 角色 | 只许动 | 不许动 | 失败时 |
|---|---|---|---|
| **领班**（主会话） | 派角色、跑收口验收、对人说话 | 自己少写核 | 告诉人勾不勾；不 commit、不勾 TODO |

**「只许动」那一格填的是动作，不是路径。** 整张表七只手，只有领班这一格是这样。
于是表对「领班能写什么」是**沉默**的，而 `roles.md:143` 那张落点图里，
`docs/cmd + SESSION` 归 `write-cmd / spec-guard / cursor-desk`，领班也不在列。

#### 为什么这是 bug

**a. 它把「谁说了算」和「谁敲键盘」搞混了——而母本自己两次禁止这么做。**

- `directory.md:270`：「『写』= **这一层归你，改了不必请示**，不是『谁敲键盘』。
  这套东西的前提是人不敲键盘，按落笔算整张表都没意义。」
- `roles.md`：「人可以口头下令、由代理落笔。**是谁说了算，不是谁敲键盘。**」

可 `roles.md:147` 那一行恰恰是按**键盘**分的：「领班收口后由规划席**写**」。
它用的正是同一页禁止的那把尺子。

**b. 报告的内容就是对账，而对账只有领班做过。**

`claude-code.md:64`：「tester（及需要时的审查）结束之后、请人勾 TODO 之前：
跑卡片里的验收、stdout 落盘、对照『交什么』逐条对账。」那是领班的活。

把落笔交给规划席，等于在**知道的那只手**和**写的那只手**之间插一道转述。
`roles.md:127-133` 刚刚才为审查那一页专门堵过这个口子——
「领班当抄手，不当编辑：照抄、标出处，不摘要、不合并、不改措辞」，
理由是「监察的结论经由被监察那条线的调度者转述，是这套里最后一个没堵的口子」。
**同一个口子，在报告这一层又开了一次，方向还反了**：这回转述的人连验收都没跑。

**c. 它和「审查不占写路径」不是一回事，但看起来像。**

`roles.md:118-120` 给审查零写路径写了很漂亮的理由：
「**无职掌，所以能判断**……不占一寸写路径，因而没有利害」。
那是**买来的独立性**——审查放弃写路径，换的是它的话可信。

领班放弃 `docs/reports/`，**什么都没换到**。
它照旧派角色、跑验收、对人说话，是被报告那条线的调度者本人。
不让它写，它不会因此变得独立；只会多一次抄。

**d. 「实现席不擅自写『通过』」那半句是对的，但被和另一件事捆在了一起。**

那半句防的是**实现席自评**，成立。可它防的是「写『通过』这个词」，
不是「碰 `docs/reports/` 这个目录」。两件事被压进了同一行。

领班完全可以写报告**而不写「通过」**——结案、发授权本来就是人的那一爪
（`roles.md`「谁决定什么」）。**把词管住就够了，不必把目录也管住。**

**e. 在规划席只辅助验收的桌上，这条规则的效果是反的。**

本桌的人把验收压在实现席领班身上。按 `roles.md:147` 办，
写报告的会是**没跑过验收的那一席**。那对 `verify.md` 的验证诚信是净损失，不是净收益。

#### 物证：这份文件

我是本桌的领班。我查了根因、跑了母本的检查套件、核了行号——
然后**写不了这份反馈**，只能先在聊天里交，再请人给授权。
人本回合的原话是「可写」。

**一条必须被人推翻才能得到正确结果的规则，本身就是 bug。**
而且它推翻得太容易了：口头一句「可写」，盘上不留任何痕迹。
这份文件此刻躺在 `docs/reports/`，没有卡、没有 TODO 行、没有红印——
**因为规则拦错了地方，所以绕过它的路也没有闸。**

#### 建议方向

不是授权，只是提。三条可以分开采。

1. **把 `roles.md:44` 领班那格的「只许动」改成路径**，和其余六只手一致。
   现在填动作，是整张表唯一的例外，而例外的代价就是上面这一堆。
2. **`roles.md:147` 按权威分，不按键盘分**：
   `docs/reports/` 的**内容**归领班（它做的对账），
   **「通过」那个词**归人（发授权），规划席仍可复核。
   词和目录拆开管。
3. **顺带补齐 `roles.md:143`**：领班既然要落盘（`roles.md:131` 抄审查那页、
   本桌还要写 `SESSION.md` 横线以下的对账页），那张落点图里不该没有它。

### 2 · `check-rename.sh` 第 4 条在任何新 clone 上必红

**类型**：可复现。**影响**：母本唯一的验收入口长期返回 `FAILED`。

#### 复现

```bash
cd submodules/Dossier && bash docs_meta/tests/run.sh
```

十五本跑完，十四本绿，`check-rename.sh` 退出码 1，总结论 `FAILED`。

```text
== 4. PNG 不比 SVG 旧（改了图必须重渲并回拷） ==
   FAIL: PNG 旧于或同龄于 SVG —— 跑 .tmp/icon/frame.sh 再把 frame@2x.png 回拷
```

#### 根因

`check-rename.sh:50`：

```bash
if [ "$png" -nt "$svg" ]; then
```

纯比 mtime。**git 不记录 mtime**，checkout 之后两份文件是同一时刻写下的。
本桌实测，**同一天测了两次，中间子模块又被 checkout 过一次**：

```text
# 第一次
2026-09-17 14:19:06.786523900  submodules/Dossier/docs_meta/src/figures/dossier-frame.svg
2026-09-17 14:19:06.786523900  submodules/Dossier/docs_meta/src/figures/dossier-frame.png

# 第二次，checkout 之后
2026-09-17 16:35:36.011963000  submodules/Dossier/docs_meta/src/figures/dossier-frame.svg
2026-09-17 16:35:36.011963000  submodules/Dossier/docs_meta/src/figures/dossier-frame.png
```

**两次的时间戳都整个换了，而每一次 SVG 和 PNG 仍逐字相同。**
`-nt` 是**严格**新于，同龄即判假。

**这一对读数是本条最要紧的证据**：它排掉了「某次 clone 碰巧同龄」这个解释——
**checkout 会把两份文件重写成同一个时刻，每次都是**。
所以这不是偶发，是**确定性**的——每一次新 clone、每一次子模块 checkout，必红。

#### 为什么要紧

`run.sh` 头自己写着它是「命令只保一份」的那一份，是母本唯一的验收入口。
它在**每一张把 Dossier 挂成子模块的桌上**都返回非零。

**一个必红的绿灯等于没有绿灯。**
下一个人先学会「那本红是正常的」，再学会忽略 `FAILED` 这个词。
那一天起，真红也一起被忽略了——而这套东西的全部指望就在「红了会被看见」上。

附带一处：FAIL 那句给的处置是**错的**。「跑 `.tmp/icon/frame.sh` 再把 `frame@2x.png` 回拷」——
PNG 没问题，重渲一次仍然同龄。照着做的人会做无用功，然后更确信这本检查坏了。

#### 建议方向

- **比内容，别比时间。** 把 SVG 的 hash 存进一份 stamp 文件一起提交，比 stamp 和现算的 hash。
- **或者把这条移出 `run.sh`。** 它查的是**发布端的构建新鲜度**，
  不是桌上的规矩。混在同一个入口里，代价就是上面那条。
  母本自己分过「给桌的那份是交叉编译，给母本自己的是自举」（`naming.md:65`）——
  这条属于后者，跟着前者一起跑，是射程串了。

### 8 · 人点了一件盘上没有 TODO 行的事，代理手上没有任何指令——沉默是合规的（2026-09-20）

**类型**：设计层。**证据**：本桌同一件事撞了两次，间隔三天。

#### 盘上是怎么写的

全程图从 ① 起步，`workflow.md:341-342`：

```text
  人    ① 点 docs/TODO.md 未勾的一行
   │       代理不准自己选行，不准顺手并刀
```

**① 预设那一行已经在盘上。** 而「人每天只做四件事」（`workflow.md:286-291`）是：

```text
1. 看 docs/SESSION.md
2. 看验收红绿
3. 决定勾不勾 docs/TODO.md
4. 拒超售
```

**四件里没有「写 TODO 行」。** 开桌那一次有（`workflow.md:335`「写下 `docs/TODO.md` 第一版」），
之后再往里加行，**母本从头到尾没有一处写谁写、什么时候写**。

#### 缺的不只是「谁写」，还有「代理该不该开口」

第 6 条说的是**裂占位行**在图外。本条是同一个缺口的第二个实例：**从零立一行**。
但本条另有一件第 6 条没说的——

**母本通篇没有一句要求代理提醒顺序。** 它写了一长串「代理不准做什么」
（不准选行、不准并刀、不准发授权、不准自己勾），
**没有一条是「代理应当说什么」**。于是人点了一件没有行的事，代理挑一种读法默默做下去，
**盘上每一条禁令都守住了**——它没选行、没并刀、没发授权。**合规，且错。**

#### 本桌撞成什么样

| 时间 | 发生什么 | 人的原话 |
|---|---|---|
| 2026-09-17 | 代理没有 TODO 行就开始写卡 | 「todo都没写，你在写card？」 |
| 2026-09-20 | 人说「1.4 重写一版即可」。代理读成「重写 TODO 那一行」——**读对了**，但没说破这句话还能读成「写卡」 | 「你做的对，的确应该先写todo再写卡，**不过你应该提醒我说应该先写todo**」 |

**第二次尤其说明问题：代理挑对了，人仍然认为这是失手。**
人要的不是被替着决定，是**被提醒顺序**。这件事母本没有任何一处覆盖。

**本桌的转译也接不住。** `CLAUDE.md` 那张「人怎么说 → 做什么」第一行是
「没点行 → 只回报结论，不改文件。**问人点哪一行**」——
「问人点哪一行」同样预设**行已经在那儿了**，问的是「点哪一条」，
不是「这件事还没有行，要不要先立一条」。
（这是坑三那个失效模式的又一实例：查找表对没覆盖的输入不会说「我没覆盖」。）

#### 建议

1. **全程图 ① 之前补一格**，和第 6 条那一条合并修：
   `⓪ 人（或人下令、代理代抄）往 docs/TODO.md 加一行 —— 从零立行 / 裂占位行，两种来由`。
   现在两种都悬在图外，读的人只能猜。
2. **「人每天只做四件事」改成五件，或明写「立行不在日常四件里，是开桌与扩容时的动作」。**
   现在它读起来像是穷举，而实际漏了一件天天在发生的事。
3. **给代理加一条「应当说」。** 这套东西现在只有禁令，没有一条主动义务。至少加这一条：
   > **人点的事在 `docs/TODO.md` 上找不到对应行时，先说出来，等人立行。
   > 人的话能读成两种以上时，把歧义摆出来，不许自己挑一种往下走。**

   **这一条和第 1 条、第 6 条是同一把尺子**：那两条是代理**做不了**某件事，
   本条是代理**不必说**某句话。三条一起修，才不会又漏第四个格子。

### 10 · 权限名单不是机械边界：规则在名单上 ≠ 规则在生效（2026-09-22）

**类型：外部产品行为 + 母本断言的适用范围。和第 5 条同根同宿主，机制不同，不并条。**

**证据：本桌 2026-09-22 实测，两条机制各自单变量复现。全程见 `docs/SESSION.md` 追记 12。**

#### 盘上是怎么写的

母本讲 harness 配置讲到两层：`claude-code.md:39-40` 说 `tools` 白名单答不了「只许写哪个目录」
（第三节第一句就并排过）；`claude-code.md:64`、`roles.md:44` 说领班不 commit、不勾 TODO——**那是纪律层**。

**`.claude/settings.json` 的 `permissions` 这一层，母本通篇没有一格。**
它不是 `tools` 白名单，是另一套规则引擎，每张桌都要配，而且人一旦配了就默认它生效。
本桌人 2026-09-21 亲手往 `allow` 里加了 24 行，**当场一行没用**。

#### 撞到什么：两条机制

| 机制 | 实测 | 后果 |
|---|---|---|
| **甲：前缀规则的 `*` 盖不住带横线的选项** | `chmod 644 <path>` 不弹、`chmod -v 644 <path>` 弹；`cp A B` 不弹、`cp -f A B` 弹。同一条规则、同一个文件，只多一个 flag。把 flag 显式写进规则也不管用 | 名单里每一条 `Bash(cmd *)` **只覆盖不带 flag 的用法**。像有意设计（否则一条 `Bash(rm *)` 等于顺手授权 `rm -rf /`），但盘上没有任何地方写着 |
| **乙：`allow` 不热重载，`deny` 和 `hooks` 会** | 中途往 `allow` 加 `Bash(unlink *)`（两份名单原本都没有、基线实测会弹、不带 flag，单一变量）——照样弹；同时往 `deny` 加 `Bash(uname *)`——当场生效；`hooks` 整块新增——当场生效 | **靠改 `allow` 治不了当场的问题。** 人加完规则看着盘上有、行为没变，只能得出「配置坏了」这个错结论 |

#### 为什么这是母本的事

1. **第 5 条有了同族第二例。** 第 5 条是 `@` 导入行在本宿主静默不展开，这一条是 `allow` 规则在本宿主
   静默不生效。两条合起来是同一句话，而这句话母本没有一处写着：
   **配置文件在盘上，不等于配置在生效；判据是宿主的实际行为，不是宿主的配置。**
2. **第三节那张表要多一行，而且这一行比其余几行更硬。** 前面几行说的是「机械验不到」，
   这一行说的是**机械验到了绿，而绿是假的**——`uname -s` 在两份名单里都没有规则，却零弹窗跑通，
   说明宿主有内建只读放行通道。于是**「这条命令过了」不能反推「那条规则生效了」**。
   本桌拿这个反推过两次，两次都错、两次都已撤；换成装仪器才查出来。
3. **这一条直接伤到 `verify.md`。** 验收脚本跑在宿主给的权限面上，而这个面**不可自省**：
   代理没有任何机械手段问出「我现在到底被允许做什么」。
   唯一能问的方式是**拿人的点击去试**——每试一次，成本落在人身上。

#### 给母本的建议

1. **第三节提议的那一节（`verify.md`「这套东西验不了什么」）补两行**：
   ①**权限面不可自省**；②**「过了」不等于「规则放的」**——能证明 `allow` 生效的只有写类命令
   （`chmod` / `touch` / `cp`），只读命令过了什么也证明不了。
2. **加一条主动义务，和第 8 条建议 3 同族：代理不许拿人的点击去试自己猜的配置语法。**
   要查配置行为，**先装仪器再推理**：`PreToolUse` 记全量调用、`PermissionRequest` 只在宿主
   要弹窗时触发，两份一比就是现场。第 8 条说的是「守住每条禁令仍然做错」，
   这一条说的是**试错的成本不落在代理身上**，所以代理不会自动省着花。本桌这一次花掉人六次点击。
3. **给 `permissions` 一格**，至少三句：`Bash(cmd *)` 的 `*` 盖不住带横线的选项；
   改 `allow` 要重载窗口才算数、`deny` 和 `hooks` 当场生效；
   **要放行一类动作，钩子比名单可靠**——钩子跑在规则引擎上游、会热重载，
   代价是**钩子的 `allow` 越过 `deny` 名单**，所以那道门必须自己守，并且要能离线验。

**这一条本桌修不动**，和第 5 条一样：根因在宿主一侧。本桌交的是绕开，不是修好——
`.claude/hooks/allow_tmp_python.py`，只放行「`python|python3|py` + `.tmp/` 或 `tests/` 下的 `.py`」
这一种形态，门用 `.tmp/perm_probe/gate_check.py` 离线验过 24 例。

### 11 · git 是判据的锚，可母本只写了「谁按 commit」（2026-09-22）

**类型：设计层缺格。不是矛盾，是空白——和第 9 条同形。**

**证据：母本全文与 git 相关的只有九处，逐条列在下面。**

| 出处 | 写了什么 |

#### 缺的五格，每一格本桌都付过账

1. **基线是哪个 commit，红印之后人再 commit 时判据怎么算。**
   本桌最近一刀：人在红印之后自己提了一个 commit（原话「我刚刚提了一个 commit，你可以开工了」），

   `workflow.md:385` 只写了结案必带 commit，**没写红印和 commit 的先后**，也没写基线怎么定。
   本桌现用的绕法可以直接抄：**判据不锚在工作区或 HEAD 上，锚在内容上**——
   按内容逐个算哈希，红印前后比，人中途提 commit 不影响结论。
2. **不归本刀的改动怎么隔离。**
   本桌工作区此刻常驻四笔和任何一刀都无关的改动：`.gitmodules`、新挂的 `submodules/get-data/`、
   `.claude/settings.json`、`.claude/hooks/`。它们挂了不止一刀，**每一刀都要在卡和 `SESSION.md` 里

   而**发明出来的例外本身没有任何人复核**。
3. **只读外部树没有机械层。**

   仓重、在开发、只调研不开发）。别人天天在提交，那一侧恒不干净，

   「对不上本刀动作，本条不因此红」（`SESSION.md` 追记 9 第 11 条）——**那是补丁，不是规矩。**
   母本的「机械可验」隐含假设了一棵自己说了算的干净树；桌上一旦挂进别人的活仓库，这个假设就不成立。
4. **子模块指针的提交纪律。**
   `naming.md:81` 写的是**内容边界**（留在子模块里的不铺进宿主），**没写指针边界**。

   **提交前重新暂存指针**。这几句每张挂了子模块的桌都要用，现在只活在本桌的口头约定里。
5. **证据的寿命。**
   `directory.md:35`/`:246` 把 `.tmp/` 定成零权威且不进 git，`verify.md` 又要求验收留证——

### 12 · 「TODO 不能变胖」只写了状态判据，没有哪一步产出那个状态；结案那一格再把胖冻死（2026-09-23）

**类型：设计层缺格，外加一条规则反向加固了它。和第 6 条同根**（规矩写了、没有谁、没有闸、不在全程图上），

#### 盘上是怎么写的

| 出处 | 写了什么 |
|---|---|
| `workflow.md:123-133` | 整节「TODO 只能长，不能变胖」。合法两种、**非法一种：一行变胖**。判据一句话：「**一行永远只是『点名 `design` 的某一节』加一个勾选框**」；「细节往 `design` 走，不往 TODO 里塞」 |

| `directory.md:206` | 已办 vs `cmd/`：**互为对账的两边**，已办行是概要、`cmd/` 是细则 |

#### 缺的那一格：有判据，没有动作

**八格里没有一格的产物是「那一行变回一行」。**
① 人点行、② 写卡、③④⑤ 施工、⑥ 收口、⑦⑧ 结案——**② 的箭头恰好是两个**，
`roles.md:45` 又把它写死成「两份都要出」。**`TODO.md` 不在禁写栏里，它是根本没出现。**

**而胖是单调累积的，且累积的时点在写卡之前。** 议事定下的口径、写卡前的复核、

`workflow.md:128` 的「勾完不删，**原措辞不动**」是合法二。

**「原措辞不动」保护错了对象。** `:137` 自己写着 TODO 要留住的是
「**人立案时写的那句话**」——规则是为保护**人的一句话**设计的。
可实际被冻住的是**代理在议事和写卡期间堆上去的分析**：表、论证、逐条口径、人落槌的原话全文。
**规则想保护人的一句话，实际保护的是代理的一堆话。**

而 `directory.md:206` 还要这一区**参与对账**。**对账的一边只会越来越胖，且按规矩不许瘦。**

## 四、转译层的坑

**这一节是人点的**：「把转译可能出现的坑也写到 Dossier 的反馈文档里」。

**先说这一层是什么。** 母本是出处，每张桌的 `CLAUDE.md` 是它的转译。
规矩写在本桌 `CLAUDE.md` 开头：「每一条后面是出处。**出处才是判据，本页是转译。**
两边对不上就改本页，不改出处。」

**这一层该有**——桌和桌的课题不同，不转译就得每张桌读全套母本。
下面六条不是说不该转译，是说**这一层现在一点机械保护都没有**。
前四条本桌都撞过，第五条是推断（标了），**第六条是 2026-09-20 撞的**。

### 坑一 · 规则分居两节，照着出处抄也会漏

**实例是第 6 条那一格。**「一次只做未勾的一行」（`workflow.md:164`，`## 工作单元 = 一刀`）
和「未分解的占位行……不是一刀，闸一不放它过」（`workflow.md:133`，`## TODO 只能长，不能变胖`）
**隔 31 行、分属两节、互不点名**。

本桌禁令抄了前一半，**出处标的正是「工作单元 = 一刀」——那一节里没有后一半**。

**判**：这不是抄错，是**规则的形状让忠实的转译也会漏**。母本那一侧的修法见第 6 条。

### 坑二 · 出处标注给的是可追溯性，不是完整性

本桌禁令每条后面都标出处，形如「→ `workflow.md`「工作单元 = 一刀」」。
**标的是一节，落的是一行。**

一节里若有 n 条、转译抄了 1 条，**盘上看不出漏了 n−1 条**。
`## 工作单元 = 一刀` 有四条，本桌禁令只抄了其中一条——这本身不算错
（别的条在别处转译了），但**没有任何机械手段查得了「这一行是否忠实覆盖了那一节」**。

**判**：出处标注让人**查得动**，不让人**知道该去查**。这两件在这套东西里一直被当成一件。

**建议**：出处标到**小标题或行号级**，不是节级；或者在母本那一侧给每节标一个
「本节共 n 条可转译项」的计数，让桌能自查。**后者机械可验，前者只靠纪律。**

### 坑三 · 把原则转译成查找表，会引入母本里没有的失效模式

本桌 `CLAUDE.md` 有一张「人怎么说 → 做什么」，三行。
**母本没有这张表**——母本写的是原则（全程图 ①–⑧、「四个词各管哪一段」）。

**两者不被覆盖时的行为不一样：**

| | 输入不被覆盖时 |
|---|---|
| 原则 | 不覆盖就是不覆盖，**读的人知道自己在猜** |
| 查找表 | **落到最近的一行**，读的人以为自己查到了 |

本桌 2026-09-17 实发：人说「写todo」，表上没有这一行，
我落进了最近的「点了未勾的一行 → 写卡」——**而且不觉得自己在猜。**

**判**：查找表比原则好用，代价是**它没有「不匹配」这个返回值**。
不是本桌把表写坏了，是这种形状自带的。

**建议**：母本若容许桌写这类表，应当要求**每张表带一条兜底行**——
「**以上都不匹配 → 停，回出处，或问人**」。
本桌会自己补。**这一条对所有桌通用，值得写进母本关于转译的那几句里。**

### 坑四 · 「两边对不上就改本页」只管矛盾，不管缺失

那条规矩预设「对不上」是**看得见的**：转译说 A、出处说 B。

**本桌两次出事都不是这个形状**——转译**没说**，出处**说了**。
**缺失不是矛盾。矛盾会撞出来，缺失是静默的。**

（和本份第 5 条同一个形状：那条是通道静默断掉，这条是规则静默缺失，**盘上都不会红**。）

**建议**：那条规矩补一句——
「**转译没写不等于出处没写。转译盖不住的输入，一律回出处，不许挑最近的一条套用。**」

**这一句要是在，本桌这一次大概率不会出事**——错的正是这一步。

### 坑五 · 转译层没有版本绑定（**推断，本桌未撞**）

母本是 submodule，会更新；桌的 `CLAUDE.md` 是手抄的，**两者之间没有任何绑定**。
母本改了一句，桌上的转译不会红，也没有机制通知任何人。

**本桌没撞过这一条**，所以标成推断。但它和本份第 5 条是同一个形状——
那条是母本对外部产品失准，这条是**转译对母本失准**，距离更近、更容易发生。

**建议方向**（选一个即可）：

- 转译行记下所抄母本的 commit 或版本；母本一动，跑一次 diff 就知道哪几行要复核。
- 或母本自带一本检查，扫各桌 `CLAUDE.md` 的出处标注还指不指得到东西——
  **小标题被改名、节被合并，现在都是静默失效**。

### 坑六 · 寿命只住在 `directory.md`，而「先读顺序」没有一档通向它（2026-09-20）

**实例是第 7 条。**「SESSION 不是历史」这句话的出处是 `directory.md:175`。
而母本给的「先读顺序」（`directory.md:154-158`）是四档：

```text
议事先读     design 那一节 → 当材料读，不当判据
开刀先读     TODO 该行 → SESSION → CLAUDE 禁令
排障先读     SESSION 四件套空位 → 本刀 .tmp/ → 相关 tests
写报告先读   SESSION 交什么 → tests/验收日志 → 卡里预先声明的判据
```

**「维护在办层文件本身」不落在任何一档。** 压缩 SESSION、整理 TODO、清 `cmd/` 都是这一类动作。
于是没有任何一行叫读的人去翻 `directory.md` 那一层「各文件寿命」——
**而那一层恰恰是唯一写着答案的地方。** 四档全都是「拿 SESSION 去干别的事」，
没有一档是「动 SESSION 自己」。

**转译侧更薄。** `claude-code.md:21` 给 `write-cmd` 的一行摘要是
「写 PROMPT + 覆盖 SESSION；写完停」，桌照着转译出来的表也就只剩**动作**：

| `docs/SESSION.md` 横线以上 | **覆盖** | 当前这一刀的运行态 |

**「覆盖」是动作，不是寿命声明。** 读的人拿到的是「写的时候要覆盖」，
拿不到「这份东西不承载历史、丢了是正常的」。人的原话「skill里应该有介绍」，指的就是这一格。

**判**：形状和坑四一样（缺失是静默的），但这一条的根在母本——
**寿命写在 `directory.md`，读的人却被「先读顺序」送去了别处。**

**建议**：

- 「先读顺序」补第五档：`维护在办层文件先读  directory.md 那张寿命表 → 本文件自己那一格`。
- 另一条路是把寿命一句就近复述进 `workflow.md` 和 skill 摘要，
  **但那和坑二直接冲突**（就近复述会造出第二份真相，而且一样没有机械手段查它有没有走样）。
  **所以前一条更稳：不复制内容，只补一条通往出处的路。**

**六条合起来说一件事**：转译层是这套东西里**唯一一层既承重、又完全没有机械保护的**。
`src/` 有测试，卡有闸一，合同有标记，报告有对账，**转译只有纪律**。
而它恰恰是每个新会话读到的**第一份**东西——
**第一份读到的东西保护最薄，这个次序值得母本自己看一眼。**

**三个机制（长上下文对精确执行的劣化）**：①**注意力稀释＋位置偏差**——注意力归一化，token 越多单个关键信息有效注意力越薄，中位信息利用率 U 形塌陷（lost-in-the-middle 族实验）；**信息在上下文里 ≠ 会被用**。②**指令密度递降**——约束越多每条遵守率越低，旧约束被后续对话冲淡。③**干扰面**——历史越长，「看起来像之前那样」的错误延续分支越多。三者伤的恰是**确定性执行**（逐条遵守、精确检索、精确 diff），不伤理解型任务——所以执行手要短上下文，领班（要全局）反而必须长，**两种活两种上下文**。

**第四机制（与长度无关）：同源偏见伤审查**——写方案的上下文倾向认为自己执行的版本是对的；自审形同虚设，新鲜上下文才是无偏验伪者。加第五：**并行物理上需要独立状态**。

**本桌活证**：根锁「不准改 submodules/」禁令在领班开工首小时的通读里就在眼前，长会话末尾的重译照样丢掉，被一只短上下文审查手抓回；同型还有 CRLF 同坑三踩、量级窗错框架、判据自引。**知其在库，不用其智**——模型知识库里都有这些原理，但范式条文不写，代理在决策时刻就不会想起去用。

**给母本的**：两席／工牌／代理席条文处宜各补一段**原理注**（上述五条一句一条），把「领班不干活、三手独立」从纪律升成有据设计；范式条文的通则建议：**「为什么」与「是什么」同页**——只写规矩不写原理，规矩会在第一次含糊处被读歪（本桌 2026-10-05 的「少写核被读成可以写」即实例）。
