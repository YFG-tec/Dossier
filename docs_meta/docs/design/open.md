# 还想对齐的问题

母本合同层的第二份文件，**是 `paradigm.md` 那些占位的展开，不是第二答案**。
背景、选项、外部对照写在这里；**冲突时以 `paradigm.md` 为准**（分工见该页 §5）。
一条定案了：先改 `paradigm.md` 的态，再把这里对应那条移进「已收」。

换根不带走。下文只写文件名时指 `docs_meta/src/` 里那一份；已拍板的目录取舍见 `directory.md`，来源见 `sources.md`。

1. **新开数值验证默认轻档还是重档？** 默认先长 `directory.md` 六块，核开始变脏再加角色文件？（`paradigm.md` §8）
2. **探索 → 入库门槛**要不要写成 `docs/design/` 草案的固定小节？
3. **harness 按什么顺序落？** 规划在 `claude-code.md` / `cursor.md`，文件还没写。先落轻档（`CLAUDE.md` + `AGENTS.md`），还是规范定稿一次铺到重档？（`paradigm.md` §4）
4. **长跑 + 稀疏监督，还是短刀 + 密集闸门？** Anthropic 官方那篇写的是同一批用例（重写数值求解器、Fortran 迁移），做法相反：plan 编进 `CLAUDE.md`，tmux 里 detach 跑几小时，偶尔上 GitHub 看。
   目前的答案是分档——**判据外生（有参考实现）就长跑，判据内生就短刀**；再加一条「数值失败是静默的，看一眼看不见」。
   两条都可能被模型能力涨掉。要不要把这条分档判据写进 `roles.md` 档位表，作为轻/重之外的第三个维度？对比全文见 `sources.md`。
   连带：**一刀内部的长跑工程**（tmux、计算节点、detach、几小时后回收）这套 Dossier 一个字没写，该不该补，补进哪一层？（`paradigm.md` §7、§8）
5. **隔离只做到工具层和路径层。** 审查禁写靠 `disallowedTools`，路径分工靠约定——同一个进程、同一份凭证。
   gh-aw 的做法是让写凭证和 agent 运行时分属两个 job。本地交互式开发用不起那套，但要不要至少写明这是已知边界，以及审查那只手值不值得单开一个会话？（`paradigm.md` §8）
6. **这套东西怎么才算错？** 母本没有 `tests/`，每一刀的验收只有「人读一遍」——正是 `verify.md` 禁止的那种验收。
   想得到的三条：文档间自相矛盾能不能机检（交叉引用、术语首现、图 alt 对正文）；
   拿 Xenia 历史补丁当**种缺陷测**回放，问「按这套走会不会在一刀之内暴露」；
   在一张真桌上跑通再发。回放是事后叙述，**怎么做才不是自证**？（`paradigm.md` §6，本页最重的一条）
7. **首页给谁看、说多硬？** 现在第一屏没有「这是什么」也没有「给谁用」，
   词汇税又高（刀 / 席 / 收口 / 超售在术语表之前就用了）。
   写死定位会劝退大半读者，不写又说不清适用边界。（`paradigm.md` §2、§7）
8. **整版英文另开分支。** 不在中文稿上对着译。欧美会把 Dossier 读成情报档案——读法成立，
   但首页英文必须钉住对象是工作结论不是人（`naming.md`）。什么时候开、readme 先英还是全文一起，未定。
