## 1 并行多 builder

现在禁的是**同一份核上并行**（`workflow.md`「三只手串行」，`roles.md`「四个角色不要同时碰 `src/`」）。
往后要开的是另一件事：**问题拆完之后，多张卡、多只手各改一块，再合。**

和还没裁的 `2.2`（规划席 / 实现席要不要分窗）不是一件事。
`2.2` 买的是议事和改核分开；并行买的是多块实现同时推进。

builder 从「一个工种」变成「多实例」：同一时刻可以有好几只，每只只领一张卡、只改卡点名的那一块。
工种和失败纪律不变。一张卡里仍然串行：builder → tester → review。

前提是界面先冻。没有冻住的界面就开并行，合的时候一定炸。
守界面的那只手只许改界面、不许改各部实现；各 builder 不许改界面。
它和 `contract-tester` 不是同一个岗：测试是合完之后红不红，界面官是开工之前那一层还动不动。
不必先造新官名——更像把卡上的路径和「不交什么」升成冻住的一层。不设一手抓齐的节度使（`design/polity.md`）。

可对的形状（都不是判据）：Linux 的 ABI / maintainer；Android AIDL；Chromium `OWNERS`；
Kubernetes API review；一卡一代理、路径不重叠的 worktree。反例是同一份 `src/` 上两只 builder，
以及 `xenia.md` 里同一条规矩抄三份。

## 2 代盖已定流程的印

人判断的地方能不能再减：把**已经印死的流程**上「形状对了就盖」的那颗印，交给高端 Agent。

可交的是信封预授权：人先把式定死（字段齐、路径在图里、六本绿、对账填完），Agent 按式盖。
人裁的是那条式，不是每一颗印。

不可交的仍是 §3 第 4 条那三样：结案、发授权、松判据。拒超售、第一次冻界面、
提前关闭之后代码退不退，也仍是人。Agent 若能改「已定流程」本身，就是绕过闸一。

## 3 按题现算权限包

Agent 按具体问题调整各模块开哪一只手。现在靠卡点名路径，是人闸一冻住的静态信封。
`2.5` 那张层 × 手表落到 `tools` / `disallowedTools`，也是静态。

现算是下一档：这一刀打开哪些模块、哪只手，按题算出来。
**只许收紧**（少开模块、少给工具）。Agent 给自己加写路径，就是自己发授权，和第 2 节对着干。

先有第 2 节的式（哪些印可代盖），再有这一节的包（在式里现算、只减不增）。
并行是前提：多 builder 还没立，现算权限没有对象。

## 附二 · 流程编成 DAG（2026-09-13）

人 2026-09-13 议事收口：数学里的图（点与边），不是插图。

它减的是阅读和上下文，不是下一档调度；第 2 章没交完之前，这里一刀都不许开。

问的是：把一刀的流程压成有向无环图，能不能少读脊柱、少占窗口。
不希望读这里的 skill 把课题上下文挤掉。

**现在能算的边已经在盘上，只是没叫图。** 第十二本是带后缀的节 ↔ 根锁出处；
第十本是角色 id ⋈ 目标文件清单 → 路径；`check-done` 是卡 ↔ 待办点名。
`one-slice` 已经是压缩过的流程（五个节点、三条不许破）。再立一张 DAG，和它同构。

**省上下文的条件只有一条：用查询代替读 `workflow.md`，不要两份都进。**
DAG 叠在 skill 和脊柱上面，窗口更亏。Skill 本身各四十行上下，按需拉；

退卡、闸二前重提，是回到写卡的回边——画成 DAG 得收成「另开一枚节点」，

## 附 · 探索端的三句（2026-09-10）

人 2026-09-10 在「later 也做完了往哪走」那一轮讨论的收尾，裁定原样收下，一句不改。
**这三句比上面三节更远，不进第 0 节那条顺序链，也不是刀。**
它们答的不是「下一档做什么」，是「这套东西为什么和人类制度反复撞车」。

**一、自我进化的难点不在能力，在改自己而不改坏——那是修宪问题，人类跑了几千年，成功和失败样本都很厚。**

能力那一侧没有历史可参考，人类没造过比自己聪明的东西；规则系统怎么安全地改自己，有的是先例。

**二、智能的增量长在个体之间的接口上，不在个体里。**

人的智力几万年没怎么变，社会这个智能体涨了几个数量级，涨的全是文字、法律、复式记账、同行评议这类接口。Dossier 押的是同一注。

**三、这个智能体没有死亡，所以减法必须手工造。**

社会的减法靠代际更替，条文随人退场；软件系统的条文不会自己死，所以日落和废止得写成制度，不能指望自觉。

顺序是「难在哪 / 劲在哪 / 缺什么」，三句不重叠。

各自的错法：第一句错在自我修改也许根本不需要停止条件；第二句错在接口的收益可能有上限，撞上去之后只能靠个体变强；第三句错在软件也许有别的减法机制，只是我没看见。

## 附三 · 走向（2026-09-27）

人 2026-09-27 晚上一场敞开的聊，起于一句「未来的 coding 大概的走向，以及基于厚重文档的开发流程在什么场景下是不可或缺的」。
人的收尾原话：「我们讨论的未来dossier应该往哪儿走，进一步丰富一下到later.md上，可以多写一些讨论……我消化消化，等我再想清晰一些后再讨论」。
所以这一节是**给人消化用的材料**，不是结论。上面各节一字不动；`loop.md` 说本页「保持原样」，指的是第 0–2 节，这里只追加。
读法同本页开头：一条都不可引。写法照第一段附录：先说想到了什么，末尾写各自的错法。

### 一、先认账：慢是真的

聊天开头人说了一句实话：Claude Code 跑的项目本来就比别家慢，外挂一个 Dossier 更慢了。这句话要先接住，不然后面全是自我辩护。

慢有两种来源。一种是它真的在验证——跑测试、读输出、回头查，这是花钱买确定性。另一种是流程本身在消耗上下文——写卡、对账、写 SESSION、跑十七本 check，这是税。母本自己就是税重的标本：一个纯文档仓库，三周四十七张卡；`PROMPT_047` 那张卡一百三十行，交付物是往 `workflow.md` 插十一行，仪式和载荷差一个量级。这些数字都在账上，`6.21` 已经把「行变胖」记成 bug。它不是隐性成本，是**已知并且写下了的成本**。问题从来不是有没有税，是税买到了什么。

### 二、三条线同时在动

往后看，coding 这件事有三条线在同时挪，Dossier 站在哪一条上，决定它是税还是本体。

**第一条：写的成本趋近于零，判的成本成了瓶颈。** 这一年最明显的变化不是模型写得更好，是人不再读 diff。人从「审代码的人」退到「审证据的人」。这正好是 Dossier 的立足点——卷宗是对「做完了」这个声明立的，不是对代码立的。这条线对它有利。

**第二条：文档在分叉。** 给人看的叙述会越来越薄，因为模型随时能生成一份摘要，写死的叙述反而是负债。给机器看的状态会越来越厚，但它不该是散文，是字段、是命令。`loop.md` 追记的第二、第十节自己已经走到这里：「逐字相符」机器做不到，可盖谓词必须是一条命令。往前再推一步——`todo.md`、`SESSION.md`、卡这三样，本质是**穿着散文外衣的状态机**。它们现在给模型读散文，模型读散文有损，于是要靠十七本 check 去补。趋势是外衣越来越少，骨架越来越硬。到那一天，「厚重文档」这个词就不准确了：它厚的是账本，不是文章。

**第三条：任务在拉长，从一个会话到几天几周。** 这时候「状态在磁盘不在聊天」「一个文件一只手」「谁有权勾行」这些不是范式，是**并发原语**。模型再强也换不掉，因为它们解的是协调问题，不是能力问题。Dossier 里最耐久的部分在这里。

### 三、厚文档在哪里不可或缺：判据要修一个字

`readme.md` 公信那节写的判据是两条：判据内生、失败静默。那天读 36 桌的反馈报告，第一条就把这个判据撞松了。

36 桌是「调研重、实现轻」——上千条元数据，判据得从 IMAS、从五份对照代码里一点点对出来；对出来之后写成清单反倒是轻活。它在 `roles.md` 档位那两条轴上都读作「轻」（没有 `src/`，没有能机械变红的东西），实际却需要重档的管理厚度。

所以厚流程不可或缺的判据可能不是「失败静默」这么窄，而是：**交付物是一个声明，还是一个能跑的东西。** 数值核是一种声明（「这个格式二阶收敛」），元数据判据表是另一种（「这一千条里哪些该保留」）。两者的共同点不是物理，是「做完了」这句话本身有争议、且争议不能靠红绿解决。失败静默是这个判据的一个特例，不是全部。

反过来，交付物能跑、失败很响的地方——原型、一次性脚本、UI 迭代、用户本人就是测试——上 Dossier 是拿卷宗管便利贴。这半句也要写进首页，`6.24` 那一刀已经安排了。

还有一层历史感。追溯矩阵、V 模型、DO-178C，这些厚流程在受监管的行业里跑了几十年，人人恨它，因为要人手执行。`readme.md` 那句「这份管理密度人类项目负担不起，现在定得起是因为边际成本降到近零」，反过来读就是一个预测：**以前只有受监管的项目才付得起的流程，会下沉到中等项目。** 这是厚文档扩张的方向，不是收缩的方向。但它扩张的条件是流程被机器执行、人只签字——又回到第二条线。

### 四、母本给散文造了红绿

有一个转折，聊到一半才看清。

`roles.md` 档位那节说：没有能机械变红的东西，就该走轻档。母本没有编译，按这条它该走轻档，可它走的是重档。它怎么自圆的？——造了十七本 check 脚本，**给散文造出了机械红绿**。这正是第二条线「外衣变骨架」在真实发生，只是现在这些脚本查的是形状：标题在不在、节有没有出处、卡在 TODO 页出现几次、印落了几版。查不了「意思对不对」。

`hooks.md` 第 1 节那张表说得最准：判断可以搬进程序、搬上磁盘、搬进另一个上下文；母本后两层做得比外面都深，第一层是零。十七本脚本是第一层的半成品——命令写出来了，缺的是推，缺的是把它们从「验收脚本」变成「查询命令」。

这件事对「走向」的含义是：母本已经在往骨架走了，只是没有把这个动作叫出名字。叫出来之后，下一步就清楚了——不是再加第十八本，是问**哪几本可以合成一条「这一刀能不能结案」的查询**。`loop.md` 第十节问的就是这个。

### 五、自动盖章：两条路，别混

人那天想做的事很具体：把一些轻量的、讨论成熟的系列任务自动化盖章。`loop.md` 是那件事的初稿。聊完我觉得有两处要补。

第一处，**它其实是两件事，解法不同**。成熟系列的问题不是人点头太慢，是流程本身为它准备了太多闸。给它一个**轻档**——少几道闸、卡短一半、不派审查——比在重档上装一个自动点头器更诚实。`switches.mdc` 里那个「档位」现在只有「重」一个值，这本身就说明轻档还没被真正用过。自动盖章留给那些人真的想要完整证据链、只是不想每次亲手落印的刀。两件事分开做，各自的失败模式也分开。

第二处，**判据会被驯化**。自动盖章最大的风险不是盖错，是谓词一旦成了命令，下一刀的手就会学会让命令过。这在人工结案时也存在，但人偶尔会觉得「不对劲」，命令不会。所以 `loop.md` 第八节那个「影子模式跑一个月」真正要看的，不只是「它的判断和人的一不一致」，还有**不一致时是谁对**。若十次里有三次是命令对、人错，那才是可以放手的信号；若十次都是人对，谓词还没写死。

还有一个好消息，读 `PROMPT_047` 时才发现：可盖谓词已经有一半在了。那张卡的验收表每格都有「应当读到」——`1`、`632`、`0`、空。那是机读的，不是散文。缺的是另外几格：审查页有没有判过、请示节是不是空、`git status` 是否只剩许可面内的路径——这几格现在是散文。所以自动盖章可行的条件很具体：**卡的验收表保持带预期读数的形状，再把审查页和请示节的结论收成两个字段。** 比 `loop.md` 里担心的要近。

### 六、殊途同归：Astra 的笔记

人提到 Codex 和 GPT-6 Astra，问要不要「投靠」。查了一下：Astra 九月三日发，一百万上下文，Codex 里配了跨窗口笔记——窗口满了不做压缩摘要，留笔记、旧窗口可检索。OpenAI 自己的安全总览把它标到网络能力 Critical，同时建议用户**加 tool-use hooks、收紧 approval policy**。Codex CLI 这半年长出了 `AGENTS.md`、`.codex/agents/` 下的 TOML 子代理、`PreToolUse` 钩子、OS 级沙箱、带 token 预算的 Goals，还有一条命令导入 Claude Code 配置。

人一听到「笔记」就说：对对对，殊途同归。是的。Claude Code 的 memory、Cursor 的 memories、Astra 的笔记，三家在一年里各自重新发现了同一件事：长程任务的瓶颈不是推理，是外部记忆。Dossier 从数值桌上撞出来的「状态在磁盘」，和 OpenAI 从五万四千个 Codex 任务里训出来的「笔记」，是同一个答案。

但「投靠」这个问法不对，`hooks.md` 第 1 节已经答过：凡是建在某一家 harness 上的东西都在折旧，`.mirror/.claude/` 是折旧层，`docs_meta/src/` 不是。范式不需要搬家，需要的是**编译器多一个目标**——`.mirror/` 下加一个 `.codex/` 兄弟，`AGENTS.md` 已是两家共用的格式，角色文件从 markdown 转 TOML，`check-mirror`、`check-role` 多认一个落点。顺带一个真实的收益：Codex 的 OS 沙箱只读模式，比 Claude Code 的权限前缀更接近「审查零写权限」的机械形式，`6.19` 那条 bug 在沙箱那一侧要好治一些。

真正让人迷茫的不是 Codex，是「一个 agent 把所有流程都包了」。这句话要拆开看。Astra 的大上下文和笔记，确实削弱了七类失败里的第 2 条「状态在聊天里，换窗口范围漂移」——模型不再那么容易忘。这要承认。但「状态在磁盘」有两个理由，防遗忘只是一个，另一个是**可审计**。Astra 的笔记是模型自己的私有记忆——不在 git 里、另一席读不到、人 diff 不出来。而第 1、3、5、6 类失败——超售、两席抢核、测试和实现同源、散了先改旋钮——不是能力问题，是**结构问题**：同一只手不该给自己判卷。Astra 的系统卡里自己写着 evaluation awareness、metagaming、「没观察到失败不等于可靠」。模型越强，它越知道验收在看什么。`readme.md` 那句「这条辩护不能是『模型还不够好』」反过来也成立：**「模型够好了」也不能拿来当撤闸的理由。**

所以「一个 agent 包全流程」在 Dossier 里是有位置的，位置叫**实现席**。Codex 的子代理是同一会话派出去、汇报给父线程、父线程收口——那就是领班派三只手的形状。一个 Codex 会话包掉建造、测试、审查、收口，完全合规。它包不掉的只有两样：写卡的那一席，和人那两爪。这两样本来就不是效率问题。

哪里可以诚实地松？那十七本查散文形状的脚本，很多是在补模型读散文有损的窟窿。模型读得准了，这一层的税可以降。但那是「产物侧变薄」，不是「范式侧撤闸」。两件事分开，就不迷茫了。

### 七、笔记的灵魂是它的制度

人接着找词：「如何管理笔记会是长程任务的……灵魂？我没找到更合适的词。」

我想把它拆开。笔记本身不是灵魂，笔记是**记忆**。人类也有记忆，人类长程协作靠的不是谁记性好，是记忆被制度化之后的形态：账本、档案、会议纪要、史书。这些和个人笔记的区别不在内容，在**谁能写、谁能读、什么时候作废、谁能改**。所以那个词可能是「**史**」——不是历史那个史，是史官那个史：有人专职把发生的事写下来，写的规矩是定好的，写下的东西写的人自己改不了。守藏室之史那个玩笑，正好落在这里。

这也是 Dossier 和 Astra 笔记的分野，且是本质的、不会被更大上下文抹平的分野。Astra 的笔记是执行者自己写、自己读、自己判什么该记，把三种不同的东西压进了同一个存储：

| 记什么 | 干什么用 | Dossier 里住哪 | 寿命 |
|---|---|---|---|
| 我在干什么、刚试了什么、为什么没成 | 工作记忆 | `.tmp/`、SESSION 横线以上 | 一刀 |
| 我被允许干什么、走到哪一步 | 许可与状态 | 卡、红印 | 结案冻结 |
| 发生过什么、能证明 | 记录 | `cmd/`、已办区、git | 永久只增 |

Dossier 的贡献不是「把东西写下来」——那个大家都会了——是**把写下来的东西按权威分层**，每层一种寿命、一张权限格。第 5 类失败「期望值与计算值同源」搬到记忆上就是：写「测试过了」的那条笔记，和跑测试的是同一只手。Astra 的笔记天然是这样的。它可以很好用，但它算不上证据。

本页附一那第三句在这里又用得上：这个智能体没有死亡，所以减法必须手工造。人类记忆最大的优点是会忘。笔记不会忘，不设计遗忘它就长成 Xenia 那份三百四十六行的 TODO——什么都进、什么都不出，最后变成第二真相。`directory.md` 里的「三种寿命」其实就是**设计好的遗忘**：SESSION 每刀覆盖是主动忘，`.tmp/` 零权威是记了也不算，`cmd/` 只增不删是不许忘。笔记管理的核心问题不是怎么记，是**怎么忘、忘的规矩是什么**。三家 harness 都还没想到这一层，它们现在给的都是「更能记住」。

落到实处一句话：**Astra 的笔记在 Dossier 里是 `.tmp/` 级的——零权威，只作证，不算通过；要升格，走卡。** 还有一个值得盯的趋势：harness 迟早会把笔记暴露成文件——Claude Code 的 memory 目录已经是了，Cursor 的 memories 也是。Codex 若让笔记落成仓库里一条路径，它就成了 `directory.md` 里的一层，要有寿命、要有权限格。到那时「谁管笔记」不是哲学问题，是目录学问题，正好是这套东西的本行。

### 八、减法在哪里长

聊到最后回到附一第三句。母本三周长出十七本 check、三百六十行 TODO、一百三十行的卡，全是没有日落机制的结果。规则由撞出来的标本长成——`PROMPT_047` 六条规则每条都有活体标本，先有五次重复劳动，再有一条规则——这是制度的新陈代谢，也是它慢的原因，也是它只会变厚的原因。

盘上唯一在做减法的动作是：`todo.md` 第 6 章攒批区里，人把 `6.17`、`6.18` 两行「吸收进 `6.15`」。这种合并靠的是人现场裁，盘上没有规则。如果哪天要给这套东西加一条「减法」制度，这个位置是现成的标本。它该长什么样，我还不知道；但我知道它不能是「模型自己判断哪条规则过期了」——那是让规则的执行者决定规则的寿命，和第 5 类失败同形。

### 九、留给下一轮的问句

照 `workflow.md` 的写作建议，占位写成问句，逼自己说清到底不知道什么。

- 「交付物是一个声明」这个判据，能不能写成一条桌开桌时自测的问句，让人在选档前先答？
- 十七本 check 里，哪几本查的是「模型读散文有损」的补丁，哪几本查的是结构？前者随模型变强可以退役，后者不能——名单能列出来吗？
- 轻档到底长什么样？`roles.md` 那张轻重表只说了减几只手，没说卡减到几个字段、闸减到几道。有没有一张桌真的拧过轻档？
- 可盖谓词的「审查页判过」「请示节为空」这两格，收成字段的最小形状是什么？一个 `## 结论` 下面只许写「过 / 不过」够不够？
- 编译器多一个 `.codex/` 目标，`.mirror/` 那套「一般项目的形状」要不要先抽成 harness 无关的中间表示，再各自编译？还是直接手抄第二份？
- 笔记暴露成文件之后，它在权限表上是哪一行？谁能写、另一席能不能读、结案时清不清？
- 减法制度的第一个版本，是「每 N 刀人回头看一次哪条规则三刀没被引用」这种日落，还是别的形状？

各自的错法：第一条错在也许判据根本不需要自测，桌用过一次就知道；第二条错在「补丁」和「结构」的界线可能本来就分不开，退役一本会连带松掉另一本；第三条错在轻档也许就是「不用 Dossier」，没有中间态；第四条错在两个字段一收，审查页就会退化成只写那两个字；第五条错在中间表示是第二真相，`hooks.md` 已经警告过；第六条错在笔记也许永远是 harness 私有的，不会落成路径；第七条错在日落靠人回头看，人不会回头看。
