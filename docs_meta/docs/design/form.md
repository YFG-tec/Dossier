# 产品形态：子模块 + init

**权威：框架参考，不作红绿的判据。** 卡片不许引本页，把关不许扫本页。

本页只说一件事：这套东西怎么到宿主手里。拿到之后怎么用，不在本页——
那是 `src/` 那几份通则的事，本页一条都不复述，要看就去那边看。

## 1 一句话形态

母本是一个 git 仓库。宿主用 `git submodule add` 把它挂进来，再跑一次 `init`，骨架就铺出来了。

两个动作，两个词，都是别人现成的词。母本一个都没自造。

母本只给默认，不给强制：子模块默认挂在宿主主目录下，`init` 默认往子模块外面一层铺。
挂哪、铺到哪、什么时候拉新版，人要改就改得动。

## 2 边界是物理的

子模块目录里面的归母本，外面的归桌。

挂进去之后，`docs_meta/`、`readme.md` 就实实在在躺在宿主仓库里了，
只是躺在子模块那个目录底下。

所以旧那句「换根不带走 `docs_meta/`」在新形态下是反的——它进来了。
为真的说法是**不铺进宿主工作区**：它在子模块里，不在宿主自己那棵目录树上。

这条边界靠的是目录，不是约定。谁在哪一边，`ls` 一下就看得出来。

## 3 `init` 铺什么，铺到哪

铺的是一棵目录树，加一批占位文件。

目录树按 `directory.md`「`docs/` 内部怎么切」那一棵。本页不抄那棵树，要看去那边。

文件只铺 `todo.md`、`SESSION.md` 这一类占位，里面是空壳，不是样例。
空壳被误当合同的风险小；样例会被下一只手直接拿去用。

**铺到哪是参数，不是母本写死的位置。** 默认往子模块目录的外面一层铺，也就是宿主根；
人指了别处就照人的。

这个默认值是相对的：脚本住在子模块里，往上一层铺，所以它不必知道宿主叫什么、在哪。

人 2026-09-14 说这件事「比较自由」。所以这里写的是默认加余地，不是规定。

本节只说形状，不说怎么实现。命令行长什么样、要不要抄现成的铺开工具，
是 `todo.md` `2.8c` 那一行的事，本页不替它作答。

## 4 升级怎么走

两步：

1. 人跑 `git submodule update --remote`，把母本拉到新版。
2. 再跑一次 `init`，补上新版多出来的东西。

第一步动的是宿主的 git 索引，**母本不代跑**。
理由和根 `CLAUDE.md` 那条「不 commit、不 push」同一条：动别人仓库的历史，得是人自己那一爪。

因为 `init` 同时是升级路径，**重跑一次必须幂等**：已存在的一律不动，只补缺的。
`todo.md` 和 `SESSION.md` 里装的是宿主攒下来的真活，覆盖就是活没了。

新建、已有仓库、升级，三档走的是同一个 `init`，不另开第二个动词。

## 5 代理在宿主那边不许改子模块

子模块里的东西归母本，宿主那边的手只读。

这是一条约定，**做不成看得见的门**。人 2026-09-14 裁过：「限制不了，不强求」。
工具面拦不住，宿主那边的手真要写，它写得进去。

所以这里写的是意图。真被改了，下一次 `git submodule update` 会撞出来——
那是事后发现，不是事前拦住。

## 6 名字从哪来

`git submodule add` 是 git 自己的命令。
`init` 是各家脚手架通用的那个词，Spec Kit 的 `specify init` 也拿它管新建和已有仓库两档。
两个都是现成的，母本不拥有自造的动作名。

「换根」和「嫁接」都作废了。
前者是旧形态的动作名，形态没了，词跟着走；
后者是我们自己发明来描述别人 `init` 的，查过业内，没人这么叫。

一个动作如果没人用过同样的名字，多半不是我们发现了新东西，是我们没去查。
