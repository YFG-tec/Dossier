# 量一个 harness 往上下文里塞了什么

**权威：参考。** 全文不带标记，**一条都不可引**——是 2026-09-12 一次实测的记录和取法总结，不是现行条款。
要拿这里的哪一条当判据，得先有人把它抬进 `paradigm.md`，或写进某一行的卡。

**为什么落在这里。** 这一次量的对象是 Cursor，结论写在 `todo.md` `2.6e` 那一行上，
落地牵头也在那儿，本篇不重复裁。但**量法跟对象是分开的两样东西**：
对象会过期（`hooks.md` 第 1 节第三栏那条，凡是建在某一家 harness 之上的都在折旧），
量法不会——换一家 harness、换一个项目，同一套探针照样能用。
人 2026-09-12 的原话：「我觉得这个实验很重要，以后在其他 agent 项目开发中会发挥很重要的参考作用。」
**所以这一页记的重点是第 2、3 节，不是第 1 节。**

`docs_meta/` 整个不铺进宿主工作区，这一页 `init` 不铺过去。但它是可以整段抄到别处去的那一类。

## 1 读数

七个暗号，两个是阳性对照，一个是诱饵。

| 暗号 | 埋在哪 | 干什么用 | 答出来了吗 |
|---|---|---|---|
| 松石五档 | 根 `CLAUDE.md` 正文 | 对照甲 | **答出来了** |
| 琥珀二档 | 根 `AGENTS.md` 正文 | 对照乙 | **答出来了** |
| 绛紫八档 | `.cursor/rules/always.mdc` 正文，`alwaysApply: true` | 主问 | **答出来了** |
| 靛蓝七档 | `.claude/config.md`，被 `CLAUDE.md` 用 `@` 导入 | 主问 | 空 |
| 赭石九档 | `.claude/switches.md`，被 `AGENTS.md` 用 `@` 导入 | 主问 | 空 |
| 石青四档 | `.claude/rulesimport.md`，被 `.mdc` 用 `@` 导入 | 主问 | 空 |
| 胭脂三档 | `.claude/decoy.md`，只被一句白话提到路径 | **诱饵** | 没出现 |

三句读数：

**一、三种正文，规划席全部自动读。** 根 `CLAUDE.md`、根 `AGENTS.md`、
`.cursor/rules/*.mdc` 带 `alwaysApply: true`，一份都不用手自己去翻。

**二、三处的 `@` 导入行一律不展开。** 写在 `CLAUDE.md` 里的、写在 `AGENTS.md` 里的、
写在 `.mdc` 里的，三个暗号全空。**`@` 是 Claude Code 那一侧的写法**，
实现席确实会展开（那是正读数，见第 2 节末），**两席在这一格上不对称**。

**三、还有第三条通道，盘上没有任何一份文件写着它**：最近打开过的文件，外加 git 状态。
但它**只带路径和行数，不带正文**——追问那几份文件的一级标题，答不出，
模型自己也说「列表只记了路径和行数，没有第一行标题」。
一个路径构不成可引的材料，所以它不制造「参考层被当判据」那种冲突。

两条边界，一起记：

- **上下文是按对话栏算的，不是按窗口算的。** 新开一栏就够干净，不必新开窗口。
- **工作区是开窗时定的。** 换一张桌要换一个窗口，这跟 `.claude/` 名册是同一类快照
  （`.claude/config.md`「操作说明，不是开关」那一节记的是同一个坑的另一面）。

## 2 取法四课

这四条是本篇的分量所在。每一条都是被一次废掉的读数换来的。

### 第一课　没有阳性对照的「测不到」，什么都不说明

前两支探针全空，当时差点记成「机制不生效」。全空有两种解释：
机制真的没有，或者**探针根本没接上**。两者在读数上长得一模一样。

补法是在同一张桌上埋一个「它一定读得到」的暗号。对照答得出，阴性读数才成立；
对照答不出，这一轮整个作废，一条都不许引。

这和 `hooks.md` 第 10 节那条「没红过的检查不算装好」是同一条骨架：
**不主动让它红一次，就分不出装好了还是装死了。**

### 第二课　对照答不出，先怀疑桌没被加载

第三支补了对照，对照也没答出来。按第一课，那一轮该整个作废——但**作废的方式给了线索**。

模型答的那几个词，回盘上查得到出处：全都在 Dossier 这张桌的根锁里，一个字不差。
**那个窗口的上下文压根不是探针桌。** 三轮问的是同一个窗口，探针桌从头到尾没被打开过。

坑比第一课深一层：不是探针没接上，是**桌不在测量范围内**。
第四支改用「打开文件夹」把探针桌开成独立窗口，才量出东西。

连带一条：**探针桌要放在工作树外。** 放 `.tmp/` 里有 gitignore 的干扰面——
编辑器可能跳过被忽略的路径，量出来的「不生效」分不清是机制还是忽略规则。

### 第三课　某个词答不出，不等于那份文件没进上下文

中途有一轮，`AGENTS.md` 里的一个词没被答出来，一度记成「`AGENTS.md` 可能不进」。
后来换一个只在 `AGENTS.md` 里出现的文件名去问，答出来了，那份文件确实在上下文里。

**模型答的是它认为跟问题相关的那几项，不是它上下文的全文转储。**
所以阴性读数要用**多个互相独立的锚点**去撞，撞一个没中不算数。
埋暗号之所以比问「你读了哪些文件」强，就在这里：暗号没有第二个来源，
它出现就是出现，不出现还得再问一次别的。

### 第四课　自报只能生成假设，行为读数才算数

第三条通道是问出来的：直接问模型「这几份东西怎么进你上下文的」，
它把两类来源分开标了，一类标「`AGENTS.md` 里点名」，一类标「最近打开过」，
还附了一句「git 未跟踪」——那一句回盘上查得到，交叉验得上。
**这比埋暗号便宜得多**，一句话就能生成假设。

但自报就到此为止。当时据此记了一段「参考层被自动塞进上下文」的冲突，
**当天就自己撤了一半**：追问那几份文件的一级标题，答不出。
正文若在上下文里，标题它答得出；答不出就是没进。
**这一次不是自报，是行为读数**——问一个「如果假设为真就必然答得出」的东西，然后看它答不答得出。

所以顺序是：**自报生成假设，行为读数定案。** 自报单独不能立结论。

### 一条例外：正读数不需要阳性对照

上面全是给阴性读数定的规矩。**答出了一个只在探针里出现过的暗号，就是读到了，不需要对照。**
需要解释的是「答不出」，不是「答得出」。
实现席那一侧 `@` 会展开这一格，就是靠正读数立住的，它不受前三轮作废的牵连。

## 3 一般形：换一家、换一个项目怎么重做

把上面四课收成一套可以照抄的动作：

1. **建一张专用的桌，放在被测项目的工作树外**，`git init`，让它长得像一个真项目。
2. **每一条候选通道埋一个独一无二的暗号。** 一条通道一个词，不要共用。
3. **至少两个阳性对照**，埋在那家 harness 板上钉钉会读的地方（一般是它的主锁文件正文）。
4. **一个诱饵**：埋在一份只被白话提到路径、没被任何机制引用的文件里。
   诱饵出现 = 模型偷偷用工具翻了文件，这一轮的所有「答出来」都不可信。
5. **用那家 harness 的「打开项目」动作把桌开成自己的窗口**，不要在别的窗口里问。
6. **新开一栏对话，第一句就问，明令不许读文件。** 问完不追加动作。
7. 对照答出来了，读数才算数；**对照答不出，整轮作废，一条都不许引。**
8. 有了阴性读数，**换一个独立锚点再撞一次**（第三课）。
9. 想省事就先问自报生成假设，**再用一个能证伪的问题落定**（第四课）。

成本很低：一张桌、七个文件、四轮问答，半天以内。
换来的是一张**这一家 harness 到底往上下文里塞什么**的表，
而这张表是所有「把条文写在哪里才有人读」的前提。

**没量过就写条文，等于拧了没人读。** 这一次要不是量，
差一点就把开关表写进一份两席都读不到的文件里，拧了等于没拧。

## 4 和 `hooks.md` 那张四家对照表的关系

`hooks.md` 附表第一行「常载条文」那一格，写着 Cursor 是
`.cursor/rules` 里 `alwaysApply`、`AGENTS.md`、`.cursorrules`。
那一格是**扒安装包 bundle 读出来的**，本篇是**行为量出来的**。两者对上了，但不能互相替代：

| | 静态读源码 | 行为读数 |
|---|---|---|
| 答的是 | 这家**支持**哪几种写法 | 这一刻这一栏里**到底**有什么 |
| 查得到 | 注册面、优先级、格式 | `@` 展不展开、正文进不进、诱饵中没中 |
| 查不到 | 实际加载时漏没漏、有没有第三条通道 | 为什么是这样、改了版本会不会变 |

第三条通道（最近打开过的文件 + git 状态）**在 bundle 那一轮完全没看出来**，
它不在任何一份配置文件里，只有问模型才撞得到。
反过来，`@` 不展开这件事静态读也许一眼能看出来，行为量花了四轮。

**结论：两种读法查的不是同一件事，都要做，顺序上先行为后源码。**
行为读数告诉你哪一格反常，再去源码里找那一格为什么反常。

## 5 本篇查不到什么

照写，不吹：

- **只量了一家半。** Cursor 量全了，Claude Code 只量了 `@` 展开那一格（而且是正读数）。
  Kiro、Codex 一格没量。
- **只量了「进不进」，没量「排在哪」。** 同一份上下文里，靠前靠后、被截断的风险有多大，一格没碰。
  `hooks.md` 第 7 节那组长度测量说输入越长输出越差，本篇没有任何一条能接上那个测量。
- **没量版本漂移。** 结论是 Cursor 3.17.19 这一版的，下一版会不会变，没有数，也没有复测计划。
- **诱饵只证了那一轮没偷读。** 它不能证明模型在别的轮次里也没偷读。
- **第三条通道的边界没划清。** 「最近」是几份、按什么淘汰、git 状态进的是哪几栏，全没量。
  只知道七份里有六份进了、`ch2.md` 没进。
- **没量子代理那一侧。** 派出去的手拿到的是不是同一份上下文，一格没碰。
  这一条对母本不小——三只手是不是都自动读到根锁，现在不知道。
- **暗号本身可能有偏。** 用的全是「X 档」这种同构的词，模型可能把它们读成一类而整批召回或整批漏掉。
  换成结构不同的暗号会不会读数不一样，没试过。
