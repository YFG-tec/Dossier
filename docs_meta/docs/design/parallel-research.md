## 三题的调研路线（草案）

### 一、任务切分
- 最小实验：挑一刀「交什么」≥3 路径的活（如 6.13 这种三文件刀），卡面直接写「分块表：块→路径→手」，两 builder 各领一块，领班验收合集。
- 判据形状：合集 diff 等于单手 diff（字节级）；两块无同文件写。
- 风险：块间隐性依赖（A 块的函数 B 块要调）——先只在**纯文本刀**上试，代码刀后置。

### 二、多 agent 并行
- 载体现成：AutoClaw subagent async ×N + Codex exec 独立进程。真正的缺口是**在办锁**（loop.md 机械件 #2）：两 agent 同改一文件的互斥。
- **在办锁 v0 细形**（2026-10-02 空转产出）：
  - 锁文件：`.tmp/locks/<行号>.lock`，内容三行 `agent=<派单对象> / taken=<ISO 时戳> / cut=<卡号>`（cut 供 check-sync 顺手对账）。
  - 四规则：派单前查锁（在→断点呈报）；取锁原子写（临时文件＋rename）；收口放锁（close_cut 末步删；忘删由巡查报警——锁龄超刀均时长×3 视为泄漏）；锁零权威（丢了不废刀，只报警）。
  - 与 check-sync 互补：sync 查「表说在一刀」，锁查「真有一刀在跑」——不合并。
  - v0 只锁 Codex 施工；subagent 无收口钩子，v1 再议。
  - 冒烟样例加第三档 `lock`：双 builder 撞锁必 FAIL——禁令档的亲兄弟。
  - 错法两条：把锁当第二真相（git 才是事实）；锁粒度到文件（一刀一锁够用）。
- 最小判据候选：撞锁 FAIL 文案含「撞锁」；收口后 locks 目录空；20 本不回归。
