# 队列：切碎的待办自己往下走

这是 2026-09-26 规划席议事的初稿，给人细读。不占 `todo.md` 一行，不是卡，不是判据。
要拿哪一句落地，先有人把它写进待办那一行。

早先的草图在 `later.md` 第 0–2 节（2026-09-09）：并行多 builder、代盖已定流程的印。

## 这一圈长什么样

人先把待办切成一行一行的刀，排成序列，授权一次：「按这个序列跑」。
此后刀与刀之间不再叫人，章界也不停。

定时醒来的那只手只读盘，把当前这一行归成三档：

| 档 | 盘上是什么 | 它做什么 |
|---|---|---|
| 在办 | 这一刀的会话还在写 | 什么都不做，等下一次 |
| 可盖 | 审卡不挡，或验收读数和卡面逐字相符、审查页判过、没有请示 | 代笔下一爪：点下一行、落开工印，或结案（勾行、搬已办、只提交这一刀点名的路径） |
| 断点 | 读数分叉、退卡、要松判据、要发授权、这一行还没切碎、要改序列、要动根基条款 | 就这一行发一封信，然后停。不改序列，不在信里问下一章 |

一刀里面仍是现在这条流水线：写卡、审卡、开工、建造、审查、收口。
同一时刻只跑一刀。同一个文件同时只一只手改。

## 已说定的形状

下面这些是这一轮人话里已经定下的方向，仍是草案，不是条款。

1. **人的代理是为了让一串切好的待办基本自己跑完。** 它不切行，不改目标。切碎发生在开跑之前，落在盘上。
2. **章界不是停点。** 章头里的依赖（谁不许早于谁）只当行与行的顺序用。章末还要人看的那一眼，本身先切成一行，跟别的刀一样跑。没排进序列的行跳过，不因为「这一章还剩几行」停下来问。
3. **定时手在两席外面。** 会话一关，领班就停；队列要靠一只会自己醒来的手。它每次只做三件事：看盘、在断点上写建议、在可盖时盖章。建议不点行，盖章不改序列。
4. **建议和盖章分开。** 同一只模型又出主意又盖章，就会把「差不多」收成通过。
5. **醒来按刀，不按章。** 上一刀收口，或安静一段仍停在「等结案」，起来看一次。同一次绿再醒一次，必须是空操作，不能盖出第二个 commit。`push` 不在这只手里，除非这串序列的授权原话写了推。
6. **一个文件同时只一只手改。** 手头的手觉得工作量过大，可以向领班交分解方案。方案只写：卡上「交什么」里哪些路径分给哪只手、每只不碰什么、合起来仍是原来那一整份。领班核对路径互不相交、合集等于卡上那一份。对上了就多派。批语落在 `SESSION` 横线以上。要新路径、少一格、改判据、或其实是另一行待办，领班不批，这一刀退卡。
7. **第一圈先不真盖。** 每次醒来只写下「会盖哪一爪、依据是哪几格」，拿已结的刀回放。`6.25` 那种格读数和卡面不一致，必须判成断点。回放对了再打开盖章。

## 三只角色

角色仍是写权限加上失败时许做什么，不是人设。决定权仍是那几爪；这一稿改的是哪几爪可以按事先写死的式子代笔。

### 人的代理

住在领班之上，干签批。执行的是序列那一次授权，不新造一爪。

能盖的只有三种代笔：点序列里的下一行、落开工印、结案。
结案包含勾行、搬进已办、commit。commit 只含这一刀点名的路径，工作区里的旧脏不跟进去。

发授权、松判据、改序列，永远走断点。「这个问题比较简单」若由它自己判定，闸一就没了。

和领班的分工：领班把当前这一刀做完并呈上读数；代理只看这一刀有没有按卡走完，走完了才放行下一刀。

### 定时手

代理要能离开聊天窗口还在，才需要这只手。它是代理的醒来方式，不是第四席。

谓词要能重复跑。断点同一行只发一封，发出去的标记写在盘上。
信里点明行号、哪一格对不上、日志在哪。

### 大副

领班的上下文会被这一刀挤满。大副是另一个会话，只读，不接这一单具体的活。
产出只有安置：这一刀碰的是哪一条根基、盘上哪一行、和哪一节冲突。
它不写核、不写卡、不判过不过、不替人签。一能写就是第二个领班；一能判红绿就抢走言官的位子。

规划席在开刀前握着整图。大副在施工中回答「这一下踩没踩地基」。两边都只指盘，不互读聊天。

第一圈可以不带它。改通则、松判据的刀先不放进序列；碰到就停。大副是以后让这类刀进序列时的保险，不是第一圈转起来的条件。

### 一刀之内的多只手

并行发生在一刀里面，不跨刀。领班按批过的切块派多只建造的手，每只只写自己的路径。
同一份文件不切开。跨刀并行不开：一次只一刀，指纹也分不出是哪只手写的。

没有这只申请，队列一样能走。它是一刀里面的加厚。

## 第一圈缺的机械件

角色说完，圈还转不起来。缺的是刀与刀之间这六件。没有它们，定时手醒了只是在读一篇散文。

1. **序列单。** 授权过的行号、现在停在哪一行、这一行走到哪一步。写在一份不随 `SESSION` 覆盖的单上。`todo.md` 不是这张单，里面还有没切碎的行。
2. **在办锁。** 上一刀的会话还在写，不再拉起第二刀。
3. **拉起下一会话。** 盖完章之后，用固定的一句话打开下一席：写卡、审卡、按卡片做、或审查。开不了会话，队列停在窗口外面。
4. **能读的绿。** 审卡页要有能对上的结论，验收读数要和卡面逐字相符。对不上就停。
5. **结案只提交点名路径，且可重复跑。** 旧脏不进 commit。同一次绿再醒是空操作。
6. **断点只发一封。** 标记在盘上。

胖行留在开跑之前。队列碰到没切完的行，按断点停下，不自动把一行切成几刀。

## 规划席追记 · 2026-09-26（材料，不当判据）

应人「充分研究一下这个课题」。下面只写看法，不改上面初稿。读法同本页开头：一条都不可引。

### 一、这一稿真正挪动的不是三只角色，是结案那一爪

初稿把并行、大副、定时手都写成角色，读起来像加了三只手。实际上并行和大副都是刀内的加厚，不碰圈；定时手只是把代理从聊天窗口里解放出来。真正让圈闭上的只有一件事：**结案从「每刀人亲口说」改成「序列事先授权，读数对上就代笔」**。

`roles.md` 现在写着「只有人能做的三样：结案、发授权、松判据」。这一稿把结案从三样里拆出来，变成「人可以一次授权一串」。这是整份稿负荷最重的改动，也是它能不能成立的分水岭。`later.md` 第 2 节写的是「结案不可交」，本稿写的是「可代笔」。两处对不上，不是笔误，是立场换了。回放不过，这处不能当已经说定。

### 二、可盖谓词必须能机读，否则定时手读的是散文

初稿写「验收读数和卡面逐字相符」。卡面是散文，读数是日志。逐字相符这四个字，机器做不到，只能人读。`hooks.md` 第 3 节已经写过这个坑：「机器一跑就知道」写了，但机器只有一半——`check-done.sh` 干的是对账，缺的是把它从验收脚本变成查询命令。

可盖谓词要落成一条命令，不是一段描述。它得答：当前行号、当前卡号、验收命令退出码、审查页有没有、请示节是不是空、`git status` 是不是只剩卡上点名的路径。这些字段现在散在 `SESSION.md`、`todo.md`、各检查脚本里，没有一处把它们收成一条「这一刀能不能盖」的查询。没有这条命令，定时手每次醒来都要把整篇 `SESSION.md` 读一遍，然后自己判断——那和领班没有区别，只是换了个名字。

### 三、序列单不是 `todo.md` 的子集，是另一份状态

初稿写「序列单：授权过的行号、现在停在哪一行、这一行走到哪一步」。这三样里，行号在 `todo.md`，停在哪一行和走到哪一步在 `SESSION.md`。`SESSION.md` 每刀覆盖，上一刀的运行态结案就扔。序列单若只是 `todo.md` 里加一列「在序列里」，那「现在停在哪一行」就没有落点——`SESSION.md` 一覆盖就丢。

序列单得是一份不随 `SESSION` 覆盖的文件，而且它的写权限要单独划。现在 `todo.md` 的写权限在「人」格里是「只勾」，规划席和实现席两格对它都是未定义（`6.18` 已经记了这个洞）。序列单若落在 `todo.md` 旁边，就是第二个「不在权限表上的格子」。它该有自己的一行，写清谁写、什么时候写、写完谁读。

### 四、拉起下一会话是整份稿最薄的一格

初稿写「用固定的一句话打开下一席」。这一句话现在不存在。Cursor 和 Claude Code 的会话都是人开的，没有 API 能从外部拉起一个带上下文的会话。定时手能做的是把「下一刀该干什么」写成一份文件，等人或另一个自动化去读。但那就不是「拉起」，是「留言」。

这一格若落不了，队列就停在「盖完章，等人开窗口」。定时手变成了「定时留言手」。这不是贬义——能自动结案、自动留言，已经省掉人每天四件事里的三件。但初稿写的「自己往下走」会打折扣：走的是结案，不是开工。开工仍要人点一下，哪怕只是回车。

### 五、断点发信是单点故障

初稿写「断点：就这一行发一封信，然后停」。信发到哪、谁读、读了之后怎么回到队列，都没写。若人三天没看邮箱，队列就停三天。这不是 bug，是设计——断点就该停。但停多久、停到什么时候、有没有升级路径（比如第二次发信、或标记为「长期断点」），初稿没有。

更实际的问题是：断点里有一类是「这一行还没切碎」。这类断点不是故障，是常态。每次碰到都发信，人会淹没在信里。初稿写「胖行留在开跑之前」，但序列是人排的，人排的时候可能把没切碎的行也排进去。定时手碰到这种行，该发信还是该跳过？跳过就是改序列，发信就是噪音。这个边界初稿没划。

### 六、和 `hooks.md` 第 3 节是同一格，别重复发明

`hooks.md` 第 3 节写「让程序算出下一步」：命令答哪些行开不了，人从剩下的里面点。那一节的前提是「点行仍是人的」。本稿把点行也交出去了——序列授权一次，代理点下一行。这是把 `hooks.md` 第 3 节往前推了一步：不只算开不开得了，还算该不该现在开。

这两格是同一个问题的两个深度。`hooks.md` 那格是「帮人算」，本稿是「替人做」。若本稿成立，`hooks.md` 第 3 节就过时了——不是它错了，是它被包含进来了。但 `hooks.md` 第 12 节写着「第 3 节那个『命令答哪些行开不了』没有原型」，本稿的可盖谓词比那个原型还大。先有小原型，再有大谓词，顺序不能反。

### 七、第一圈的回放标准要写成命令，不是「回放对了」

初稿写「回放对了再打开盖章」。回放对了是什么？是定时手在 `6.25` 的盘上跑一遍，输出「断点：格 1 读数 2 对卡面 1」？还是输出「可盖」？前者对，后者错。这个对错要写成一条断言，不然「回放对了」本身就是人读一遍——正是 `verify.md` 禁止的那种验收。

回放该长这样：拿已结案的刀（`6.11`、`6.14`、`6.15`、`6.25`），把当时的 `SESSION.md`、`todo.md`、检查输出喂给定时手，看它输出的档位和实际人的决定一不一致。`6.25` 必须输出断点，`6.14` 必须输出可盖。这个对照表要写成测试，不是散文。

### 八、一个更小的第一圈

初稿的第一圈已经比愿景小，但还可以再小。小到什么程度？小到只干一件事：**定时手每次醒来，把「会盖哪一爪、依据是哪几格」写成一行日志，不真盖**。跑一个月，看它的判断和人的实际决定一不一致。不一致的地方就是谓词没写死的地方。这比「回放已结的刀」更真——回放是事后，这是事中。

这个更小的第一圈不需要序列单，不需要拉起会话，不需要发信。只需要一条命令和一个日志文件。它验证的是最核心的问题：可盖谓词能不能写成机器能跑的。这个问题不验证，后面的序列单、拉起、发信都是空中楼阁。

### 九、三只角色里，只有定时手是必要的

并行是刀内加厚，大副是以后的事，定时手是让代理离开窗口的唯一理由。但定时手不是角色，是代理的醒来方式。初稿把它写成「三只角色」之一，读起来像要给它划写权限。它不该有写权限——它只读盘，写日志，发信。它的「写」只有两处：日志和信。这两处都不在现在的权限表里。

若把定时手当成角色，就要给它划「只许动日志和信」的格子。若不当角色，它就是一段 cron 或一个 hook，不是手。这个区分初稿没做。`hooks.md` 第 9 节已经讨论过「触发器」和「命令」的分别，定时手是触发器，不是命令。它的输出（日志、信）是命令的输入，不是命令本身。

### 十、最该先回答的问题

初稿「还没定」列了七条。最该先回答的不是「序列单放哪条路径」，是：**可盖谓词能不能写成一条命令，且这条命令在 `6.25` 上输出断点、在 `6.14` 上输出可盖**。这一条答不了，其余六条都是白答。

这条命令现在不存在。`check-done.sh` 对的是账，`check-gate.sh` 对的是闸一，`check-link.sh` 对的是结构。没有一本对「这一刀能不能结案」。要写这本，得先把「能结案」的定义从散文变成字段。这是本稿落地前唯一必须做的事。
