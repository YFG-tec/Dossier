**建议：摘掉 `tee` 和 `chmod +x`，并且给这一档改个名。** 叫「读测」而里面躺着写动作，

### 5.3 落之前要量一次：前缀看不看得见重定向

要是罩住了，A 那一栏放出去的 `echo` / `awk` / `sed -n` / `grep` 四条**全部等于写权限**，
而且写得到运行态和卡。这和 §2 末那句「壳上 `cp`/`rm` 还能绕过编辑器」是同一个病，

量法很便宜：先只放一条窄前缀，跑一条带 `>` 的命令，看弹不弹。
**这一量在改盘之前做，不是改完再补。** 量出来是「罩住了」，A 就落不成只读，

### 5.5 C 档今天在盘上是空的（照记，人裁暂不处理，不补）

现数：**两份 `settings` 都没有 `deny` 键，全仓一处 `deny` 都没有。**

而 `allow` 里已经躺着两条，各自等于 `Bash(*)`：

- `Bash(python -c ' *)` —— `python -c` 能写任何文件。
- `Bash(cat > *)` —— 能盖任何文件。

C 想拦的 `rm -rf`、对 `.git` 动手、出仓网络，都能从这两条里过去。
**「全留问」这句话今天不成立。**

还有一层：这种松是**不可逆的**。手一滑点一次 Yes，`allow` 里就多一条宽前缀，
而没有 `deny` 压得住它——`deny` 不存在，所以没有任何东西能把已经放宽的收回来，

### 5.6 B 为什么落不了地（照记，人裁暂不处理）

B 的写法是「落到 `docs_meta/`、`.claude/`、源码仍问」，也就是**按目标路径分档**。
前缀匹配匹的是命令字面的开头，而目标路径是参数，不在开头。

`Bash(cp *)` 罩住所有 `cp`；`Bash(cp .tmp/*)` 只罩第一个参数在 `.tmp/` 下的那些——
可是 `cp a .tmp/b` 和 `cp .tmp/a b` 首参数的位置正好反着，一条要拦、一条要放。
**一条前缀表达不出「写到哪里」。**

落得了地的三条路：反向用 `deny` 拦目标路径；写一个 `PreToolUse` hook 自己解析命令行；
或者承认这一档做不到，把它整档并进 C，一律问。

### 5.7 §0 和 §3 两处口径对不上（页内的，不是实现席的意见）
