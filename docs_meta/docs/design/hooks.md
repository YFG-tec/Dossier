# 卸载：条文要细，模型背不动

**权威：参考。** 全文不带标记，**一条都不可引**——是 2026-09-10 的思考，不是现行条款。
要拿这里的哪一条当判据，得先有人把它抬进 `paradigm.md` 或等章界过了再立案。

**本篇不要单独开刀。** 它是第 2 章产物侧（`2.4` / `2.5`）怎么编锁的思路，也碰 `4.1` 那种「入口住 `.tmp/`」的搬家。
第 2 章文档侧没走完，产物侧一行都不许开。第 5 章不开也不并进。`later.md` 里代盖已定流程的印，仍排在这后面。

人 2026-09-10，对照 Kiro 的钩子，问的是：条文拆得够细才能准，模型却因此背不动。

本篇答的是这一问的一般形。钩子只是答案里的一格，不是全部。
外部材料（Kiro、Spec Kit、OpenSpec、aider、BMAD）当对照读，**一条都不可引**，同 `xenia.md` 的读法。

## 1 三个搬运终点 — 草案

**草案：这个分法是判断，没验证过。**

拆细条文和模型背得动，本来不冲突。冲突只在一种情形下发生：条文全部住在上下文里。
所以问题不是「条文该不该细」，是**判断能搬到哪里去**。只有三个终点。

| 搬到哪 | 硬度 | 靠谁活着 | 母本现状 |
|---|---|---|---|
| 搬进程序 | 模型绕不过 | 厂家的事件词汇表 | **零** |
| 搬上磁盘 | 模型可能读漏 | markdown + git | 足。合同层、卡、`todo.md` 都是 |
| 搬进另一个上下文 | 省得最多，最软 | 「能开两个会话」 | 足。两席、两个会话 |

母本在后两层做得比外面那几套都深。第一层一个字都没有。
`.tmp/check-*.sh` 那七个是第一层的半成品——命令已经写出来了，缺的是推。
现在是模型得记得去拉；忘了就静默过。

这一张表也是本篇的排序依据：先补第一层，后两层不动。

### 第三栏要单独说：harness 还没定型 — 草案

人 2026-09-10：模型技术算比较成熟，harness 还远远没定型。

**成熟的不是能力，是接口契约**——模型是一个从上下文到 token 加工具调用的无状态函数，
这条约两年没动过。所以「把判断搬出上下文」这个动作本身不会过期。
能力那一侧反而还在动，且动的方向反直觉：见第 7 节那组长度测量，以及 aider 那个
「编辑格式的优劣随模型能力翻转」的结果。**不能从「模型成熟了」推出「可以少管它」。**

harness 那一侧，几处现成的证据：

| 现象 | 说明什么 |
|---|---|
| Claude Code 三十来个钩子事件，Kiro 一套，Cursor 一套，互不通用 | 同一个概念，三家三种事件词汇表 |
| Codex 的 VS Code 插件覆写 `writable_roots`（openai/codex#8029） | 配置分层这种基础问题，出货产品里还在错 |
| Codex 的 `on-failure` 审批档已废弃 | 语义在改，不是加功能 |
| Amazon Q Developer 退役，换成 Kiro | 整条产品线重来 |
| Cursor 卡住会吃掉正在编辑的内容 | 母本自己撞上的 |

不是「还能更好」，是**原语还没谈拢**。

由此第三栏才是这张表的重点：**凡是建在某一家 harness 之上的东西都在折旧。**
母本已经建成的两层恰好是不折旧的两层——`src/` 全是 markdown，两席只要求能开两个窗口，
两样都没押在任何一家身上。没建的那一层，恰好是折旧最快的。

**所以钩子的问法要改：不是「要不要装」，是「装哪一半」。**
命令是壳脚本，换谁都还能跑，现在就该搬（第 9 节）；
事件注册是折旧的那一半，编进锁、随桌走、不回流母本（第 8 节）。

**连带一条规矩，写在这里免得日后当税删掉：**
**因 harness 缺陷立的规矩，条文里要标出它立于何时、为哪个缺陷。**
现成的例子是「落盘后回盘上核一次，不信编辑器的成功回执」（第 10 节第 3 条）——
它读起来像通则，其实是 2026-09 一个具体 bug 逼出来的。
哪天那个 bug 修了、harness 定了型，下一个人看不出它为什么在。
按 §10 末句那个规律（不带理由的规矩，下一个人会当成税删掉），它会被删，而且删得有道理。
**标了来源，删它的人至少知道自己在删什么。**

## 2 钩子：搬进程序 — 草案

不是某一种语言。多半是「何时跑」加上「跑哪条命令」。命令可以是 bash、python、一条 `git`。

固定的、每次答案该一样的，写成命令；模型不再负责「要想起来去做」。
判断——这段有没有说反、过不过闸——仍留在模型和人手里。

厂家把动作分成两种，Kiro 和 Claude Code 都是。
第一种是 `command`：事件到了跑壳命令，不吃模型。
第二种是 `agent`：往对话里再塞一段提示，仍吃模型。
要卸的是思考负担，用的是第一种。第二种只是把说明书自动贴上去，条文一条都少不了。

**钩子和便宜模型不是同一档便宜。** 比的是失败长什么样。

钩子错，是命令写错或没挂上，错一次次次一样，能红。
便宜模型错，是这一次忘了、看漏了、把红说成绿。便宜，所以更愿意多问；问得越多，静默降档的面越大。

| 活 | 钩子 | 便宜模型 | 贵模型 |
|---|---|---|---|
| 停步跑检查、无印拦核、写完对路径 | 该它 | 多余 | 多余 |
| 抽路径、填表、落盘格式 | 做不好 | 该它 | 亏 |
| 审卡、验收里「意思有没有反」 | 做不了 | 不可靠 | 该它 |
| 结案 / 升格 / 松判据 | 不许 | 不许 | 人 |

倒过来——先上一只便宜模型把条文背一遍——条文还在上下文里，只是换了个更爱漏的读者。

`2.4` / `2.5` 不要把「用哪个模型」写进锁。锁只写怎么调命令。
便宜模型若要进，它是一只手（书记），不是一种档位。

## 3 让程序算出下一步 — 草案

钩子是被动的：事件到了才跑。还有一格更省，是让程序**主动算出下一步该做什么**，模型只负责做。

母本已经有让它可算的全部条件。`workflow.md` 那句写着：

> 每一份 `cmd/PROMPT_xx.md` 在 TODO 页上恰好出现一次，每一条已办恰好点名一份 `cmd/`；
> 对不上就是有一刀没落盘，**机器一跑就知道**。

「机器一跑就知道」写了，机器有了一半——`.tmp/check-done.sh` 干的就是这件对账。
缺的是把它从「验收脚本」变成「查询命令」：不只答对不对，还答**下一个该动哪一行**。

外部对照：OpenSpec 的 `status --json` 返回一个按依赖排序的清单，第一个 `ready` 的就是下一件该写的。
选哪一件不经过模型，是命令算出来的。

**母本不照抄这个形状。** 点行是人的动作，不是命令的输出（`workflow.md`「人每天只做四件事」第 3 件）。
可搬的只有下面这一半：

- 命令答**哪些行现在开不了**（占位未分解、依赖未落、`design/` 那一节还是占位）。
- 人从剩下的里面点。

这样闸一那一眼看的是「这一行该不该现在做」，不必再兼着算「这一行开不开得了」。
**减的是人和模型的算量，没有减人的那一爪。**

**2026-09-13 补一句方向，不是本节省的活。** 人把「流程压成 DAG」收成以后可能的优化：
查询下一边，代替读 `workflow.md` 全文。和本节同一半——命令算开不开得了，点行仍是人的。
省上下文的条件是**代替阅读，不常驻第二份**。第 2 章没交完不开。展开见 `later.md` 附二、`open.md` 第 10 条。

## 4 给手的输出一律结构化 — 占位

**占位：检查的输出该长什么样？现在七个脚本各长各的。**

外部对照里最便宜的一条来自 OpenSpec：所有诊断统一成一个信封。

```text
severity   error / warning / info
code       机器可读的短码
message    给人看的一句话
target     指到哪一处
fix        一句可执行的话或一条命令
```

值钱的是最后那个 `fix`。报错不只说哪里错了，直接给出怎么修。
读的那只手不必再推理补救路径，照做即可。

同一份材料里另有两条，都是减负的：人类散文和进度条走 stderr，stdout 只留一份结构化文档；
退出码的含义写成一张表，不靠读输出猜。

**这一条对母本的用处不止在钩子上。** 退卡页三段（哪条做不到 / 试过哪几条路 / 卡在哪一层）
已经是结构化的，但没有 `fix` 那一栏。对账表同理：「没做到」后面应该跟一句「下一刀该怎么开」。

**占位：`fix` 这一栏要不要写进卡片最低字段？** 写进去就是给所有桌加一栏，不只是母本的事。

## 5 交叉一致性：现在没有东西会红 — 占位

**这一节接的是 `paradigm.md` §6，那是本页最重要的占位。**

母本每一刀只有「人读一遍」这一道验收。已经出过一次事：
`ch2.md` 附二那张表漏了三节，**是人派的独立审查用眼睛查出来的，不是脚本**。

外部有一个现成的形状，Spec Kit 叫 `analyze`：在动手之前，跨几份交付物查六类。
逐类对到母本身上：

| 类 | 查什么 | 母本对应 | 现在有没有 |
|---|---|---|---|
| 重复 | 近似重复的条目 | 两份文件互为第二真相 | 无 |
| 含糊 | 无度量的形容词、`TODO` / `???` 占位符 | 卡上的验收命令写成「检查一下」 | 无 |
| 欠规定 | 有动词没宾语、没有可度量结果 | 「交什么」不可验收 | 无 |
| 合同冲突 | 与不变量抵触 | 与 §3 那七条抵触 | 无 |
| 覆盖缺口 | **双向**：条目无任务，任务无条目 | 已办 ↔ `cmd/` | `check-done.sh` 有一半 |
| 不一致 | 术语漂移、交叉引用指空 | 层名、`【定】` 的裸 / 提及之分 | `check-link.sh` 部分 |

三处细节值得单独记，都不是「多一个检查」那么简单：

**一、这只手严格只读，一个字都不写。**
和 `workflow.md` 的审查那只手（「什么都不写，连 `.tmp/` 都不写」）是同一条骨架，
不是新规矩，是老规矩多了一个实例。

**二、合同冲突自动判成最高级，且不许稀释。**
外部原话的意思是：撞上合同就得改下游那几份，不许重新解释合同、不许悄悄放过。
合同本身要改，必须是**单独一次明确动作**，不能夹在别的刀里顺手改。

这一条正好答母本一个悬着的问题：**改检查脚本算不算松判据。**
删一个检查显然是。改它的匹配面让它少查几条路径，也是。
按上面那条读，答案是：**动检查的口径要单独一刀，不许夹带。**
`paradigm.md` §9 已经有过一次教训（`PROMPT_008` 既写 `workflow.md`，又给 `check-link.sh` 加了 D 段）。

**三、检查自己有 token 预算。**
外部那份写着「至多报 50 条，其余进溢出摘要」。
检查的输出也是要进上下文的；一个吵的检查比没有检查更贵。

**占位：这六类里哪几类属于把关层，哪几类只是「口」？**
§6 那条已定判据划了下界（能机检的是词的共现，不是意思）。
上表六类**全部**落在词的共现这一侧，所以它们补的是「口」，不是把关层。
**这一句要写死，否则装上之后 §6 会因为有绿灯而显得不急。**

## 6 查规矩写得够不够 — 占位

上一节查的是几份文件互相对不对得上。还有一类查的是**单独一条规矩写得能不能被执行**。

外部把它叫「英语的单元测试」，并且明写它不是什么：

- 不是验证实现对不对。
- 不是检查代码符不符合说明。
- 是问：这条要求完整吗、量化了吗、边界写了吗、跨处一致吗。

母本身上的样子，举三个现成的：

- 「一行永远只是点名某一节加一个勾选框」——**量化了**，能查。
- 「卡片交 3–6 条可验收」——**量化了**，能查。
- 「框架要聊全，判据只要够第一刀」——**没量化**，查不了。它是判断，该留给人。

同一份材料里还有一条，和母本一条老规矩撞了个正着：

> 本命令生成或追加清单条目，**它绝不能自己把条目勾成 `[x]`**。
> `[x]` 表示审阅人判定该条质量达标，不表示实现完成。

这是别处独立长出来的「代理不准自己勾」。
收敛到这个粒度，说明那条规矩不是母本的偏好。这算一条外部旁证，见第 9 节。

## 7 上下文腐烂：两席的第二条支柱 — 草案

`paradigm.md` §5 立两席的理由是分工：两席各背一条方向相反的品质要求，一只手同时背等于一条都不背。

外部有第二条理由，走的是完全不同的路。
2025 年有一组测量，覆盖 18 个当时的前沿模型：**输入越长，输出质量越差，每一个模型、每一个长度增量上都成立**。
上下文没满也会退化。有效窗口远小于标称窗口。

由此得出的做法有两条，都和母本对得上：

- **隔离。** 把一段活放进独立的上下文窗口，探索过程不回流主对话。两席、两个会话就是这个。
- **早压缩。** 到一半就压，不要等接近上限。

**这条对母本的用处不是改设计，是补一根支柱。**
两席现在只靠「分工」一条理由撑着；分工是可争的，退化是可测的。
`paradigm.md` §5 那句「席不参与重判」因此更硬：重判的是手，因为手是分工问题；席还压着一个物理问题。

**草案：要不要把这条写进 §5？** 写进去就是给一条已定结论补理由，不改结论。
按 §10 末句（不带理由的规矩，下一个人会当成税删掉），倾向写。

## 8 一份真相，锁里只写调用 — 草案

源码只保一份：检查怎么跑、对哪条路径、红是什么。
`.claude` / Cursor 的锁里只写**怎么调这份**，让那个 harness 自己去用。
不给 Cursor、Kiro、Claude 各编一份钩子 JSON——那就是第二、第三真相。

产物是说明书，不是又实现一遍。口径改了只改源；锁里若还抄口径，就是 `xenia.md` 那种抄三份。

**这条有第二个理由，比「不许有第二真相」硬。** 按第 1 节第三栏：
**唯一真相那一份，同时也是唯一不会随厂家一起过期的那一份。**
壳脚本换谁都还能跑；事件注册的键名、matcher 语法、配置分层，三家各一套，且都还在改。
所以这不是洁癖，是把折旧面收到一处——真要过期，只过期锁里那几行调用。

停步跑哪条命令，是读锁、照做，不是判断。这点儿都做不到，条文写得再细也没用。
不够格的，换手，不把逻辑再抄一遍去迁就它。

代价认下：调不调仍取决于那只手有没有按说明去做。宁可漏在调用，也不让三份文件各漂一次。
要补厂家事件注册，是桌自己的事，不回流母本。

## 9 落点：单独成层，不要根上的点目录 — 草案

单独成层，这个冲动对；叫 `.hook`、还点在仓库根上，不合适。

目录按权威分层，不按「这是不是自动化」。命令能红、能复跑，权威在实现或把关，不在草稿。
根上再点一个点目录，旁边已经有 `.tmp`（零权威）和 `.claude`（产物）。第三者会把它读成第三份私货，或读成又一个 `.tmp`。
和厂家也撞名（`.kiro/hooks`、Claude 也可能在 `.claude` 里挂钩）。

形态也对不上。`docs_meta/` 不铺进宿主工作区。根上 `.hook` 若跟着铺过去，桌就多了一棵母本检查树；
若不铺过去，锁里的调用会指到一份桌上没有的路径。

| | 母本 | 桌 |
|---|---|---|
| 命令（唯一真相） | `docs_meta/src/` 下单开一层，从 `.tmp/check-*.sh` 搬过来 | 各桌自己的 `tests/` |
| 调用说明 | 编进锁：「停步跑哪条」 | 同一份锁，指向**本仓库的验收入口** |
| 厂家 hook 文件 | 不维护 | 桌爱挂不挂，不回流 |

先把命令从 `.tmp/` 请出来，比先发明目录名要紧。那是 `4.1` 同类的搬家：入口不准继续住零权威层。

**占位：这一层叫什么。** 原稿写的是 `src/hooks/`，现在看不一定对。
盘上那七个文件叫 `check-*.sh`，它们是**检查**；钩子是**触发器**。
叫 `hooks/` 等于把触发器的名字安在命令身上，而第 8 节刚说触发要留在锁里、命令才是唯一真相。
按 §10 那两条命名判据（不借外部方法论的词、要经得起在正文里反复出现）重挑一次，
`checks/` 大概更贴。**没定，留给那一刀。**

## 10 先做 / 不要做 — 草案

值得先做的，都是已经拆细、且不需要懂意思的：

1. **停步跑验收。** 自动跑卡上那串检查，stdout 落 `.tmp/`。领班不再背「绿必须落盘」。
2. **写完对路径。** 对照本刀卡点名的路径；多动了当场红。审范围，不管实现好不好。
3. **写完验盘。** 关键文件写完立刻回盘上核那几行在不在，不信编辑器的成功回执。
4. **写之前拦一拦。** 没红印不许改核；勾 `todo.md` 只许人那一爪的口令进来。

不要做成机械层的：

- 闸一、结案、松判据。人的三爪。代盖是 `later.md` 那一档，现在没到。
- 「这段读下来是不是仍说反了」。`paradigm.md` §6：机检是词的共现，不是意思。

## 14 软钩：本仓库养工具，调不调交给模型 — 草案

人 2026-09-10，`2.5` 结案之后。对照 DeepSeek Harness 的插件，裁的是这一句：

**要装的是软钩，不是硬钩。原则上叫 `tools`。** 本仓库自己维护；怎么用交给大模型自主调用，卸的是思考需求，不是触发本身。

和本篇第 1–2 节原来想装的那一半反过来。硬钩是厂家事件推命令（文件写完、工具调用，harness 自己跑），省的是「要想起来去做」，押的是各家事件名——第 1 节第三栏已经写了，原语没谈拢，建在上面的都在折旧。软钩是仓库里一份工具目录（名字、干什么、怎么调），**调不调是模型拉，不是事件推**。形状近 DeepSeek 的 `defineTool`：插件注册在仓库里，模型看见描述就自己 `execute`。

| | 硬钩 | 软钩（这一裁） |
|---|---|---|
| 触发 | harness 事件 | 模型自己决定 |
| 住哪 | 厂家配置，折旧 | 本仓库 |
| 谁用 | harness 推 | 大模型拉 |
| 卸的是 | 「要想起来去做」 | 「要想起来怎么做」 |
| 对照 | Kiro / Claude Code hooks | DeepSeek Harness 插件 |

和刚结案的 `2.5` 能接上：`docs_meta/tests/run.sh` 已经是一条能被叫的命令。软钩要补的是**目录和调用约定**，不是再挂一家 `.claude/hooks`。锁（`2.4`）里只写「工具住哪、怎么调这一份」，不把口径抄进各家 JSON。第 8 节那条（一份真相，锁里只写调用）仍然成立，只是「调用」的主语从事件改成了模型。

三件不要并进去，和第 10 节同一条铁：闸一 / 结案 / 松判据仍是人的爪；「读下来有没有说反」仍是人读；厂家事件注册随桌走、不回流母本。

第 9 节那个占位（这一层叫什么）按这一裁收一格：**原则上叫 `tools`，不叫 `hooks`。** 叫钩子容易和硬钩撞名。还没立案，落点写卡时裁。

## 15 口少、服务可以多 — 草案

同一轮问的是：平铺一堆工具给模型选，还是数个统一接口、每个下面一串服务。

**数个统一接口，每个下面一串服务。** 接口数量要克制；接口下提供的服务可以尽可能多。平铺一堆工具，模型要背的是一份会涨的菜单；统一接口，模型要背的是三四个入口，菜单在磁盘上现查。

平铺的病，`2.5` 刚治过一次：八本检查住 `.tmp/`，模型得记得去拉，忘了就静默过。收成 `run.sh` 一条入口、下面八本——已经是「口 + 服务」。再给每本各挂一个 tool，等于把入口拆回去。

接口少，还有三条理：

- **上下文。** 工具描述进系统提示。接口每加一个，人人都要重新选；服务每加一个，只涨那一个口里的目录。第 7 节那组长度测量：输入越长输出越差。
- **折旧。** 接口是合同，服务是实现。锁只写「调这几个口」，不写一串服务名。换一家 harness，只迁这几个口。
- **发现可以软。** 每个口带一条 `list`。模型先问「这个口下面有什么」，再调，不必把四十条说明书塞进上下文。软钩卸思考卸的是这一截：不用想「有没有、叫什么」，想「这一步该走哪个口」。

接口不要做成万能口令。一个 `do(action=...)` 包天下，是把菜单藏进参数，选型负担没少，类型还松了。好的形状是**口少、每个口的动词闭。** 新活先问归哪个口；哪个口都不要，才新开口，不新开 tool。

母本够用的大概就这几个，先记不立案：

| 口 | 下面的服务（可涨） | 不干什么 |
|---|---|---|
| `verify` | 全量、单本、绊线、先红后绿 | 不裁「绿了算不算通过」 |
| `query` | 哪行开不了、指针在不在、本刀点了哪些路径 | 不点行（点行是人） |
| `record` | stdout 落 `.tmp/`、对账表骨架 | 不勾、不 commit |

`2.5` 的 `run.sh` 就是 `verify` 的第一根腿。`query` / `record` 现在还没有，不必为了齐三个口硬造。

和 DeepSeek 那套不打架：插件是**服务**（一份 `execute`）；注册进仓库的是**口**。模型调的是口，不是四十个插件名。Code Mode 更极端——一个 `run_code` 当口——母本不必走那么远，三个口已经够克制。

平铺只在一种时候更合适：服务互相不成系列、调用极稀、描述必须各自极短。母本的检查、查询、落盘都是系列活，不是这种。

**开口是立案，加服务可以后补。** 模型看见的是口；口下面的目录可以长，口本身不长。

## 16 这一裁之后仍然查不到什么

第 12 节那几条还在。这一裁多三条，照写：

- **没立过一个口，也没注册过一个服务。** `run.sh` 是入口，还不是 `verify` 这个口。
- **三个口是这一轮聊出来的草案，不是已定清单。** 少一个或多一个，要立案那一刀裁。
- **没量过「口 + list」比平铺少选错多少。** 减思考是方向，没有对照数。

两句判断先摆前面。

**一、检查装死和检查通过，在盘上长得一样。**

Kiro 的 `command` 动作只认三档：`exit 0` 过，`exit 2` 拦，其它一律 `silent failure, no block`。

所以第 10 节那条「没红过的检查不算装好」不是洁癖，是退出码语义逼出来的：
不主动让它红一次，就分不出装好了还是装死了。
Cursor 的判决走 JSON 不走退出码，脚本挂了算什么，没核。

**二、漂的是注册那一半，收敛的是命令那一半。**

这一句要限范围：**收敛的是 Kiro 和 Claude Code 这一对，Cursor 是另一套，Codex 根本没有判决面。**
Kiro v2 按工具调用分事件（`PreToolUse` / `PostToolUse` + matcher 正则），和 Claude Code 同一套，退出码语义也同一套；
Cursor 按动作分（`beforeShellExecution` / `beforeReadFile` / `afterFileEdit`），判决是 JSON 里 `allow` / `deny` / `ask`。
会话级事件反倒四家几乎同名（`sessionStart` / `stop` / `preCompact`）。
而厂家自己在承认注册面会漂——Kiro 的 agent 定义里明写要用工具标签而不是工具名，
理由就是工具会被改名重组，`.kiro.hook` 也已成 legacy 格式，代码里带 v1→v2 迁移器。
第 1 节第三栏那句「不是要不要装，是装哪一半」照旧，换成这条证据；第 14 节那一裁接的就是这里。
