## 病灶：三个触发器围不住 docs 面

隔离的三道现有触发器，作用域各占一角：

| 触发器 | 作用域 | 条文 |
|---|---|---|
| 改 `src/` 换会话 | 区域（席级） | `../../src/cursor.md:30` |
| 并行刀派 subagent 必发工牌 | 模式（并行级） | `../../src/roles.md:77` |
| 轻档减手数，声明代偿即可 | 档位 | `../../src/roles.md:275` |

串行＋docs 面＋重档的刀三不沾：写卡、施工、验收、汇账四角色同一上下文合流，全程零机械红。
39 桌 2026-10-08 搬迁刀是活标本（现场见报告「活标本」节）：动机良好、照条文走，照样掉坑——**公共库该按最差配合度的读者验收**。标本里验收脚本两次亮假红，写错的手和查错的手是同一个脑子，连误诊都共享。

归因订正一处：报告缺陷 5 说「39 转译丢了承重墙」，不确。「继续推进只够写卡或改文档」是母本原文（`../../src/roles.md:18`、`../../src/cursor.md:30`，2026-10-08 亲核）——**墙从来不在母本里，不是搬丢了**。docs 面的刀从源头就没进射程；修 39 的转译没用，得修母本规则的射程。

## 视角：洞在写权限表，不在公理层

- 隔离做得最好的是审查，靠的不是哪一句自觉，是**审查零写**（`../../src/roles.md:90` 写权限「无（只读、只跑）」，`:151` 「审查的手不写文件」）：一只不能写的手没法和施工手是同一只——施工必写。隔离是写权限的副产品。
- 「两份上下文」是宿主内部状态，盘上不可证。指纹防忘记，防不了同源：合流的那个会话最容易忘的恰是给自己发牌。
- 洞的形状：docs 面的卡，**写卡手与施工手坐在同一个写权限格**（规划席默认可写 `docs/`，`../../src/roles.md:91`），路径重合，物理上分不开。
- 盘上查得到的只有**换手痕迹**，而换手留痕只有一种方式：工牌。公理立十条也造不出这个痕迹。

## 修法草案：回避

**卡点名的产品路径，写卡那只手自卡落盘起只读，到结案解封。**

- 名字来历：公讼回避——经手立卷的人，不得同时经手卷内标的。旧公文词，循 5.37 画风。
- **名字裁定（2026-10-08）**：暂用「回避」，落实之前再查一遍成熟提法有没有占位。第一遍已查（当日现算）：
  - 原则位早有主——**分权**（`../../src/naming.md:23`「章不自己盖给自己：写卡的手不改核」）。回避不是新原则，是分权在路径层的落法。
  - 形状位也有先例——**「卡片点名才动」**已写在两张权限格上（`../../src/directory.md:303` 合同层、`:310` harness 件）。回避是把这形状从两格推广到一切卡点名路径，不是发明。
  - 近邻词各有主：「冻结」被生命周期义占用（`../../src/workflow.md:231` 结案冻结），「封存」在 `../../src/sources.md:32` 是封日志，都不抢。
  - 业内近邻是审计学的职责分离／四眼原则，中文原生对应正是「回避」。结论：槽位空着、不撞车；落实前照裁定再核一遍。
- 射程从「区域」（`src/`）改成「路径」（卡点名）：docs 面、串行、规划席可写区自动进射程，不分席内席外、串行并行。
- **判形（两半合成一次手交接；落印时点人裁在先）**：军事学类比只为讲得通——主帅落印＝决断，工牌＝虎符（牌与卡对合，`../../src/roles.md:79`「内容与卡冲突时以卡为准」）；**类比是材料，判据仍是条文与时点**。
  - **印前冻结（回避本半）**：卡落盘 → 闸一红印之间，卡点名路径**零变更**——主帅没拍板，谁都不许动。锚＝红印时点（每刀必经、自带日戳、`check-gate` 已守，`../../src/workflow.md:298`）；接归因两件（时间＋路径，`../../src/workflow.md:412`）。
  - **印后持牌（工牌半）**：落印之后，动卡点名路径的手**必须持牌**——印只证明决断，不证明换手。39 活标本恰是过了印才合流：印拦抢跑，牌拦自任，缺一不可。
  - **直令例外**：批外直令＝主帅亲点一员将，直令原文在 queue 台账——派将有案，视同持牌，不算合流。
  - 分兵派将发生在每一次决断之后，不是只在并行战：单刀＝派一员将，并行＝分几路兵——工牌作用域推广到「凡按卡施工」由此讲通。
- 规划席不丢能力：议事、立案、写卡、`design/`、`reports/` 照旧可写；**封的只是本刀卡点名的那几条路径**。与「合同要人点名才动」同形，从合同面推广到产品面。

## 换桌漂移：两种，各归各

| | 量什么 | 现状 |
|---|---|---|
| 版本漂移 | 字节走样（拉新后宿主那份偏没偏） | 内容戳已管（`../hardening.md` §二；5.19 落） |
| 语义漂移 | 意思走样（安装时触发器译窄、本质没跟过去） | **零信号** |

修语义漂移不从生成器做，从**触发器形状**做：射程写成「卡点名路径」，规则本身变厚——不管哪张桌，装完跑一次行为自检（写卡会话试图动卡点名路径必红）就能抓住。**规则的正确形状，比规则的转译保真更根本。**

与 `5.30`（转译基线种子＋比对脚本）的关系**已裁（2026-10-08 原话「并入」）**：语义漂移这一半并入 5.30 那一行，todo 行已随裁更新；本页「换桌漂移」节作它的材料页之一。

## 该留的新话（报告里真正新的，收这三条）

1. **上下文是物理量。** 换手＝换脑；同源偏见、指令密度、干扰面是约束条件，不是玄学。角色不是人设，是上下文容器。
2. **分工一句。** harness 解决一次调用的窗口问题，范式解决几百次调用之间的连续性问题；前者跟模型走，后者跟信任走。
3. **退役的尺。** 「模型没有这个缺陷了，这条还要不要」——要，是桌子；不要，是脚手架。
   - **起步机制（2026-10-08 人裁）**：流程未定形，先以**人手同意**的方式进行——领班在开发途中推荐退役候选，**必须给出详细理由**（哪条只补模型缺陷、模型已补上什么、退役后哪格接手）；同意权在人。单列一行（5.42 已立）。
