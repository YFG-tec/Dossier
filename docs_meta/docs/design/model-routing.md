# 模型路由：按模态分席（设计材料）

「我想针对不同场景自动选择不同模型」；「自定义模型，应该都能通」；「主要是glm5.3不是多模态模型，用起来有很多不便」。
要落地，先有人把它裂成 todo 行；判据写在行里。

## 分档的轴：模态覆盖，不是价格

初稿（同日）按「贵/便宜」切，错了。人点破的真实约束：**主力模型不是多模态**，
所有「要看」的事它都做不了——截图、图的 alt 与版面、首屏长得对不对、GUI 里那个选项长什么样。
这些活不是「更便宜的模型能干」，是「**另一个模态的模型才能干**」。分席按这条轴：

| 席 | 模型 | 领什么活 | 永不领 |
|---|---|---|---|
| **推理席** | 非多模态主力（现 GLM-5.3） | 写卡、建造、条文、审查签字、对账 | 一切「看」的活 |
| **眼睛席** | 多模态模型（自定义，都能通） | 截图巡查、图 alt 与版面核对、首屏/图形态验收、GUI 探查（键鼠手的眼） | 写卡、签字、动条文 |

**判定进命令的仍然优先进命令**（`check-verdict.sh` 先例）——命令连模态都不要，比眼睛席更省。
眼睛席只在「命令查不了形状」的地方上场：alt 与实图对不对、版面乱不乱、GUI 那个选项在哪。

## 现成的实证（都在本桌账上）

- 巡查手用 `desktop_agent` 截图＋OCR 读过屏（patrol-2/7/9/10…），那是眼睛席的活，干得动；
- 6.24 的 readme 帽子刀，验收 11 格全是 grep/行号——**恰好一格「看」的都没有**；但 `release.md` §0 的 90 分档写明「读者在第一屏之内看见①②③」，那一格机器查不了，只能眼睛席判；
- 框架图 alt 与实图的一致性（`3.3` 出图、`6.2`/`6.3` 行记的首页图账）是常驻的眼睛席活。

## 形状（草案）

- **代理席派单时按活选席**，不按刀选席——一刀内部两类活都有（建造是推理席、首屏验收是眼睛席），
  派单粒度到「格」或「步」，不到「刀」。
- 眼睛席的产出落 `.tmp/`（证据、形态描述），**不落结论**；「过/不过」仍由卡上判据＋推理席（或命令）定。
  眼睛席是感官，不是法官——同「审查只核对结果和标准」一族。
- 绑定在应用侧（Saved Agent 自定义模型），代理席不发明绑定，只选用。

## 判据候选（裂行时定死）

- 眼睛席验收格（如「首屏之内可见①②③」）有落盘证据 ≥1 份/刀（截图进 `.tmp/`）；
- 推理席的刀内不出现「看图」类验收（有则说明路由漏了）；
- `run.sh` 本数不涨。

## 错法

错在「看」的边界会漂：文本 diff 里混一段 alt 叙述，推理席读着也对——但「对不对」和「长得对不对」是两回事，
前者 grep，后者只有眼睛席。宁可多派一次眼睛席，也别让推理席拿文字猜版面。
