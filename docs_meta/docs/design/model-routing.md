# 模型路由：副官（设计材料）

**权威：参考。草案。** 不带标记，一条不可引。人 2026-10-02 六句原话立题：
「我想针对不同场景自动选择不同模型」；「自定义模型，应该都能通」；「主要是glm5.3不是多模态模型，用起来有很多不便」；
「有些模型原生多模态能力就很强，这一席原则上备用；先不叫眼睛席（主要是难听，功能没问题），重想个名字」；
「叫副官得了，副官必须是多模态模型」；「副官以后会常驻，他除了代看以外，上下文中还需要维护项目的整体状态，
如果有需求，代理席和规划席访问副官，这样代理席和规划席主要的精力放在规划和解决问题上，整个项目的完整结构由副官了然于胸」。
要落地，先有人把它裂成 todo 行；判据写在行里。

## 名与资格

**这一席叫副官。** 名字归人裁（2026-10-02 定）；「副」字自带备用与辅佐两层——正主（主力模型）缺模态时它顶上，
正主自己能看时它退回幕僚位，与「原则上备用」同构。

**任职资格是硬的：副官必须是多模态模型。** 不是偏好、不是推荐配置——非多模态模型不得任副官，
换模型时先验这一条再上岗。副官的全部价值就在「看得见」；看不见的副官是占着编制的空椅子。

## 分档的轴：模态覆盖，不是价格

主力模型不是多模态，「要看」的活它做不了——截图、图的 alt 与版面、首屏长得对不对、GUI 里那个选项长什么样。
这些活不是「更便宜的模型能干」，是「另一个模态的模型才能干」。分席按这条轴：

| 席 | 模型 | 领什么活 | 永不领 |
|---|---|---|---|
| **推理席**（正主） | 非多模态主力（现 GLM-5.3） | 写卡、建造、条文、审查签字、对账 | 一切「看」的活 |
| **副官** | **必须多模态**（自定义，都能通） | 截图巡查、图 alt 与版面核对、首屏/图形态验收、GUI 探查 | 写卡、签字、动条文 |

**判定进命令的仍然优先进命令**（`check-verdict.sh` 先例）——命令连模态都不要。
副官只在「命令查不了形状」的地方上场：alt 与实图对不对、版面乱不乱、GUI 那个选项在哪。

## 副官常驻：双职责建制（人 2026-10-02 第二裁，取代「原则上备用」）

**副官常驻，不再备用。** 两个职责：

1. **代看**（多模态，任职资格不变）：截图巡查、图 alt 与版面核对、首屏/图形态验收、GUI 探查——按格点名，不按刀。
2. **项目状态的活索引**：上下文中维护项目的整体结构与现态；代理席和规划席**按需访问副官**拿导航，
   主力精力留给规划和解决问题。

**红线（与「状态在磁盘，不在聊天」的共存条件）：副官的胸中丘壑必须从盘上现算，不靠记性。**
它维护的不是记忆，是一张随时能从 `todo.md`/`cmd/`/`SESSION`/`src/`/`queue.md` 重建的活地图——
磁盘是真相，副官是索引。答询三律：

- **带出处**：每一句答（结构、状态、行号）附盘上路径＋行号；答不出出处的，问的那席不采信（同「审查每句话背后要有跑得出来的数」）。
- **带时点**：答案标注读于哪个 `HEAD`/mtime；盘面已过时点，先重扫再答。
- **不落结论**：副官答「在哪、是什么、什么状态」，不答「过不过、该不该」——导航不是判据，感官不是法官。

若靠记性而非现算，副官就成了 Astra 笔记的翻版：模型私有记忆、不在 git、人 diff 不出——第二真相。
备用原则的退出口换一种方式保留：**地图腐化（答旧盘）即失格，重建即复位**。

## 架构边界：AutoClaw 的工具层模态与「盲法官读证词」

AutoClaw 的主驱动（5.3）本身不看不听：OCR、图像理解、语音转录全是工具层专项模型（autoglm 系）出的**文本转述**，
主模型收到的是证词不是画面。这个架构保证得了**证据采集**（可落盘、可 grep 的文本），保证不了主模型对视觉结论的
**最终担保**——OCR 把「已结」读成「己结」，推理席察觉不到；「版面乱不乱」只能采信转述。
所以副官的证据规矩：**凡涉「长得对不对」的验收格，证据必须带原始截图存档（`.tmp/`），不只交文字转述**——
留给将来的人或更强的眼睛复核。推理席是盲法官，副官的证词要能被重审。

## 现成的实证（都在本桌账上）

- 巡查手用 `desktop_agent` 截图＋OCR 读过屏（patrol-2/7/9/10…），那是副官的活，干得动；
- 6.24 的 readme 帽子刀，验收 11 格全是 grep/行号——恰好一格「看」的都没有；但 `release.md` §0 的 90 分档写明
  「读者在第一屏之内看见①②③」，那一格机器查不了，只能副官判；
- 框架图 alt 与实图的一致性（`3.3` 出图、`6.2`/`6.3` 行记的首页图账）是常驻的副官活。

## 形状（草案）

- **代理席派单时按格点名副官**（代看类），不按刀选席——派单粒度到「格」或「步」。
- **访问协议**：代理席/规划席 → 副官的问询通道（同一 AutoClaw 会话或定向子代理）；答询照上节三律。
  这正是 `later.md` 附二那句「用查询代替读全文」从一刀之内的流程，推广到**整个项目结构**：两席不再各自重读全树。
- 副官的产出落 `.tmp/`（证据、形态描述＋原始截图、答询快照），**不落结论**；「过/不过」仍由卡上判据＋推理席（或命令）定。
- 绑定在应用侧（Saved Agent 自定义模型），代理席不发明绑定，只选用；**上岗先验多模态资格**；常驻后进权限表行（只读＋`.tmp/`）。

## 下限表的增补

上节角色下限表中，副官一行随之更新：**必须多模态（任职资格）＋常驻（答询能力要求足够长上下文与稳定会话）**；
巡查一行可并入副官（读盘巡查本就是重建地图的例行动作）。

## 判据候选（裂行时定死）

- 副官验收格（如「首屏之内可见①②③」）有落盘证据 ≥1 份/刀（截图进 `.tmp/`，不只转述）；
- 推理席的刀内不出现「看图」类验收（有则说明路由漏了）；
- 任副官者的模型具备多模态能力（任职资格的验法：给它一张带文字的图，答对才上岗）；
- `run.sh` 本数不涨；副官不进权限表常设行（备用原则的机械验法）。

## 每个角色都能独立配模型——那范式管什么（2026-10-02 人问）

**管下限，不管型号。** 应用侧（Saved Agent 自定义模型）确实每个角色都能独立绑；但角色条文（`roles.md`）定义的是
写权限＋失败时许做什么，模型绑定是实现层——**绑定可换，职责的最低模型要求不可破**。下限表（草案，裂行时定死）：

| 角色 | 模型下限 | 依据 |
|---|---|---|
| 写卡 `write-cmd` | **重**——构思、判据可执行性、预期值都在这只手上（本桌两回卡面预期错的账在这） | `hooks.md` §2 分工表 |
| 实现 `builder` | **浮动，沿档位轴**——轻刀可降，动 `src/` 条文/写检查脚本恒重 | 档位字段现成 |
| 契约测试 | 写口径**重**；跑格进**命令层**（零模型优先，`check-verdict.sh` 先例） | 同上 |
| 审查 `review` | **恒重**——换弱模型＝松判据 | 三爪同族 |
| 领班收口 | **重**——对账、代抄、呈报判断 | |
| 代理席 | **重**——断点判断是它的全部价值 | |
| 副官 | **必须多模态**（已立，任职资格） | 人 2026-10-02 |
| 巡查 | **无下限**——命令、便宜模型、副官皆可 | |

**换绑纪律（红线）**：下限之内的浮动，代理席可调；**触碰下限——给审查降档、给副官上非多模态、给写卡换轻模型——
是「松判据」的另一种形状，归人那一爪**。配置面不许变成绕闸的后门。
绑定表是部署配置：住应用侧，不进 `src/`，不立第二真相。

**演进路径**：全重起步 → 按角色影子验证（本桌 5/5 回放是先例）→ 逐角色降档——地板永不动。

## 实现面与验证坑（2026-10-02 人问「容易实现么」）

**机械上容易：三个实现面，两个是现成功能，一个是 UI 配置活。**

| 面 | 角色 | 怎么绑 | 证据 | 难度 |
|---|---|---|---|---|
| Claude Code 实现席内 | builder / contract-tester / review | `.claude/agents/*.md` 前言自带 `model` 字段，一只手一行 | `hooks.md` 附表：「`.claude/agents/*.md`，带 `tools` / `model`」 | 分钟级 |
| 跨席的 app 会话 | 规划席 / 实现席 / 代理席 | 各 app 开会话时自选模型——本来就各归各 app | 席位定义本身 | 零（已在用） |
| AutoClaw 内 | 审查 / 副官 / 定时巡查 | Saved Agent 在应用侧绑自定义模型（人 2026-10-02：「都能通」）；代理席只按 agentId 派单 | `manage_saved_agent` 接口无模型字段——绑定在 UI，不在接口 | UI 配置活 |

**三个真坑，都不在「绑不上」：**

1. **身份不透明——验不了绑的是谁。** 会话内部读不到自己跑在哪个模型上（本桌实测：`get_runtime_status` 返回无已落账请求事实）。
   下限失守没有机械闸，只能行为探针：副官上岗先过看图资格测（已立）；其余角色靠影子一致率抽检。
2. **下限的执行是纪律不是机制。** 换绑在 app UI 里，有 UI 权限的手都能点。红线（触下限＝松判据归人）写进条文，
   巡查抽查只能事后——这一格机械验不了，照写不吹。
3. **绑定表不能进库。** app 侧改了绑定仓库不会知道，写进来必腐化成第二真相。进库的只有下限；
   「哪个角色现在跑在哪个模型上」作为副官答询的一格——从 app 侧现读，作证词不作真相。

**落地建议：先三档，不 N 模型。** 每角色一个不同模型会把交接面拉爆（七类失败里交接正是没闸的地方）；
重 / 轻 / 多模态三档已覆盖下限表全部角色，角色间差异用绑定表达、不用模型数量表达。

## 副官落位（人 2026-10-02 第三裁：随代理席同模型）

人原话：「anyway，副官是你自己用，就在你的模型下就行」——**副官随代理席跑，不单独绑多模态**。
由此带来的职责分层（照实写）：

- **活索引职责即刻上岗**（不依赖模态）：答询三律、盘上现算、项目状态导航——今晚巡查读屏已是事实上的代看，
  只是走 OCR 转述而非原生视觉。
- **代看职责降级为「工具层模态」**：截图→OCR/图像理解工具（autoglm 系）出证词，推理席读证词不读像素。
  边界照旧：「长得对不对」类验收的证据必须带原始截图存档，供未来重审。
- **任职资格条款由「硬性」转为「待未来」**：主驱动原生多模态之日，即资格回归之时——条款不删，挂起。

## 宿主现状与工具需求（人 2026-10-02 表达，需求记录非裁定）

人对当前管理方式不满：「我希望能有一个coding工具，针对不同角色分配不同模型，而且是以清晰可管理的方式运作，
不是像现在这样模模糊糊的」。同轮比较：Claude Code「每个角色都有一个固定的文档说明」方便很多。

快查（2026-10-02，公开场）：**Codex 的 `.codex/agents/*.toml` 是 TOML 形 per-agent 配置**（可指定模型），
Claude Code 的 `.claude/agents/*.md` 前言带 `model` 字段——两家都是文件系统原生，git 可管。
AutoClaw 的差距在目录接口无模型字段、绑定住 UI、无单一 config 全景——本桌实测三坑之首。

**这与 Dossier 的答案同构**：`later.md` 附三§六——不是搬家，是编译器多一个目标（`.mirror/` 加 `.codex/` 兄弟，
角色文件 md→TOML，`check-mirror`/`check-role` 多认一个落点）。宿主可换，范式带走；
`src/` 是不折旧层，`.mirror/` 本来就是折旧层。

## 错法

错在「看」的边界会漂：文本 diff 里混一段 alt 叙述，推理席读着也对——但「对不对」和「长得对不对」是两回事，
前者 grep，后者只有副官。宁可多派一次副官，也别让推理席拿文字猜版面。
反向的错法有二：主力模型已能看、副官还在常态在岗——备用原则失守，补丁长成了编制；
副官位上坐了个非多模态模型——资格失守，空椅子占了编制。
