## 三问答了什么

### 第二版那张三支表的第三支写错了

第二版列过三支，第三支写的是：「两边都轻档 → 七份一份都不落。本刀退卡，`2.6a` 那一行改写成『档位已答，不落文件』。」

人落的正是这一支，但同一句里给了理由：完成 `2.6` 整体之后才会有重档的选项。这句话把两件事分开了：

- **档位**说的是现在派不派手。
- **角色文件在不在盘上**说的是有没有东西可派。

第二版把这两件揉成一件，所以才推出退卡。是那一支写错了，不是人的答案和卡冲突。

盘上的证据，三处，都能现核：

- `roles.md` 第 183 行，轻档「角色文件」那一格：「职责仍按上表分，**可**不落成 agent 文件」。是**可**，许可式。
- `claude-code.md` 第 43 行，同一格：「职责仍按 `roles.md`，不落 agent」。禁止式。
- `roles.md` 第 164 行另有一句，触发条件根本不是档位：「旧桌没有义务补文件；新桌按上表分职责，**核一脏就把文件落下来**。」

两份都在 `docs_meta/src/`，都是源码，同一格两个口径。哪一份是正身，`claude-code.md` 自己写了：第 3 行「职责表见 `roles.md`。本文只写这个 harness 怎么落」，第 32–33 行「出处是 `roles.md` 那张层 × 手的表，角色文件只是把那张表兑现成 frontmatter，不是第二处定义」。

所以正身是「可不落」。轻档下落文件不违反出处。**本刀不退卡，六件全部保留。**

第二版那一支，和 `todo.md` `2.6a` 行里那句「轻档就是零角色文件」，抄的都是紧的那一版。行里那一句要改，改法写在第 6 件。

### 为什么轻档仍然要落文件——这是读法，不是裁

人只落了「轻档」和那半句理由。下面这一段是这只手接的，写在这里供人核，不当判据用。

`roles.md` 第 174 行写着，翻转点是「桌上长出能机械变红的东西的那一天」。

`2.6a` 落的七份文件本身没有哨兵。正文里写歪了、把桌的合同抄进去了，不会有任何东西变红。`2.6b` 装的正是那条哨兵：源码 ↔ harness 的对账线。

所以顺序是这样的：`2.6a` 把文件落到盘上，`2.6b` 让它们能机械变红；两刀都完了，角色文件才是「能机械变红的东西」，那时候派手才买得到保护。在那之前派，等于多开几个没有闸的交接面。

这和 `roles.md` 第 190 行对得上：完整角色流水线在改共享离散核时值回票价，在跑一个 `.tmp` 探针时是税。

**推论要写进每一份文件**：七份落在盘上是**待启用**，不是已启用。启用是人另外一个动作，不在本刀里。

### 问三：留 `Bash`，射程写死在 `docs_meta/tests/`

人落的是第二版那两条路里的乙，并且加了一条第二版没有的限制：射程限在 `tests` 文件夹内。人同时点明这一条严格不了，只能靠说明维护。

本刀照办：

- `review.md` 的 `tools` 白名单保留 `Bash`。不给 `Write`，不给 `Edit`。
- 正文写死 `Bash` 的射程：只在 `docs_meta/tests/` 下跑，只跑不改。
- 正文同一处写明这一条没有哨兵，不许吹成硬隔离。

**软在哪要说清**：`tools` 是工具级白名单，它答得了「这只手有没有 `Bash`」，答不了「这只手的 `Bash` 只许跑哪个目录」。所以射程那一句和四份 agent 的路径限制是同一种东西——给手读的约束，不是机械隔离。

人另外问了有没有办法。第三版摆了三条路，人 2026-09-12 落了「丙可以」。

**丙是什么**：不拦，改成一定会红。派审查之前取一次工作树指纹，那一页交回来之后再取一次，不一致就红。取法是现成的壳命令——`git status --porcelain` 加未跟踪文件的哈希，两次比对。三条理由见「缺口照记」那一条。

**丙的落点，这只手裁一句，理由写明**：新开 `2.6c`，不塞进 `2.6b`。

`2.6b` 那一行断言的是「`docs_meta/src/` 每条禁令在 harness 里有没有落点」，对象是禁令清单。丙断言的是「审查那只手这一趟有没有改盘」，对象是一次调用的前后状态。两个对象不同，揉进一行就是让那一行变胖，而 `workflow.md` 那条是「TODO 只能长，不能变胖」。所以走「长」那一向，不走「胖」那一向。

**本刀仍然不装丙。** 本刀不带哨兵是人 2026-09-12 认过的，顺手装一条就是并刀。第 6 件只把 `2.6c` 那一行记进账，不写脚本、不跑红。

裁错了，审查那一页可以驳。

## 现状：开干之前会踩的几个坑

**一 `.claude/` 现在只有 `settings.json`，里面和角色无关。** 十一条 `permissions.allow` 全是上一轮画图留下的，`py -3`、`cairosvg`、`compare_icons.py` 之类。本刀不碰它。

**二 母本没有根 `src/` / `tests/`。** `claude-code.md` 那张表写的是桌的路径，落进母本要按 `directory.md`「`docs/` 内部怎么切」现算成 `docs_meta/src/` 和 `docs_meta/tests/`。这是转译，不是抄，所以会有损有增，方向只准源码 → 产物。

**三 `.claude/` 不在 `.gitignore` 里。** 落下去当场入库，也当场对本会话生效。本刀和之前每一刀不一样的地方就在这里：产物会立刻改变这只手自己的权限面。所以验收要在落完之后真跑一次，不能只看文件在不在。

**四 工具面管不了路径，这是本刀最重要的一条。** `tools` 是工具级白名单，写得下「这只手有没有 Write」，写不下「这只手只许写 `SESSION.md`」。`design/ch2.md` 2.3 节早就记过这一条（当材料读）：「只写哪里」在工具面本来就做不到。

推论要写死在每一份角色文件里：正文那句「只许动哪些路径」不是机械隔离，是给手读的约束；工具面只兑现「有没有这只手」。两件分开写，不许把正文那句冒充成隔离。

**五 `review` 那一份兑现得最多，但只硬了一半。** 不给 `Write`、不给 `Edit`，这半条是硬的；白名单里留着 `Bash`，而 `Bash` 能改盘。人 2026-09-12 落的是留，并且把射程限在 `docs_meta/tests/`，那一句是说明，不是拦截。

其余六份拿的是同一套读写工具，路径限制只活在正文里，写歪了不会有任何东西变红。这正是 `2.6b` 存在的理由，也是本刀「不带哨兵」那句话的具体内容。

**六 `skills/` 那三份不是角色。** `claude-code.md` 写着调度 skill 不是角色，`one-slice` 只规定 `roles.md` 那条顺序，`example-report` 是公式写法。它们不配 `tools` 白名单，别按 agent 的形状写。

**七 `CLAUDE.md` 是转译层，不作断言落点。** 角色文件里要引判据，引 `roles.md`，不引 `CLAUDE.md`（`claude-code.md` 第 28–30 行）。

| `grep 'docs_meta/tests' .claude/agents/review.md` | ≥ 1 处 | 一处都没有就是 `Bash` 的射程没写进正文 |

`.claude/` 不在九本里任何一本的射程里，所以九本的读数本来就不该动。这句话同时是一条缺口：本刀交的七份文件没有任何一本检查看得见。

**冒烟证的是跑得动，不是判得对。** 假人默认档只会回「是」，只推进不判定；审卡要第二个会话，一趟跑不出来。这两格照 `4.8` 写成缺口，不许算成过。

## 独立审查那一格为什么是「派」

`roles.md` 写的是「动了 `src/` 就派」。本刀不动 `docs_meta/src/`，按字面可以写「免」。这里仍然派，两个理由：

一是本刀交的东西当场改变这只手自己的权限面，落完之后这只手就在自己写的隔离里跑。形式上是自证，和闸一红印那一格同一个毛病，唯一的防线是另一席去读。

二是本刀不带哨兵。`2.6b` 还没开工，七份文件写歪了没有任何东西会红。派一页只读的审查，是这段过渡期里唯一还在的那一格。

派审查是收紧，不是放宽，所以不另发一次授权。
