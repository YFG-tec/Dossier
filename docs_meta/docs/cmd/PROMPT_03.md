# PROMPT_03 — 合同层改成正向标定

2026-09-08 ｜ 对应 `../SESSION.md` ｜ TODO 第 1 行（【优先】那条）

> 人提的。起点是对「占位必须写成问句」的质疑——能不能放宽成「尚未确定」这类提法。
> 议下来的结论不是放宽，是**翻方向**。原委留底在 `PROMPT_02.md` 拍板第 3 条。

## 可贴指令（以下整段可直接粘进实现席）

把合同层的授权规则从**标不确定**翻成**标确定**。

### 为什么（写进文档时要保留这个「为什么」）

| | 现在（标不确定） | 反向（标确定） |
|---|---|---|
| 默认 | 可引，除非标了 | **不可引**，除非标了 |
| 标记丢了 | 沉默升格 —— **失效朝危险倒** | 降成参考 —— **失效朝安全倒** |
| 谁吃亏 | 下游：拿参考当合同做了一刀 | 上游：该标没标，东西没人引，很快被发现 |

**改的不是宽严，是失效方向。** 标记一定会丢——上下文压缩会丢、摘录会丢、
复制粘贴会丢、手滑改一行也会丢。设计时就该假定它会丢，然后问丢了往哪边倒。

顺带解决三个已知的坑，不是解决一个：

- **摘录鲁棒性**：不再需要。授权不在被引的那句话里，在**源头有没有标**。摘录摘不走一个不在句子里的东西。
- **节 vs 句的粒度**：不再需要。标在哪一条，哪一条可引。
- **混态节**：不存在。§6 里升一条标一条，节标题的态降级成摘要，不再承重。

### 两个维度要拆开

现在的三态把两件事塞进了一个标记：

```
权威（能不能引）     二元：已定 / 不已定      ← 由标记决定，机械可查
进度（想到哪一步）   三元：验证过 / 没验证 / 没答案   ← 正文叙述，不承重
```

草案和占位的区别一点不丢，只是**不再管授权**。
「其余一律参考」不等于没用：**参考喂建议，已定喂指令**——
规划席读参考提建议，卡片只许引已定。这和「审查有发言权没否决权」「builder 有提议权没采纳权」
「领班有升格建议权没落笔权」是同一条骨架的第四份。

### 交什么

1. **`workflow.md` 开桌那一节的三态**改写成正向标定：
   默认不可引；`【定】` **行内**标记；权威二元 / 进度三元拆开；
   索引 `grep -n '【定】'` 现算、**不存盘**；代价照写（见「不交什么」下面那条）。
2. **`workflow.md` 收口那一段**：升格 = 在那一行前面加一个 `【定】`，
   是个**能 diff 出来的动作**，不再只是「一道手续」。
3. **`paradigm.md` 页首三态说明** 改写；**§5 那段必须同步**——
   它现在明写「这正是『占位必须写成问句』那条机械保险的用法：展开不是答案」，
   新机制下理由换成**「`open.md` 里像答案的句子不作数，因为它没标」**。
   不同步就是合同自相矛盾，正是 §5 自己点名的那种「静默降档」。
4. **标样板，只标三处**：§5、§10 的决议、以及 §6 里那一条
   （「能机检的是词的共现，不是意思」——上一刀的升格建议在这里落地）。
   收口时把**其余各节的候选清单**列出来呈人，供下一刀批量。
5. **新增 `.tmp/check-mark.sh`**：三条，见下「验收」。

写到的路径：`docs_meta/src/workflow.md`、`docs_meta/docs/design/paradigm.md`、
`.tmp/check-mark.sh`。**只此三处。**

### 不交什么

- **不全量标记。** 标记 = 授权 = 人的权力，代理不自己决定哪条是已定。
  本刀只交**样板 + 候选清单**，批量落标是下一刀。
- **不另立「已定清单」文件。** 那是 `directory.md` 明禁的第二真相——
  清单和正文迟早不一致，且不一致时没人知道该信哪个。正向**行内**标记，索引现算。
- **不删「占位必须写成问句」。** 它**降成写作建议**，理由从「机械保险」换成
  「逼作者说清不知道什么」。**性质变了理由必须跟着换**，
  否则下一个人会发现它不保任何险、当税删掉——那一次删得对。
- **不装第四条检查（引用授权比对）。** 那条最强，但现在库里一处新格式引用都没有，
  装上就是恒真式。**没见过红的检查不算检查**，恒真式连红的机会都没有。留给全量标记那一刀。
- 不动 `open.md` 结构（「已收」列表照旧）、不动 `directory.md` 权限表
  （发现冲突只报告不改）、不动图不重渲。
- commit / push —— 除非人本回合点名。

### 禁令

- **除卡片点名的三处，不给任何条目加 `【定】`。** 越权标记 = 代理自己发了授权。
- 标记字符串固定为 `【定】`，不发明第二种；不新增其他概念名词。
- 不在 `docs/design/` 下新增文件。
- 不勾 `todo.md`。

### 验收

```bash
bash .tmp/check-mark.sh 2>&1 | tee .tmp/check-mark.log
```

三条，都要能红：

- **A 格式**：`【定】` 只许出现在行首，或紧跟 `- ` / `| ` 之后。
  格式散了 `grep` 就会漏，而这套机制整个押在 `grep` 上。
- **B 越权**：`【定】` 只许出现在 `paradigm.md` 的 §5 / §6 / §10 三节内，且总数 ≤ 5。
  本刀交的是样板，不是全量。这条防的是实现的手顺势多标几条。
- **C 同步**：`workflow.md` 三态那一节须同时含「默认不可引」和「`【定】`」；
  且「问句」附近必须出现「写作建议」——防止只改了机制、忘了给旧规矩换性质。

**先让它红一次再改文档。** 顺序写进对账。

### 独立审查

**派。** 上一刀写明「豁免不再顺延」，而本刀改的是合同层的核心机制。
人拍过「纯文档项目一个角色 hold 住」——那一条说的是**规划席 / 实现席不必分**，
审查是零写权限的第三只手，不在那条豁免范围内，成本也只有一个来回。

审查要回答两条，都不问做法：

1. **新机制和已定条款有没有打架**——尤其 §3 的不变量、§5 的两份文件分工。
2. **样板标记有没有越权**——标出来的那几条，是不是真的是人拍过板的，
   而不是实现的手觉得「这句挺确定的」。

## 这一刀实际发生了什么

**红了三轮，其中两轮是审查逼出来的。**

1. 改文档前：A 的「一处都没有」+ C 四条全红，点名 `workflow.md:34`。
2. 改完绿了 → **审查抓到 `workflow.md:185`**「第一刀要碰的那一节必须已定」，
   粒度和授权条件两处都和本刀新写的 `:99` 相反。**本刀新造的自相矛盾**，
   而检查 C 只扫「开桌」那一节，扫不到全程图。收紧 C4（全文扫）→ 红 → 修 → 绿。
3. 审查还指出 **B 从没红过**。于是故意在 §1 多标一处跑一次（`§1 第 25 行 FAIL`），
   再还原复验。**按本仓库自己的规矩，这一步不做 B 就不算检查。**

**派审查这一步值回票价，而且值在意料之外的地方。** 我以为它会去审新机制对不对；
它真正抓到的是**执行的手在卡片缝隙里做的三个决定**——挑哪句标、新立什么判定口径、
哪条检查从没失败过。这三样单手作业永远自查不出来，因为做的时候都觉得理所当然。
