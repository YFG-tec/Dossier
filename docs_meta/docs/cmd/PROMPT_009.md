## 卡改过六轮，理由记下来

卡在闸一之前改是合法的，冻结的时点是闸一，红印还没落。
但六轮都要留痕，不然下一个人看不懂射程为什么和行原文不一样。

### 第一版：判据落错了轴

第一版写的是「分席买的是两只手写两棵树（`src/` / `tests/`），母本没有第二棵」。

规划席闸一审卡指出一处措辞过满。核下去发现底下还有一层，审阅没碰到：**「席」和「手」不是同一根轴。**

| | 分的是谁 | 「两棵树」指哪两棵 |
|---|---|---|
| 席 | 规划席 / 实现席 | `docs/` vs `src/` |
| 手 | builder / tester / review | `src/` vs `tests/` |

§9 要改的那一行写的是「单会话，不强制两席」，是席轴。
而 `PROMPT_001` 给的理由是「两只手写两棵树」，是手轴。它自己的措辞就是「手」。

换回席轴看，母本恰恰有那两棵树：`docs_meta/docs/` 和 `docs_meta/src/`，§5 那张对应表列着。
所以「买不到隔离」在席轴上不成立。拿手轴的理由解释席轴的事，改措辞救不回来。

### 第二版：把档位拧到了错的那根轴上

第二版接受了「分席是档位选择」，于是打算放松 `roles.md` 那句「两席必须是两个会话」。**这一步是错的。**

人 2026-09-09 补了四句，把轴分清了。原话逐字：

> claude code 和cursor的主分工是，claude code 负责执行从领班开始的所有手，也就是'尚书省'，cursor是人的主要参谋，这么分的角色

> 再往下，claude code以下的角色视情况可以多分或者少分

> 再说句实在的，你看到的审核意见基本是cursor给的

> 所以Agent一直都是两个角色哦

连同前两句一起读，五点定死：

1. 席是常设的两个，不是档位选项。
2. 档位拧的是**领班以下那几只手**，视情况多分或少分。
3. 判据是有没有「编译运行」，原话：

   > 对，针对不同的开发场景，可以选择重度分离，对于大型项目十分关键，轻度可分可部分，快速完成即可，或者说是咱们这种没有'编译运行'的情况

4. 轻档是**可以不分**，也可以只分一部分。原话：

   > 抱歉我的错别字，可以不分

5. 母本一直是两席，本刀读到的那份审卡就是另一席出的。

所以第二版要放松的那一句不许动，第三版反过来收：档位表那一格才是错的。
`PROMPT_001` 那一裁仍然没被推翻——「分席只换来往返」讲的是手，一个字不动。

### 第三版：漏了两席的「为什么」

第三版把席定成了常设，但没写清为什么必须两个。人 2026-09-09 当场补上。原话逐字：

> 应该是我的问题，我一直没有提 Dossier 的最基础要求就是双Agent，1个负责出主意，审核，另一个主要负责执行

> 前者要求能快速出结果，出结论，后者要保证产出稳定，准确

> 另外，一直禁止cursor写src test，只会动card todo design之类的

两点：

1. **双 Agent 是 Dossier 的最基础要求**，不是档位、也不是某一档的推论。
   根 `readme.md` 写着「一刀，两席」和「开两个会话」，所以这一条盘上早就有；
   缺的是它的理由。`readme.md` 只写「能力差异加上权限差异」，没写差异买的是什么。
   买的是两条方向相反的品质要求：参谋席要**快**，执行席要**稳准**。
   这两句要补进 `roles.md` `## 两席`，见交什么第 1 件。
2. **规划席一直禁写 `src/` / `tests/`**，只动卡片、TODO、`design/` 这一类。
   `cursor.md` 现在写的是「要用户点名才动」，比这松。本刀**不改它**，只报，见现状第 11 条。

### 第四版：把「领班写卡」判成了偏离

第四版把「写卡那只手坐错席」列成 §9 第一条真偏离，理由是写卡该在规划席。**这一条整个撤销。**

| 谁 | 写什么 |
|---|---|
| 领班（实现席） | **卡本体** `cmd/PROMPT_*.md`。唯一有这个权限的手 |
| 参谋（规划席） | **review**，落 `SESSION.md` 横线以下。不改卡本体 |

## 现状

实现会踩的坑，写在开干之前。

### 1. 两根轴，档位只拧一根

| 轴 | 分的是谁 | 是不是档位 |
|---|---|---|
| 席 | 规划席（Cursor，人的参谋）/ 实现席（Claude Code，尚书省） | **不是。常设两席、两个会话** |
| 手 | 领班以下：`builder` / `contract-tester` / `review` | **是。视情况多分或少分** |

判据「有没有编译运行」只管手那一根。它决定要不要把手拆开落成 agent 文件，不决定席。

**席为什么不是档位**：双 Agent 是 Dossier 的最基础要求（人 2026-09-09）。
两席各背一条品质要求，方向相反：参谋席要快出结果、快出结论；执行席要产出稳定、准确。
一只手同时背这两条，等于一条都不背。所以席不进档位表。

### 2. 母本两席俱在，§9 那一行是事实错误

分工盘上早写着，不是今天新定的：

| 出处 | 写的 |
|---|---|
| `cursor.md` 第 6 行 | Cursor 默认坐规划席：读合同、写卡、对账、拒超售 |
| `claude-code.md` 第 6 行 | Claude Code 默认坐实现席，主会话当领班 |
| `roles.md` 「和目录的对应」那一段 | `docs/cmd` 和 `SESSION` 归 `write-cmd` / `spec-guard` / `cursor-desk` |

Cursor 和 Claude Code 是两个会话。所以 `roles.md` 那句「两席必须是两个会话」母本**没有违反**。

§9 现行那一行写「单会话，不强制两席」。对母本不只是理由错，事实也错。
它大概是规划席还没进环之前写下的，此后没跟着动。

`2.5` 要拿这一行去定「派不派、几席」。照现在这句读，会得出母本没分席的结论，正好反了。

### 3. `roles.md` 自己打架，而裁法和第二版相反

| 出处 | 说的 | 第三版怎么裁 |
|---|---|---|
| `## 两席` 末段 | 「两席必须是两个会话」这一条不能换 | **对。一个字不动** |
| 档位表「会话」栏轻档一格 | 规划+实现可同一会话 | **错。这一格要改** |
| 档位表下「读法」第一条 | 同一窗口又写卡又改核又改测，是没守原则，不是轻档 | **对。保留，只补一句指回两席** |

轻档减的是实现席内部的手，不是席。那一格把手的宽松写成了席的宽松。

### 4. 那条绊线被绕过两次，没有任何东西红过

§9 现行那一行末句写着「一旦开始改 `docs_meta/src/*.md` 的实质条款，就该分席」。

`PROMPT_007`（`2.1`）和 `PROMPT_008`（`2.7`）都改了 `workflow.md` 的实质条款。
两张卡都在抬头写「这是已知偏离」。

规矩被绕过两次仍挂在那里，它就已经不是规矩了。
这是母本自己那条「静默降档」的现成实例（§5：没有任何东西会变红）。

而现在看清了：那两刀根本没有违反两席，写在卡上的「已知偏离」认错了对象。

### 5. 真偏离是两条，都在席内，不在席间

原则在 `roles.md`「没做这么严，原则上仍要分开」。照实核一遍，母本弯了两条：

- **写卡的手接着改核。** 领班写卡是设计，不是偏离（见上面第四版那一节）。
  弯的是下一步：轻档里领班兼着 `builder`，所以同一只手写完卡接着落实现。
  这踩中六条原则第一条。**要写清弯的是哪一半**——写卡的席没错，接着改核那一步才是。
- **改核的手同时动判据。** `2.7` 那一刀既写 `workflow.md`，又给 `check-link.sh` 加了 D 段。

**审查那只手不是零写权限，本刀记成档位安排，不记偏离。**
审查交参谋席兼办，而参谋席要写 `docs/`；`roles.md` 那张表给审查的写路径是「无」。
但人 2026-09-09 裁明「参谋负责 review」是两席的分工本身，不是省下来的一只手。
所以它进 §5 那段讲席的正文，不进 §9。闸一若认为它仍该记成偏离，那一条加回 §9 即可，另两处不受影响。

这里有一处母本反而比通则严，一起记：审查那一页是参谋席自己落盘的，不经领班转述。
`roles.md` 说领班转述是「最后一个没堵的口子」，母本这里没有这个口子。

代偿是现成的，只是从没写全：

| 弯了哪条 | 代偿 |
|---|---|
| 写卡的手接着改核 | 写完停在闸一；卡交参谋席 review；**两边共识才推进**；人在闸一裁 |
| 同时动判据 | 判据只许收紧；松判据是人的那一爪；照实报告 |

残余风险照抄 `PROMPT_001` 记的那条：卡片自相矛盾时，判断该不该退卡的是有利害的那只手。

**第一条的代价，本刀自己就是现成实例，要写进 §9。**
这张卡改了六轮，每一轮都是人或参谋席补进一段实现席看不到的现场：谁坐哪一席、手可以多分少分、
审卡出自另一席、双 Agent 是地基、规划席禁写 `src/`、写卡权限只在领班而 review 在参谋。
实现席这只手只看得见自己那半张桌子，却在写整张桌子的规矩。

**这不是「写卡该换一席」，恰恰是共识那一条为什么必须在。**
领班写得出卡，写不出自己看不见的那一半；补上那一半的是参谋席的 review 和人。
六轮改稿就是这套民主协商在跑，不是它失灵。

### 6. 翻转条件必须是看得见的动作

判据是「有没有编译运行」，所以翻转点是母本长出能机械变红的东西。

例如把 `.tmp/` 那几本检查固定进 `test/`。`PROMPT_007` 提过这条路，人 2026-09-09 松管 `.tmp/` 时也说了「稳定的单测另固定到 `test/`」。

那一天到了，重判的是**手**要不要拆开，不是席要不要分。席那时也还是两个。

### 7. 档位那半边仍然不许自己落

`todo.md` 行末写着「建议升格、人落槌」。§4 的三个占位挂在节标题的态上。
§5「母本停用标记」那张表写死：把态从占位改成已定，是降低立案门槛，仍是人的那一爪。

今天这几裁没有改变这一条。裁的是判据的实质，不是谁去翻 §4 的态。

### 8. 判据只许有一个家

档位的正文在 `roles.md` `## 档位`。
`claude-code.md` 那张轻 / 重档表讲的是落哪些文件，末尾已经指回 `roles.md`。

新判据只落 `roles.md` 一处。`claude-code.md` 和 `cursor.md` 一个字不动，两处都写就是第二真相。

### 9. `check-cmd.sh` A 段会扫 `paradigm.md` 和 `roles.md`

一行里既出现 `cmd` 或 `PROMPT`、又出现「覆盖」二字，且同行没有「只增」「新增」，当场红。

本刀要在这两份里写卡名，那几行不许出现「覆盖」。

### 10. `todo.md` 第 2 章章首那句话是假的

它写着「本章一张卡都还没写，所以没有任何东西被指错」。那是重排当天的现场判断，如今 `2.1`、`2.7` 两张卡都在。

前两刀报过两次，两次都因为不在许可面里而搁下。本刀点名了 `todo.md`，这次写进来。

### 11. 一处写权限对不上，本刀只报不改

人 2026-09-09：规划席一直禁写 `src/` / `tests/`，只动卡片、TODO、`design/` 这一类。

盘上三处比这松，都写成「点名就能开」：

### 12. 卡本体谁写：桌和母本选了不同的默认，不是打架

人 2026-09-09 裁：母本这边卡本体只有领班写得，参谋只在 `SESSION.md` 里 review。

盘上两处写的是反的：

| 出处 | 写的 |
|---|---|
| `cursor.md` `cursor-desk` 那节 | 规划席「写卡按 `write-cmd` 的口径：**新增** `PROMPT_xx.md`」 |
| `roles.md` 「和目录的对应」 | `docs/cmd + SESSION` ← `write-cmd` / `spec-guard` / `cursor-desk` |

**这两处不是错的。** 它们是从三张桌提取来的：桌上确实是规划席写卡。母本反过来。
人 2026-09-09 点出了这一层：「其他项目不一定有这个结构设计」。

所以处理办法不是去改 `cursor.md`，是**分层**：

| 层 | 放什么 | 进不进桌 |
