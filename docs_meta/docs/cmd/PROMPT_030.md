### 一、跨盘不兜底，退出码 4

`os.path.relpath` 在 Windows 上跨盘符会抛 `ValueError`（盘上实测：靶子在 `C:\...\Temp`、子模块在 `D:`，当场抛）。

本席判：**抛了就印一行、退出码 4，不铺**。不做「算不出相对路径就填绝对路径」的兜底。

理由两条。一、真实布局撞不到：子模块在宿主树里，宿主根和子模块永远同盘。
二、绝对路径进了宿主树就是机器专属的串，换台机器就假，而且盘上没有一本把关会为它红——
那比当场退出更难查。

代价照写：母本自测时靶子只能挑和仓库同盘的地方。第二句处理的就是这个代价。

### 二、`check-skel.sh` 自造那棵树挪到仓库 `.tmp/` 下

`check-skel.sh` 不给靶子时会 `mktemp -d` 自造一棵树。这台机器上那是 `C:\Users\...\Temp\`，和仓库不同盘，
撞上第一句就当场红——**红得不对，红的是临时目录选在哪儿，不是核坏了**。

本席判：那棵合成树改造在仓库 `.tmp/` 下（`mktemp -d "$PWD/.tmp/skel.XXXXXX"`），跑完照旧 `trap` 清掉。
`.tmp/` 被 `.gitignore` 排掉，盘面看不见；它和仓库永远同盘，换机器也成立。

**这不算在母本上冒烟**（人裁己）。合成树是 `check-skel.sh` 自己造的断言对象，本来就存在，
本刀只挪了它的落点，一个字节都不多写。真正的冒烟仍然只在 `D:\project_init_test`。
