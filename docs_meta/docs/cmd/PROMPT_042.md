## 写卡阶段现算

### 一、矛盾是单边的,修孤家

盘上三处出处,两处一致、一处孤立:`roles.md` write-cmd 行(:45,新增 cmd+覆盖 SESSION)与落点图(:145)一致;`claude-code.md` 目标文件段(:16、:21)把 `spec-guard`、`write-cmd` 都落 `.claude/`(实现席的 harness),与 `roles.md` 相容。**孤立的是 `directory.md`:276 那格裸「只读」**。行上问「改哪处」,答案:改孤家那一份,不动一致的两份。

### 二、取乙案(格内写「由桌自己定」),不取甲案(列头补「默认」)

行上给了两案,择一。「甲」是列头 `实现席(有卡片之后)` 补「默认」——代价:整列八格一起变软,而 `CLAUDE.md` `AGENTS.md` 那格的**只读**是红绿(约定层两席都不许动,人写),不该跟着软。**把一列的软硬一起翻,是放宽判据,不取。**「乙」只给打架那一格开豁免、指向 `roles.md` 已有的「由桌自己定」机制(:16、:35),两处出处从对立变引用。列头动不动是整表读法,归 6.13 家族,货架。

### 三、豁免不吞 reports

那一行捆着 cmd / SESSION / reports 三样。reports 的实现席权限是另一个家族的账(6.10:领班写不了报告;反馈 #9:人列没有 TODO 的格)。冻结文本末尾点名「`reports` 仍只读」,豁免只覆盖写卡那只手碰的两样。

### 四、D 段绊线双向已实测,不是预测

写卡阶段落了仿真 `/d/tmp/042-dsim.sh`:对基线抄件 `/d/tmp/042-base-directory.md` 跑 → RC=1、红案点名「裸只读」;对新文本试改件跑 → RC=0。冻结行对 `check-cmd` A 段绊线(cmd+覆盖须带新增/只增)预检放行——新行自带「新增」二字。判据先量后冻,不拿预测当读数(批五的教训)。

### 五、这病今天对机械检查隐形,绊线是本刀的另一半

实测:改前 `check-cmd` RC=0、整盘 17 本 `ALL PASS`——出处打着架,盘上全绿。这是反馈 #10「绿证明的比看上去少」的标本。只修文本不加绊线,修完不设防,下次有人把格子改回裸「只读」照样全绿。所以本刀交两样:文本修正 + D 段。**加检查是收紧,是测试这只手的本职,不发授权**(check-word 头账同款先例)。

### 六、D 段进现有本,不开新本

`run.sh` 靠 `check-*.sh` glob 收本;D 段长在 `check-cmd.sh` 里,本数保持 17。

## 缺口,照记不补

一、D 段是**词的共现**不是意思:格被改成别的软话(不含「由桌自己定」四字)会红——绊线买的是「不许改回这个形状」,不是「永不打架」。check-cmd 自己头账也写着这条边界。
二、列头「实现席(有卡片之后)」的时序语义本刀不动:写卡发生在「有卡片之后」之前,豁免格把话锚在手(「写卡那只手」)不是锚在时序。整列对齐归 6.13 家族,货架。
三、reports 那一格的三个未决(人列没有 TODO 的格、领班写不了报告、落点图「由规划席写」)各有其行(6.19、6.10),本刀只在格尾写「仍只读」四个字守住现状,不判它们。
四、「三张表、一处声称只有一张」(`claude-code.md`「不是第二处定义」句)是 6.13 的行,人没点名吸收,本刀一字不碰。
五、别桌若把根锁改成引用权限表那一行,本卡的「无产品面同步」前提失效——照「对不上改转译不改出处」处理,不在本刀射程。
