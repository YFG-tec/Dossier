## 自证那个缺口

写卡的是这只手，落地的还是这只手（`paradigm.md` §9 第一条）。
这一刀比前几刀多一层：它改的是「什么东西算判据」本身，而判据正是用来管这只手的。

### 这只手在同一个位置连错三版

**第一版说**：「收紧」这个词全仓只活在合同层，所以 C 段改指必红。
盘上是 `directory.md:88` 独立写着这条方向差。**只数了一本就下了结论。**
连带写进 `SESSION.md` 的那句「人这一裁把方向差连带降成了参考」也是假的，要一并改掉。

**第二版说**：A / B 改指 `workflow.md` 即绿，因为三个词都在。
那三处是转引，不是条文。**拿全文词频当条文存在的证据。**

**第三版说**：代落规格随第 3 件从 `paradigm.md` 搬进新节，「功能换个地方实现」。
盘上规格一直在 `roles.md:109`，`paradigm.md` 那两段都只是指针。**从没搬过家。**
这一错比前两次贵：**它当着人的面进了一次裁决的前提。** 人裁第 6 样「删了就行」，
理由是「我们的功能只不过换个地方实现了而已」——那句话是照这只手写在卡上的假前提说的。
人没判错，是这只手把假前提端上了桌。所以第 6 样重呈一次，并把第三条路（丙）一起摆上去。

三次是同一个形状：**词在不在、指针指着谁，不等于条文在哪。**
这恰好是 `check-paw` B 段自己防的那件事——抽象句吃掉具体禁令，词还在，锚没了。
在给它改指的时候连犯三次它防的错，三次都是回盘上 grep 才发现，不是重读读出来的。

**第三次揭出一条比前两次更硬的教训**：这只手每次都是顺着指针往下读，
读到「见 §5 末段第二档」就当那里是落点，没有一次真的翻到链末。
`paradigm.md:72` → `§5` → `224-6` → `workflow.md` 收口纪律 → `roles.md:109`，四跳。
**指针链上每一跳都可能不是终点，而卡上写的「搬内容」预设了终点在第一跳。**

所以第 2 问被列为审查最重的一问：第 3 件很容易写成「凑够那五个词」而不是写成条文。
机器分不出来，那一问只能人眼答。

### 共同的失效模式仍然是漏

没写的东西没有对照物，机器不会红。本刀已经现场吃过四次：
行里写「`src/` 两处」（实际五处）、「`check-paw` 整本改指」（做不到）、

前两处在九本全绿的时候就已经是错的。

三次里两次是同一节没扫完（第 1 条），一次是改产物忘了源码（第 2 条）。
