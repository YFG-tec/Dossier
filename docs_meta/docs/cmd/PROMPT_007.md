## 独立审查

**派。** 一条理由，不是惯例：

**本刀在拆母本唯一的引用授权机制，而拆除类改动的失败是静默的**——
少写一处读法，合同和实现就矛盾了，六本检查一个都不会红。

审查回答四条，**都不问做法**：

1. **「先抬进 `paradigm.md` 才能引」这道手续，在库里还有没有没跟着改的落点？**
   全仓 `grep`，逐处判定。漏一处就是母本一边说停用、一边还在要求标记。
2. **§3 第 4 条那三样的母本读法，三样是不是都写了？** 少写一样就是静默降档——
   尤其「发授权在母本没有对应动作了」这半句，漏掉会让下一个人以为改节标题的态就是发授权。
3. **`check-mark.sh` 的 C 段，是不是原封不动地活下来了？**
   拿改前改后的 C 段逐字比——A / B 是奉旨删的，C 不是。
   放行词（`grep -v 标` / `grep -v 授权`）少一个、`【定】` 那三个关键词少一个，都算被顺手弄坏。
   **删两段的时候最容易连坐删到第三段，这是唯一要盯的地方。**
4. **`ch2.md` 那段追记和本卡对得上吗？两头都要查。**
   追记里点名的每一节，卡上要有对应的条；卡上消化过的每一节，追记里要点到。
   **只查一头会漏掉「消化了但没记」。** 顺带确认 `ch2.md` 的字数没少——
   它不在任何检查的射程里，删了不会有东西红。
