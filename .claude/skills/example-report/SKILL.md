# example-report · 算例报告写法

**这不是角色，是一段写法。** 角色表在 `docs_meta/src/roles.md`，本文件不复述那张表。
出处是 `docs_meta/src/verify.md`「验证诚信」那一节。两边对不上，改本文件，不改出处。

**母本这张桌现在没有算例。** 母本的产物是文字，不是核，`docs/reports/` 这一层是空的。
所以本文件在母本上暂时没有对象，落下来是给有算例的桌用的。**照记，不假装有。**

## 最低结构

1. 目的与判据
2. 方法与参数
3. 可复制的运行命令（入口在 `src/` 或 `tests/`，从项目根复制即可跑）
4. 结果：表 + 内嵌图
5. 限制：本结果推不出什么
6. 结论：对照判据逐条 通过 / 未通过 / 未测试

第 5 条最容易掉。掉了，报告就只剩好消息。

## 数字怎么来

- **禁止同义反复**：计算值和期望值不能同源。
- 报告数字**对回 JSON / 日志，不凭记忆**；口径对齐要写明。
- 收敛至少 3 个网格，给实测阶，**不写「残差变小了」**。

## 「通过」这个词怎么用

- 只用于**预先声明的量化判据**，而且只出现在交付层。
- `.tmp/` 那一层零权威，只写「实测得到 / 预测被否定 / 未定」，**不准写「通过」**。
- 没做的写「**未实现**」，不写「待下一阶段」。

## 图是断言

必须打开看。坐标、单位、网格或时间参数都要写上。

控制组和故意的错误实现**要画在图上，并在读图里点名**。

要正式留证，图进引用它那份文档所在层的 `figures/`，不进公共的图目录。

## 本文件不做的

不判通过不通过——那是审查那只手对着卡片里预先声明的判据做的事。
不改核，不改测试，不勾 `todo.md`，不 commit。
