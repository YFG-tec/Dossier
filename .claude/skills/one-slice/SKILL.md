# one-slice · 一刀的顺序

**这不是角色，是一段调度。** 角色表在 `docs_meta/src/roles.md`，本文件不复述那张表。
出处是同一页「顺序是锁，不是建议」那一节。两边对不上，改本文件，不改出处。

**现在没有手可派。** 母本这张桌轻档，桌那边也轻档（人 2026-09-12），
四份 agent 落在盘上是待启用。所以这几步现在由领班兼着一步一步走完，顺序一步都不许省。
**轻档减的是手的份数，不是这条顺序。**

## 顺序

```text
写卡 / spec-guard   →  停，等人看卡片
       ↓ 人说开工，红印落下
builder             →  只交卡片点名的那几件
       ↓               做不到 / 只剩折衷 → 退卡，当场停
contract-tester     →  只收紧本刀的 docs_meta/tests/
       ↓
review              →  本刀改了 docs_meta/src/ 就派；SESSION 写「免」才跳过
       ↓
领班收口            →  绿落盘 + 逐条对账，交给人勾选
```

## 三条不许破

- **禁止并行改同一份核。** 几只手不要同时碰 `docs_meta/src/`。
- **卡片已经写过且和 `todo.md` 一致，就不要再派 `spec-guard`。**
- **动了 `docs_meta/src/` 就派审查**，只改一个字也算。不动源码的刀不派。

## 这段调度自己不动什么

不改 `docs_meta/src/`，不改 `docs_meta/tests/`，不写卡，不勾 `todo.md`，不 commit。

它只回答「下一步轮到谁」，不回答「这一步做得对不对」。
