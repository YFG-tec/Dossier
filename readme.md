## 设计思维

### 干活的是智能体

这份管理密度，人类项目负担不起。一刀一卡、收口对账、图必须打开看、「通过」是预先声明的判据才配用——让人来执行，一天做不完两件事。

它在这里成立，是因为**执行规矩的边际成本降到了近乎为零**：写卡、落盘、逐条对账，对智能体是顺手；文档是它唯一稳定的记忆。规矩定得细不是因为聪明，是因为现在定得起。

没有 harness 就没有这套范式；有了 harness 而不立规矩，得到的就是下面七条。防的从来不是人，是不受约束的智能体。

### 提取，不是汇编

这套东西是几个数值项目里边做边收的。各桌有各自的实现和探索路径。Dossier 做的不是汇编，是**提取、统合、抽象、升级**：单桌没想到的缺口要补，不利于管理的冗余要丢掉。三桌里有的，不自动进公共层。旧桌没有义务回改。对照表见 `docs_meta/src/sources.md`。

### 防的是七类失败

1. **超售。** 用户要一行验证，它顺手开下一阶段。
2. **状态在聊天里。** 换窗口，范围漂移。
3. **规划席和实现席抢同一份核。**
4. **探针对不上复现。** 报告引用 `.tmp/run_*.py`，交付第二天废。
5. **测试不能失败。** 期望值和计算值同源。
6. **散了先改数值旋钮。** 病状没了，合同被换掉。
7. **图没人看。** 真错误只在打开图时才露。

所以核是一句话：

**先用目录把权威分开，再用一刀把范围锁死。范围、合同、证据、许可都落到磁盘上。**

目录不是配套设施。分层细则见 `docs_meta/src/directory.md`。

### 两席，角色是写权限

两席不是两个 AI 一起写代码。分工是能力差异加上权限差异。选哪个 harness 坐哪一席可以换，**两席必须是两个会话**不能换。同一个会话里既议事又改核，卡片就退化成事后叙述。

角色不是人设，是**写权限 + 失败时许做什么**。原则上始终成立：

- 写卡的手不接着改核
- 改核的手不改测试口径
- 写测试的手不把核修到绿
- 审查的手不写文件；只核对结果和预先声明的标准
- 规划席说「继续推进」打不开 `src/`

文件和分窗是落地厚度，不是「可以混岗」的许可证。职责表和档位见 `docs_meta/src/roles.md`；Claude Code / Cursor 怎么落见 `docs_meta/src/claude-code.md`、`docs_meta/src/cursor.md`。

### 核心不是转化，是取信

不是把原料变成产品，是让一个结论**可以被相信**：判据先声明、证据能复现、盖章的手不是干活的手。立案、举证、对账、结案——只有结案是人的。名字和换根的来历见 `docs_meta/src/naming.md`。

## Quick Start

**母本只有一份，桌一张张从它出来。**

| 词 | 指什么 |
|---|---|
| **Dossier** | 本仓库。这套规矩本身 |
| **桌** | 课题仓库 |
| **刀** | 桌上的一个工作单元 |

`docs/` 是给桌的骨架（卡片空壳和目录），换根带走。`docs_meta/` 和本页是母本自己的规划，不进桌。

```text
1. clone 母本   拿走 docs/ + harness 规矩
2. git 换根     新 remote / 新项目名；从此是你的课题仓库
3. 长代码层     建 src/<pkg>/ tests/ .venv/ ——母本里没有
4. 开桌议事     和规划席把大框架聊透，聊到能写出第一刀的判据为止
5. 立合同       docs/design/ 先立章节：已定 / 草案 / 占位（占位写成问句）
6. 写第一版 TODO（三五行就够），按一刀开干
```

**合同不必填完。** 第一刀要碰的那一节必须已定，其余可以只是一个问句；
未定的东西随开发逐渐清晰，收口时点名升格。这是 `docs/design/` 存在的主要理由——
它是未定事项的收容层，不是存档。见 `docs_meta/src/workflow.md`「开桌」。

换根认领的是管理骨架，不是 fork 某份物理代码。旧桌没有义务回改；要对齐已有仓库，嫁接比换根合适。

### 第一天

约定和合同定完之后，人每天只做四件事：看 `docs/SESSION.md`，看验收红绿，决定勾不勾 `docs/TODO.md`，拒超售。人是产品负责人，不是结对程序员。

开两个会话。规划席（默认 Cursor）写卡、改文档；实现席（默认 Claude Code）按卡片改 `src/`。没有卡片不准动核。聊天点头不算许可。

一次只做 TODO 未勾的一行。代理不准自己勾，也不准 commit，除非你点名。

细则按需要打开，不必先读完：

| 要干什么 | 读 |
|---|---|
| 目录长什么样、图放哪 | `docs_meta/src/directory.md` |
| 一刀、卡片、收口 | `docs_meta/src/workflow.md` |
| 验证、排障 | `docs_meta/src/verify.md` |
| 角色、档位 | `docs_meta/src/roles.md` |
| Claude Code 怎么落 | `docs_meta/src/claude-code.md` |
| Cursor 怎么落 | `docs_meta/src/cursor.md` |
| 外面有什么、为什么不那样做 | `docs_meta/src/sources.md` |
| 还没对齐的问题 | `docs_meta/docs/design/open.md` |
